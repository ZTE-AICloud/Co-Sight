# 02 整体架构与核心流程

## 架构总览

系统可以理解为三层：

- **接入层（Web）**：FastAPI 路由 + WebSocket，将请求转成一次“计划执行”，并将过程流式返回给前端（见 [main.py](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/main.py)，[routers](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/routers)）。
- **编排层（CoSight 引擎）**：负责 plan_id/workspace、规划、并发调度 Actor 执行、最终汇总（见 [CoSight.py](file:///d:/lingdong/Co-Sight/CoSight.py)）。
- **执行层（Agent + Tools）**：Planner/Actor 基于 LLM 工具调用循环执行；工具执行产生文件/网页/搜索/代码等结果（见 [BaseAgent](file:///d:/lingdong/Co-Sight/app/cosight/agent/base/base_agent.py)，[TaskActorAgent](file:///d:/lingdong/Co-Sight/app/cosight/agent/actor/task_actor_agent.py)，[tool](file:///d:/lingdong/Co-Sight/app/cosight/tool)）。

## 关键数据对象

- `plan_id`：一次任务的唯一标识；WebSocket topic、日志目录、Langfuse session_id 都围绕它组织（见 [CoSight.py:L35-L68](file:///d:/lingdong/Co-Sight/CoSight.py#L35-L68)）。
- `Plan`：步骤列表、状态、依赖关系（DAG）、工具调用记录、步骤产物文件路径等（见 [Plan](file:///d:/lingdong/Co-Sight/app/cosight/task/todolist.py)）。
- `history(messages)`：Planner/Actor 的对话历史，LLM 工具调用循环以它为输入不断追加（见 [BaseAgent](file:///d:/lingdong/Co-Sight/app/cosight/agent/base/base_agent.py)）。

## 核心执行链路（从一次 HTTP 请求开始）

以 `POST {base_api_url}/deep-research/search` 为例：

1. **路由接收请求与准备工作区**
   - 获取/生成 `plan_id`、创建工作区目录、准备队列与订阅回调（见 [search.py](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/routers/search.py)）。
2. **启动引擎执行（后台线程）**
   - 创建 `CoSight` 并调用 `execute()`，让后端主线程继续负责流式输出（见 [CoSight.execute](file:///d:/lingdong/Co-Sight/CoSight.py#L76-L132)）。
3. **Planner 生成计划**
   - `TaskPlannerAgent.create_plan()` 调用 LLM 产出步骤与依赖（DAG），写入 `Plan`（见 [TaskPlannerAgent](file:///d:/lingdong/Co-Sight/app/cosight/agent/planner/task_plannr_agent.py#L29-L67)）。
4. **并发执行可运行步骤**
   - `Plan.get_ready_steps()` 计算依赖已满足、且未开始的步骤（见 [Plan.get_ready_steps](file:///d:/lingdong/Co-Sight/app/cosight/task/todolist.py#L57-L75)）。
   - `CoSight.execute()` 为每个 ready step 启动独立线程执行 `_execute_single_step()`（见 [CoSight.py:L95-L130](file:///d:/lingdong/Co-Sight/CoSight.py#L95-L130)）。
   - 每个线程内创建独立 `TaskActorAgent`，调用 `act(question, step_index)`（见 [CoSight._execute_single_step](file:///d:/lingdong/Co-Sight/CoSight.py#L133-L150)）。
5. **Actor 执行某一步（LLM 工具调用循环）**
   - Actor 先把该 step 标记为 `in_progress` 并发布 plan 事件（见 [TaskActorAgent.act](file:///d:/lingdong/Co-Sight/app/cosight/agent/actor/task_actor_agent.py#L141-L172)）。
   - `BaseAgent.execute()` 调用 LLM：若 LLM 返回 `tool_calls`，就执行工具函数并把结果以 `tool` role 回填到消息历史中，然后继续迭代（见 [BaseAgent.execute](file:///d:/lingdong/Co-Sight/app/cosight/agent/base/base_agent.py)）。
6. **事件上报与流式输出**
   - 计划进度事件：`plan_report_event_manager.publish("plan_process", plan)`（见 [plan_report_manager.py](file:///d:/lingdong/Co-Sight/app/cosight/task/plan_report_manager.py)）。
   - 工具事件：`BaseAgent._push_tool_event()` 统一上报 `tool_start/tool_complete/tool_error`（见 [base_agent.py](file:///d:/lingdong/Co-Sight/app/cosight/agent/base/base_agent.py#L155-L214)）。
   - 路由侧将事件写日志、入队列，并用 `StreamingResponse` 流式发送给前端（见 [search.py](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/routers/search.py)）。
7. **可选：可信分析（Credibility）**
   - 步骤完成后触发异步可信分析，基于“步骤内容 + 工具调用”生成可信总结并推送到同一消息流（见 [search.py:L129-L206](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/routers/search.py#L129-L206)）。
8. **最终汇总**
   - `TaskPlannerAgent.finalize_plan()` 生成最终总结，并发布 `plan_result` 事件（见 [finalize_plan](file:///d:/lingdong/Co-Sight/app/cosight/agent/planner/task_plannr_agent.py#L52-L67)）。

## 路径与产物可访问性（本地路径 → 前端 URL）

为了让前端能点击查看生成的文件，后端会把工具结果中的 `work_space/...` 本地路径改写成 `StaticFiles` 可访问的 URL（见 [search.py:_file_path_to_url](file:///d:/lingdong/Co-Sight/cosight_server/deep_research/routers/search.py#L67-L101)）。
