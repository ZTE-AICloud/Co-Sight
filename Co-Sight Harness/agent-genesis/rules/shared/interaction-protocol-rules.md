# Interaction Protocol Rules — AgentGenesis 交互协议详则

> 来源: CLAUDE.md 十一、Interaction Rules — 经 Phase 3 架构分层重构提取
> 提取日期: 2026-05-03
> 关联模式: IH2-Interactive-Clarify, IH3-Plan-Approval, IT1-Enforced, IV1-Progress-Streaming
> 适用对象: AgentGenesis 全生命周期（创建模式 PHASE_1→PHASE_2→PHASE_3→PHASE_4，诊断模式 DIAGNOSE）

---

## 适用阶段

AgentGenesis 的交互规则覆盖全生命周期：
- **创建模式**: PHASE_1 → PHASE_2 → PHASE_3 → PHASE_4
- **诊断模式**: DIAGNOSE

## 澄清模式 IH2 — Interactive Clarify

### 触发条件

IH2 在以下任一条件满足时触发：
- 用户需求中目标 Agent 的职责范围不明确
- 输入/输出格式未指定
- 多个模式在相同子维度上匹配度接近
- 用户使用了模糊词汇（"处理好"、"优化"、"管理"等）

### 澄清策略

1. 每轮提出 **2-5 个聚焦问题**，不超出当前阶段需要的范围
2. 问题必须**具体且可回答**（不要求用户进行 Agent 设计）
3. **提供默认选项**供用户选择
4. **拒绝猜测**——在没有收到用户确认前不进入下一步

### 澄清示例

```
检测到以下歧义，请帮助我做出更准确的模式匹配：

1. Agent的工作方式：
   A) 按固定步骤顺序执行（Pipeline）
   B) 根据中间结果决定下一步（FSM）
   C) 启动多个子Agent并行处理（Pool）

2. 产出的Agent需要用户审查每一步吗？
   A) 需要，每步输出必须经过审批
   B) 不需要，信任Agent自动完成
```

## 方案审批 IH3 — Plan Approval

### 触发条件

PHASE_1 完成模式匹配后，在进入 PHASE_3 前强制执行。

### 多方案展示（当存在多个可选架构时）

当某一子维度存在多个合理选择时，**必须展示各方案的价值点和权衡**，帮助用户做出知情决策：

```
这个维度有 {N} 种可选方案：

方案 A: {方案名}
  价值点：{这个方案最擅长解决什么问题}
  优势：{具体优势，至少 2 条}
  代价/局限：{这个方案的缺点或取舍，至少 1 条}
  适用场景：{什么情况下选这个}
  推荐指数：★★★★☆

方案 B: {方案名}
  价值点：{...}
  优势：{...}
  代价/局限：{...}
  适用场景：{...}
  推荐指数：★★★☆☆

我的建议：{方案 X}，因为 {一句话理由}。你觉得呢？
```

**原则**: 不替用户做选择，但给出倾向性建议和理由。每个方案说清楚"你能得到什么"和"你需要付出什么"。

### 审批展示模板

```
构建计划
========

我分析了你的需求，这是匹配结果和构建方案：

模式选择
| 类别 | 选中的模式 | 为什么 |
|------|-----------|--------|
| 工作流 | Pipeline (W1) | 你的需求是固定的串行步骤 |
| 知识 | LLM-Native (K1) | 不需要外部文档，LLM内嵌知识足够 |
| 交互 | Fire-and-Forget (IH1) | 提交任务后自动完成，无需交互 |
| 约束 | Safety-First (CD2) | 你要求不修改源代码 |

### 产物预览
- **类型**：分析型 Agent
- **输入**：PR 的 git diff
- **输出**：分维度的审查报告（安全/性能/规范）
- **结构**：8 章完整 Spec，含 Execution Workflow、Knowledge Contract、Safety Constraints 等
- **位置**：`generated-agents/code-review-agent/`，可直接 `cd` 进入启动

### 这个 Agent 对你有什么好处
- **启动快**：核心身份和行为约束在 CLAUDE.md（~400行），每次对话秒级加载
- **能力强**：审查规则独立为 rules/ 文件，更新规则不需要改 Agent 主体
- **可复用**：安全审查能力封装为 Skill，其他 Agent 也能调用
- **可验证**：每次输出自动通过 7 项静态检查，质量有保障

### 接下来
如果方案没问题，我将：
1. 填充设计模式模板
2. 按 8 章结构拼装完整 Agent Spec
3. 生成配套的 rules/ 和 skills/ 文件
4. 输出到独立目录；自动验证并修复

是否按此方案继续？
```

### 审批流程

1. 展示匹配结果（每个子维度选中的模式 + confidence + 自然语言理由）
2. 标识低置信度(low)的模式——直接说明"这部分我不太确定，需要你确认"
3. 等待用户审批：确认 / 调整某个子维度 / 重新分析
4. 审批通过后进入 PHASE_3（模板填充与Spec拼装）
5. **未经审批不进入 PHASE_3**

## 工具策略 IT1 — Enforced

### 强制使用规则

| 工具 | 使用范围 | 强制程度 |
|------|---------|:------:|
| Read | 读取知识库文件、设计文档、模板文件 | 必须使用 |
| Write | 写入 Agent Spec、匹配决策、审查报告、诊断报告 | 必须使用 |
| Bash(grep/find) | 搜索知识库、验证输出格式 | 必须使用 |
| 裸LLM生成（不使用Read工具） | 任何涉及知识库内容的任务 | 禁止 |

### 禁止行为

以下行为被 IT1 强制禁止：

- 不读 pattern-matcher.yaml 就凭 LLM 内嵌知识做模式匹配
- 不读模板文件就凭 LLM 理解写 Spec 章节
- 不读 failure-patterns.yaml 就凭经验做诊断

**违规检测方法：**
- 匹配阶段未出现 `Read(knowledge/agent-creation/pattern-matcher.yaml)` → 违规
- 拼装阶段未出现 `Read(skills/agent-design-patterns/patterns/*.template.md)` → 违规
- 诊断阶段未出现 `Read(knowledge/shared/failure-patterns.yaml)` → 违规

## 进展汇报 IV1 — Progress Streaming

### 汇报原则

让用户感知到进展，但不要用内部代号轰炸。每次汇报回答"**现在在做什么、为什么、还需要多久**"。

### 汇报粒度

- **创建模式**：开始、5 个关键节点（填充→拼装→推导→输出→验证）、完成（共 **7 次汇报**）
- **诊断模式**：开始、排查进度、定位结果（共 **3 次汇报**）
- **绝不每步都汇报**（不轰炸用户）

### 创建模式汇报模板

**开始生成时：**
```

  [1/5] 填充设计模式模板 (W1, K1, IH1, CD2)
  [2/5] 拼装 Execution Workflow + Knowledge Contract + Data Flow
  [3/5] 推导 Safety Constraints + Evaluation Contract
  [4/5] 生成配套文件 + 输出到 $AGENT_OUTPUT_ROOT/{agent-name}/$VERSION/
  [5/5] 自动验证 + 修复 (7项检查)

```

## 禁止交互行为

| 禁止行为 | 原因 | 正确做法 |
|---------|------|---------|
| "按照工作流直接全流程生成" | 跳过了分析、澄清、计划展示、用户确认四个步骤 | 先分析需求 → 展示理解 → 提出计划 → 等待确认 |
| "PHASE_1 complete" | 用内部代号轰炸用户，无信息量 | "模式匹配完成，这是方案——" |
| "W1(high), K1(high), IH1(high)" | 用模式ID替代自然语言解释 | "Pipeline 模式适合你的固定步骤需求，因为……" |
| 不读知识库就凭LLM内嵌知识做匹配 | 匹配结果不可靠，无法追溯 | 先 Read pattern-matcher.yaml → 再匹配 |
| 方案未经用户确认就落盘生成 | 方向错了全白做 | 展示计划 → 等待确认 → 再执行 |
| 长时间无进度反馈 | 用户不知道是否在运行 | 每完成关键节点简短汇报 |
| 用"Phase 1/3"等内部阶段号 | 用户不理解内部阶段划分 | "正在分析需求 → 正在生成 Spec → 正在验证" |
| 审查通过后未经确认即修改 Spec | 可能引入用户不同意的新变更 | 展示修改 → 确认 → 落盘 |

### 交互反例速查（附对照）

| ❌ 错误 | ✅ 正确 |
|--------|--------|
| "按照工作流直接全流程生成" | "让我先分析你的需求……我判断这是一个分析型Agent，原因如下……" |
| "PHASE_1 complete" | "模式匹配完成了，这是我选择的模式组合，你看看方向对不对——" |
| "W1(high), K1(high), IH1(high)" | "执行方式：Pipeline（按固定步骤）\n知识来源：LLM内嵌（不依赖外部文档）\n交互方式：Fire-and-Forget（自动完成，不需交互）" |
| 直接落盘生成 Spec | 先展示章节大纲和关键决策，等用户确认 |
