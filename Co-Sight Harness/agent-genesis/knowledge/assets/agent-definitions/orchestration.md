# 多 Agent 编排指南

> AgentGenesis 自研资产 — 主 Agent 调度 SubAgent 的通用约定（W1/W3/DP1/IV1）。

## 核心原则

**SubAgent 是自包含单元**：从预加载的 SKILL.md 读流程，按需 Read 知识依赖，
写输出到指定路径。主 Agent 只传四样东西：

1. SubAgent 名称（调度入口）
2. 输入文件路径列表
3. 输出文件路径列表
4. 禁读列表（forbidden_inputs，保证审查/验证独立性）

不传实现细节、不代做 SubAgent 的职责。

## 拓扑选择

| 拓扑 | 适用 | 特征 |
|------|------|------|
| Pipeline (W1) | 固定串行步骤 | 阶段间用文件传递产物，每步有明确 I/O 契约 |
| Router (W3 变体) | 按类型分发 | 入口判定 → 路由到专职 SubAgent |
| MapReduce (W3) | 可并行子任务 | 主 Agent 切片 → 并行执行 → 聚合结果 |
| 博弈对 | 生成/审查对抗 | 生成者与审查者上下文隔离，审查 FAIL 回压重试（≤3 轮） |

## 上下文隔离（审查独立性）

- verifier/reviewer 类 SubAgent 必须声明 `forbidden_inputs`，禁读设计文档与上游产物中的"自我验证素材"
- 独立 context 运行，销毁后知识不残留主 Agent
- 同一 Agent 不得既执行又审查自己的产出（G1 门禁）

## 数据传递（DP1）

- 阶段间用**文件**传数据，不用对话上下文（防膨胀与丢失）
- 每个中间产物有生产者/消费者声明，数据流闭合（无悬空实体）
- 关键产物标注来源（可追溯性：结论 ← 哪一步哪个文件）

## 进度汇报（IV1）

- 长流程在关键节点简短汇报："现在在做什么、为什么、还需多久"
- 不逐步轰炸、不用内部代号（说"匹配完成"而非"PHASE_1 done"）
- 失败时汇报：什么失败了、重试第几次、上限几次、下一步干什么

## 反模式

- 主 Agent 替 SubAgent 干活（S-07 类硬约束：编排者不执行被编排者的任务）
- 无 forbidden_inputs 的"独立"验证
- 并行任务被串行化（先判定依赖，无依赖就并行）
- 上下文窗口在后 20% 时还做大范围重构（此时只做单文件小编辑）
