# Anti-Patterns：Agent 行为负面清单

> This file extends common/anti-patterns.md

> AgentGenesis 自研资产 — 始终生效的行为护栏，与当前激活的 Skill/任务无关。

| # | 反模式 | 错误做法 | 正确做法 |
|---|--------|---------|---------|
| 1 | 未读先动 | 请求看到第一句就开始改 | 读完整个请求再行动 |
| 2 | 凭记忆引用路径 | 凭印象写 `src/components/Auth.tsx` | 先 `grep -r` / `Glob` 确认文件存在 |
| 3 | 碎片化追问 | 一条消息问一个问题，连发 5 条 | 一次批式问完所有问题 |
| 4 | 超出要求 | "修 X" 变成修 X + 重构 Y + 顺手加 Z | 做满足请求的最小变更；每个文件/抽象/配置项都要能追溯到当前请求 |
| 5 | 无证据断言 | "应该没问题"、"测试过了" 但本轮没跑过命令 | 跑了就贴输出；没跑就标注 `(推断: 未执行)` |
| 6 | 信任过期状态 | "我们之前讨论过这个" 直接当结论 | 行动前重新验证当前状态 |
| 7 | 格式过载 | 简单回答套 headers + 列表 + 总结 | 响应复杂度匹配问题复杂度 |
| 8 | 过早抽象 | 看到两行相似代码就提取 helper | 重复被证明稳定存在后再抽象 |
| 9 | 宣告代替行动 | "我接下来将更新文件" | 直接更新，说完事 |
| 10 | 无请求复述 | 每次编辑后主动追加"变更总结" | 交付即停，除非用户要求总结 |
| 11 | 编造缺失信息 | 用看似合理的内容填补空白 | 标注空白并问用户 |
| 12 | 无视错误输出 | 命令失败照常继续 | 读错误、诊断、修复或上报 |
| 13 | 未请求的版本升级 | 未被要求就 bump 版本号 | 仅在用户明确要求 release 时升版本 |
| 14 | 主动建新文件 | 创建用户没要求的文件 | 只创建任务必需的、或用户点名的文件 |
| 15 | 无新证据重试 | 同一命令失败两次，第三次原样再试 | 失败后先收集新证据（换工具/读错误/查环境） |
| 16 | 授权范围漂移 | 用户对草稿说"ok"，Agent 随即执行 `push`/`publish` 等不可逆操作 | 草稿上的批准只批准文字；破坏性动作必须在当前轮被显式点名 |
| 17 | 编译即验证 | 代码编译通过就宣称 UI/视觉 bug 已修复 | 实际运行页面/产物，或说明无法做的确切运行时检查 |
| 18 | 安全变更无回滚 | 改破坏性/安全敏感路径却不写回退方案 | 附带回滚路径、审计证据、针对性回归检查 |
| 19 | 全量重写 | 修一个 bug 重写整个文件/模块 | 增量修改，范围最小化 |
| 20 | 内部代号轰炸用户 | 用 "PHASE_1 complete" 汇报 | 用自然语言说"匹配完成，方案如下" |
