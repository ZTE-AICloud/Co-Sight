# Command Router — 关键词意图路由 Agent

本 Agent 是一套确定性意图路由协议：第一个词提取 → 查表 → 加载指令文件 →
执行。核心原则：**路由是查表行为，不是语义猜测**——`investigate` 永远触发
调查流程，`kb-sync` 永远触发知识库同步。不做最少的事，但把事做对。

## When to Use

- 任务域明确、流程固定的项目（路由表 3-8 个目标即可覆盖）
- 需要行为完全可预测、可单元测试、可 CI 触发的场景
- 指令文件需要独立演进、互不影响的架构（新增流程 = 新增文件 + 路由表加一行）

## 核心机制（三件）

### 1. 首词路由表

```
用户输入的第一个词
  ├── "ask"         → prompts/ask.instruction.md
  ├── "investigate" → prompts/investigate.instruction.md
  ├── "refine"      → prompts/refine.instruction.md
  ├── "kb"          → prompts/kb.instruction.md
  └── 非关键词       → 启发式推断（见机制 2）
```

路由表是集中索引：新增流程 = 新增指令文件 + 路由表登记一行触发词。
触发词用用户原话词汇，不用内部术语。

### 2. 启发式回退推断

第一个词不在路由表时，按输入形态推断：

- 看起来像研究/问题（疑问句、无代码特征）→ 按 `ask` 处理
- 看起来像编码工作（含代码片段、文件路径、报错堆栈）→ 按 `investigate` 处理
- 其他非编码工作（规划/文档/维护）→ 直接执行，不加载指令文件

回退规则按特异性从高到低排列，写在 CLAUDE.md 路由段内，格式统一为
`IF <可观察输入特征> THEN route to <指令文件>`。

### 3. 指令文件完全分离

路由器不含任何执行逻辑。每个目标流程是一个独立的指令文件
（`prompts/*.instruction.md`），定义完整的步骤序列。改 kb 指令不影响
investigate 流程。这是开闭原则的直接体现。

## 输入预处理协议（三步）

### Step 1 — 首词提取

读请求的第一个词，查路由表。命中则加载对应指令文件，跳到 Step 3。
未命中进 Step 2。

### Step 2 — 回退推断与参数提取

对 `investigate` / `kb` 类指令，读第二个词（若存在），转为标题
`# THE-WORD` 作为该指令的上下文锚点。其余输入保持原样。

### Step 3 — 装载执行

把处理后的请求当作"最新一条消息"传入指令文件，按指令文件的步骤
立即执行，不再等待额外输入。

## 语音输入检测（可选适配）

当输入几乎没有换行或标点时，判定为语音输入，引入大量同音错字——
此时对输入做同音词容错推断再路由。这是针对语音工作流的个性化适配，
常规文本输入不启用。

## 路由表维护约定

- 路由表与指令文件一一对应；漂移即失效（路由表写了 `ask` 但文件不存在 =
  构建缺陷，G028 g023 batch 会抓住这类声明未生产）。
- 新增指令文件时同步在路由表登记触发词，并声明与既有触发词的消歧关系。
- 指令文件内不引用其他指令文件的路径（保持独立可测）。

## Not for

- 需要模糊语义理解的路由场景（第一个词匹配无法覆盖"帮我看看这段代码"类
  请求——除非回退启发式恰好覆盖）
- 流程间需要共享状态或自动串联的场景（本协议每次路由独立执行，无状态传递）
- 路由目标超过 ~8 个的复杂域（路由表膨胀后回退规则不可靠，应改用
  语义路由或分层路由）
