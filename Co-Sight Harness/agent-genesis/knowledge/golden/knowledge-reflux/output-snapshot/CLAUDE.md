# Knowledge Reflux — 会话模式提取与自我进化 Agent

本 Agent 是一条四级学习管道：观察（从会话痕迹收原始记录）→ 原子模式
（带置信度的小行为单元）→ 聚类（相关模式合并为候选能力）→ 升级（成为
正式的 Skill / Command / Agent 定义）。核心原则：**学习是提取, 不是记忆**
——不存对话原文, 只存可复用的行为模式; 模式有置信度, 低置信度不自动
升级。

## When to Use

- 需要 Agent 从使用历史中持续学习（同一项目用得越久越顺手）
- 多人/多项目共享底座, 但个人生成内容不应污染共享目录
- 需要区分"项目特有惯例"与"跨项目通用模式"

## 核心机制（三件）

### 1. 四级进化管道

```
会话执行（在项目内）
  │
  ▼ 钩子/观察件捕获原始记录（prompt + 工具调用 + 结果 + 项目标识）
+-------------------------------------------+
|  observations.jsonl（项目作用域, 追加写）   |
+-------------------------------------------+
  │
  ▼ 后台分析（轻量模型, 不占主会话上下文）
+-------------------------------------------+
|  原子模式（instinct）                        |
|  - 一触发一动作, 原子不可再分                 |
|  - 置信度 0.3-0.9 加权                      |
|  - 领域标签（code-style/testing/git/...）    |
|  - 证据链（哪几次观察产生的, 可回查）          |
+-------------------------------------------+
  │
  ▼ 定期聚类（/evolve）
+-------------------------------------------+
|  候选能力（聚类后的模式组）                   |
+-------------------------------------------+
  │
  ▼ 升级（/skill-create 或人工策展）
+-------------------------------------------+
|  Skill / Command / Agent 定义               |
|  - 先落个人作用域（project-evolved/）         |
|  - 跨项目复现 ≥2 次后可提升为全局             |
+-------------------------------------------+
```

### 2. 原子模式格式

```yaml
---
id: prefer-functional-style
trigger: "when writing new functions"
confidence: 0.7
domain: "code-style"
source: "session-observation"
scope: project
project_id: "a1b2c3d4e5f6"
---

# Prefer Functional Style

## Action
Use functional patterns over classes when appropriate.

## Evidence
- Observed 5 instances of functional pattern preference
- User corrected class-based approach to functional on 2026-09-15
```

**属性纪律**:
- **原子**: 一个触发器 + 一个动作, 不装多条规则
- **置信度加权**: 0.3 = 试探, 0.9 = 近确定; 升级阈值为 0.6（默认, 可调）
- **领域标签**: 便于检索与聚类, 不跨领域硬合并
- **证据链**: 每条模式可回查产生它的观察记录, 不是无源断言
- **作用域感知**: project（默认）或 global; 全局模式不得含项目特有名词

### 3. 项目作用域与防污染

- 每个项目有独立作用域目录（以项目路径 hash 为 id）, 模式默认落项目作用域。
- 全局作用域只收"跨项目通用模式"（如"总是校验输入"）; 项目特有模式
  （如某 React 组件库约定）留在项目内, 不全局可见。
- **提升路径**: 同一模式在 ≥2 个项目独立出现后, 可提升为全局——不是
  项目内重复出现就全局化, 是跨项目复现才全局化。
- **目录分离纪律**: 共享底座（curated）与个人/项目生成（generated）分
  目录存放; 个人生成的优秀模式经策展评审才可升入 curated。这条纪律防
  止个人实验性内容直接污染团队共享目录。

## 置信度与升级规则

| 置信度 | 含义 | 处置 |
|--------|------|------|
| 0.3-0.5 | 试探性观察 | 只存不写, 等待更多证据 |
| 0.5-0.7 | 较稳定模式 | 可在项目内建议, 不自动升级 |
| 0.7-0.9 | 稳定模式 | 可进 /evolve 聚类 |
| ≥ 0.9 且跨项目复现 | 近确定通用模式 | 可提升为全局 |

升级永远不是全自动: 最后一跳（模式 → Skill/Command/Agent 正式定义）
要么经人工策展, 要么经显式命令（/skill-create 类）触发。

## 数据与边界

- 观察原始记录只存项目作用域, 不跨项目共享; 全局只有提炼后的模式。
- 原始观察记录定期清理（保留模式, 清理原始 jsonl——提取完成后原文
  不长期保留）。
- 模式文件不含密钥/个人信息/项目敏感路径; 捕获层做脱敏后再落盘。

## Not for

- 需要精确记忆对话历史的场景（本 Agent 只存模式, 不存对话原文）
- 强实时响应场景（后台分析管道有延迟, 不阻塞主会话）
- 单项目一次性任务（无跨会话积累, 学习管道无输入）
