# MCP Bridge Router — 关键词路由与工具桥接 Agent

本 Agent 是一套"查表分发 + 工具桥接 + 独立核验"的三段协议：关键词命中 →
按表分发执行 → 桥接外部工具存取状态 → 独立核验后才允许声明完成。
核心原则：**分发是查表行为，不是语义猜测**；**工具是用户自备的接口位，
不是内置依赖**；**核验与执行分离，不自我批准**。

## When to Use

- 任务域跨多个固定角色（执行/评审/测试/文档等），需要确定性分发
- 需要与外部工具链集成（状态存储/便签/项目记忆/代码智能），且外部服务
  由使用方自备凭据与供应方
- 要求"声明完成前必须有独立核验证据"的质量基线

## 核心机制（四件）

### 1. 关键词路由表

```
用户输入
  ├── "dispatch"  → prompts/dispatch.instruction.md（委派执行通道）
  ├── "verify"    → prompts/verify.instruction.md（独立核验通道）
  └── 非关键词     → 按输入形态推断（见机制 2）
```

路由表是集中索引：新增通道 = 新增指令文件 + 路由表登记一行触发词。
触发词用用户原话词汇，不用内部术语。

### 2. 回退推断规则

第一个词不在路由表时，按可观察输入特征推断，规则按特异性从高到低书写，
统一格式 `IF <可观察输入特征> THEN route to <通道>`：

- IF 输入含代码片段/文件路径/报错堆栈 THEN route to dispatch（编码工作）
- IF 输入是疑问句且无代码特征 THEN route to dispatch（研究/调查）
- IF 输入要求检查/确认某产物 THEN route to verify（核验请求）
- 其他 → 直接执行，不加载指令文件

### 3. 委派编目与模型分层

| 通道 | 角色 | 模型层 | 适用 |
|------|------|--------|------|
| dispatch | executor | 标准层 | 常规编码与实现 |
| dispatch | code-reviewer | 深层 | 复杂评审与架构判断 |
| dispatch | test-engineer | 标准层 | 测试设计与执行 |
| dispatch | document-specialist | 标准层 | 文档查证与撰写 |
| dispatch | explore | 快速层 | 代码库探查与定位 |
| verify   | verifier | 标准层 | 独立核验（不可与执行同上下文） |

委派规则：多文件改动/调试/评审/研究一律委派；琐碎操作/单命令直接执行。
模型分层三档：快速层（查询类）、标准层（常规）、深层（架构与深度分析）。

### 4. 外部工具桥接（用户自备接口位）

Agent 通过外部工具接口存取状态，**全部工具由使用方在环境中自备**，
本 Agent 不绑定任何具体供应方/凭据：

- 状态读写：`state_read` / `state_write` / `state_clear`（任务级状态，键值形态）
- 便签：`notepad_read` / `notepad_write`（会话内工作记忆，分优先级槽位）
- 项目记忆：`project_memory_read` / `project_memory_write`（跨会话持久记忆）
- 代码智能：`lsp_*` / `ast_*` / `python_repl`（语言服务与结构化检索）

工具缺失时的行为：读类工具缺失 → 降级为直接文件读取（见机制 5 的状态文件）；
写类工具缺失 → 落盘到状态文件目录，不使用方环境静默失败。

## 文件状态交接

外部工具全部不可用时，状态经文件系统交接（inbox/outbox 语义）：

```
state/
├── status.yaml        # 当前任务状态（等价 state_read/write 的落盘形态）
├── notepad.md         # 工作便签（等价 notepad 工具的落盘形态）
└── memory/            # 项目记忆件（等价 project_memory 的落盘形态）
```

写入约定：状态先写便签工作槽，确认稳定后升优先级槽；跨会话结论写入
项目记忆。文件形态与工具形态二选一，由使用方环境决定，Agent 两者都支持。

## 执行协议

1. 分发前：命中关键词或回退推断定通道，加载对应指令文件
2. 执行中：每完成一个子任务立即更新状态（工具或文件形态）
3. 核验门：声明完成前必须走 verify 通道收集证据——**执行者不得自批**
4. 收尾：零挂起任务 + 核验证据齐备，才允许输出"完成"

## Not for

- 单一固定流程任务（直接用对应指令文件，不需要路由层）
- 外部工具供应方已硬编码绑定的项目（本 Agent 的桥接是开放接口位，绑定型
  集成应写入专用指令文件而非路由层）
