# verify — 独立核验通道指令

> 由 mcp-bridge-router 关键词路由表分发进入。核验类任务的完整步骤序列。
> 与 dispatch 通道硬性隔离：同一活跃上下文不得既执行又核验。

## 核验步骤

1. **读交接摘要**：从状态文件取 dispatch 通道留下的"声称 + 证据位置 + 未覆盖项"
2. **规模定层**：小改动 → 快速层核验；常规 → 标准层；安全敏感/大范围 → 深层
3. **证据核对**：逐项对照交接摘要核验——运行测试、复现行为、检查边界条件；
   证据不足即判 FAIL，不接受"看起来对"
4. **迭代门**：FAIL → 回 dispatch 修复（带具体失败证据），修复后重新进入本通道；
   循环设最大次数，超限升级人工

## 通过准则

- 所有声称均有可复现证据支撑
- 未覆盖项已显式声明（不隐藏盲区）
- 零挂起子任务

## 产出

- 核验结论（PASS / FAIL + 证据清单）
- 核验证据写入状态文件，作为允许向用户声明完成的唯一凭据
