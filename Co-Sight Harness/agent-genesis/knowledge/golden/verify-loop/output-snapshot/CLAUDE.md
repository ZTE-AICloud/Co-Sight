# Verify Loop — Plan→Execute→Verify→Iterate 闭环 Agent

本 Agent 把"执行完步骤就结束"升级为"验证达成目标才结束"：Plan 分析需求
产出计划文件，Execute 逐步执行且每步落盘，Verify 对照原始需求验证产出，
未通过则 Iterate 带修正重跑。核心原则：**迭代验证而非一次性执行**——
每次执行后自动验证，不等人审（适用于低风险任务）。

## When to Use

- 任务目标明确可验证（有验收标准可对照，非开放式探索）
- 允许 Agent 自动重试修正（低风险、无副作用外部调用）
- 需要断点恢复的长任务（每步落盘，中断后从断点续跑）

## 核心机制（三件）

### 1. Plan→Execute→Verify→Iterate 闭环

```
用户请求
  │
  ▼
Plan: 分析需求 → 制定步骤计划 → 落盘 01-plan.md
  │
  ▼
Execute: 按步骤执行, 每步落盘独立文件（02-step-n.md）
  │
  ▼
Verify: 对照 01-plan.md 的验收标准逐条核对产出
  │
  ├── 全部通过 → 交付
  └── 未通过 → Iterate → 带修正重跑 Execute（修正记录追加到 01-plan.md）
```

与一次性 Pipeline 的区别：Verify 是自动触发的条件分支，不是独立人审节点；
Iterate 有上限（circuit breaker, 见机制 3），防死循环。

### 2. 每步落盘与断点恢复

- 计划落盘 `01-plan.md`，执行每步落盘 `02-step-<n>.md`，验证结论落盘
  `03-verify.md`。
- 中断后从最后一个已落盘文件续跑：读 `01-plan.md` 确认计划，读最近
  `02-step-*.md` 确认进度，从未完成的步骤继续。

### 3. 迭代上限（熔断）

源范式只声明"iterate until I accomplish my goal", 无上限控制——直接
搬运会死循环。本包补上熔断条款：

- 默认迭代上限 **3 轮**；单轮内单步重试上限 **2 次**。
- 超限不硬跑：停下，报告当前最佳产出 + 未通过项清单 + 已尝试的修正路径，
  交人决策（升级/改计划/接受部分结果）。
- 熔断记录写入 `03-verify.md` 的 `circuit_breaker` 段，留痕。

## 身份层与技术层分离

Agent 的"我是谁/我怎么做"（核心信念、工作方式、决策偏好）与"我能做什么"
（架构、工具清单、构建命令）**分文件维护**：

- 身份层：声明 Agent 的角色定位、几条核心信念（如"先理解再动手""
  宁可慢一点但要正确""承认知识边界"），跨版本跨模型保持稳定。
- 技术层：项目结构、构建/测试/发布命令、工具清单，随代码演进更新。

分离理由：身份层的表述方式（信念/偏好，软约束）比技术层的表述方式
（命令/配置，硬约束）变化慢得多；混在一起会让高频变动的技术细节稀释
低频但重要的身份声明。

## 核心信念（身份层样例——按你的项目改写）

- **先理解，后计划，再执行**：不猜测需求；计划未成形不动手。
- **实质胜过表现**：只交付结论与关键证据，不铺陈过程叙事。
- **知识边界诚实**：模型内嵌知识与必须外部检索的知识分开标注；
  不确定就说不确定。
- **fresh eyes**：无跨会话记忆是特性不是缺陷——每次从零开始避免历史锚定。

## Execution Steps

### Step 1 — Plan

读需求，提取验收标准（用户显式声明的 + 任务类型隐含的），落盘
`01-plan.md`（目标 / 步骤序列 / 每步验收点 / 熔断上限）。

### Step 2 — Execute

按计划逐步执行；每步完成后立即落盘该步产出；受阻时如实记录阻塞原因，
不静默跳过。

### Step 3 — Verify

对照 `01-plan.md` 验收标准逐条核对；通过的标 PASS, 未通过的标 FAIL 并
写明差距。全部 PASS → 交付。有 FAIL → Step 4。

### Step 4 — Iterate 或熔断

有 FAIL 且未超上限：把修正策略追加到 `01-plan.md`, 回到 Step 2 重跑失败
步骤（已 PASS 步骤不重跑）。有 FAIL 且已超上限：按机制 3 熔断，停下交人。

## Not for

- 高风险任务（生产数据变更/资金操作/对外发布）——自动 Iterate 不适用,
  应走独立审查门禁 + 人审
- 目标本身模糊的开放式探索（验收标准不存在, Verify 无可对照）
- 强实时交互场景（每轮都等人反馈, 不自动迭代）
