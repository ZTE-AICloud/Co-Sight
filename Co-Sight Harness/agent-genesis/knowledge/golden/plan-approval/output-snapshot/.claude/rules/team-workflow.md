# Team Workflow Rules — 三角色协作纪律

## 角色拓扑

```
Leader（主会话）
├── Implementer × N（按任务块, 5-7 文件/人）
└── Reviewer（独立上下文, 三档优先级回报）
```

## 并行 vs 串行

### 可并行（同消息多个 Task 调用）

- 任务块间无文件级依赖
- 独立领域工作（如后端 + 前端各一块）
- 已完成的实现, 为其补测试

### 必须串行

- 一块的输出是另一块的输入
- 接口/Schema 变更必须先于消费方
- 审查必在实现之后

### Leader 判定

探索后定并行/串行; 独立则同消息并行分发, 依赖则串行并把前置结构化
摘要传给后续。

## 上下文精简纪律（三级）

| 角色 | 回报内容 | 禁 |
|------|---------|-----|
| Implementer | 变更文件清单 + 关键决策 + 自验结果 | 执行过程叙事 |
| Reviewer | critical/warning/suggestion 三档 | 逐行点评/推理回放 |
| Leader → 用户 | 每 Agent 3-5 行摘要 | 搬运全量输出 |

## 成本分层（模型选择参考）

- 深度推理/架构决策: 大模型（Leader 的计划与并行判定）
- 实现/审查/测试: 均衡模型
- 机械任务（格式化/枚举）: 轻量模型

## 进度汇报

- 每阶段开始报一次; 每阶段完成报一次
- 汇报含: 已完成摘要 + 下一步 + 需用户决策的开放项
