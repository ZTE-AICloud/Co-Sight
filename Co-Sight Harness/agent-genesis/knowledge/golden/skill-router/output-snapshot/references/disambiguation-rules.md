# 消歧规则集模式

> 本文件是 skill-router 的 L3 参考：多命中时的判定规则写法与排序约定。

## 格式

每条规则一句，统一结构：

```
IF <具体可观察条件> THEN route to <具体能力>
```

条件必须可观察（用户请求里能直接看到的特征），禁止抽象条件
（如"如果比较复杂"）。

## 排序原则：特异性从高到低

排在前面的规则条件更具体、判定依据更窄。路由时从第一条开始核对，
取第一条命中的规则——所以排序就是优先级。

经典规则类型（按源项目 10 条规则提炼的通用模式）：

1. **对象区分**：已交付走审查；跑不通走诊断。两者都可能匹配"帮我看看"，
   按"有没有具体错误现象"区分。
2. **动作区分**：要写发布文案走写作；要执行发布动作走审查（发布模式）。
3. **载体区分**：截图说"丑"是审美校准；截图证明"以前好的现在坏了"是回归诊断。
4. **产出阶段区分**：从零到成稿走研究；已有稿子要改走写作。
5. **意图区分**：价值判断（该不该/值不值得）走方案能力；异常判断
   （为什么不工作）走诊断能力。

## 兜底规则（永远最后）

两个候选都模糊时：读候选能力的 "Not for" 段做排除法；仍无法排除
则追问用户。**不允许在兜底层做猜测路由**——误路由的代价高于不路由。

## 维护规则

1. 新规则插入时保持特异性序：比它更具体的规则必须排在它前面。
2. 每条规则必须对应一个真实发生过的混淆场景，不为假想场景立规则。
3. 规则集定期回访：两条规则从未同时各自命中过，考虑合并。
