# 路由表模式（阶段分路）

> 本文件是 skill-router 的 L3 参考：路由表的完整结构约定与列定义。
> 主文件只讲机制，此处给可照抄的表格骨架。

## 结构

路由表按工作流阶段分四段，每段一张两列表：

| 列 | 内容 | 写法要求 |
|----|------|---------|
| 触发 | 用户请求的特征词/短语 | 用用户原话词汇，不用内部术语；同义触发并列写满 |
| 目标 | 命中后加载的能力 | 写相对路径或能力名；一个目标可带模式标注（如"审查（发布模式）"） |

## 四段骨架

### 动手前（Pre-build）

| 触发 | 目标 |
|------|------|
| 新功能 / 架构决策 / "怎么设计" / "应该用什么方案" / "值不值得" | 设计/方案能力 |
| UI / 组件 / 页面 / 视觉问题 | 视觉能力 |

### 交付前（Post-build）

| 触发 | 目标 |
|------|------|
| 实现完成 / 合并前 / "review 一下" / 产物检查 | 审查能力 |
| 发布 / 提交 / 打 tag / 发布前检查 | 审查能力（发布模式） |

### 出问题（Diagnostic）

| 触发 | 目标 |
|------|------|
| 报错 / 崩溃 / 测试失败 / "为什么不工作" / 回归 | 诊断能力 |
| 工具链异常 / 配置漂移 / 指令被忽略 | 健康检查能力 |

### 内容进出（Content）

| 触发 | 目标 |
|------|------|
| URL / 网页链接 / "读一下这个" | 读取能力 |
| 写作 / 润色 / 文案 / 本地化 | 写作能力 |
| 深度研究陌生领域 / 材料沉淀成文 | 研究能力 |

## 维护规则

1. 触发列宁多勿少：用户实际用语是路由键，内部术语匹配不上。
2. 新增能力必须先回答"它与表里哪些目标的触发重叠"，重叠处必须
   在消歧规则集里有一条区分规则。
3. 阶段段数固定四段；新阶段需求先论证，不轻易加段（段是生命周期
   轴，不是分类垃圾桶）。
