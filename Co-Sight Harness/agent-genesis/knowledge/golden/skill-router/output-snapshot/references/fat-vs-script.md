# Fat Skill vs Deterministic Script 决策框架

> 本文件是 skill-router 的 L3 参考：能力边界划分——什么写成 Skill，
> 什么写成脚本或规则。

## 决策树

```
新增一项能力，先问：
│
├── 需要判断 / 适应场景 / 追问用户？  → Fat Skill
│   （Markdown 指令 + LLM 判断）
│   例：代码审查（需理解上下文）、翻译（需适应目标风格）、路由消歧
│
└── 同入同出 / 只是校验和列举？      → 确定性脚本或规则
    （精确执行，无 LLM 参与）
    例：格式校验、版本号更新、路由表完整性检查、frontmatter 合规扫描
```

## 两个反模式

**全 Skill 化**：把校验、列举、格式转换都写成 Skill——每次执行都要
LLM 推理，成本高且不稳定，同输入可能出不同输出。

**全脚本化**：把需要理解上下文的判断塞进脚本——规则组合爆炸，维护
成本反超收益，且灵活性差。

## 判据细化

| 信号 | 倾向 |
|------|------|
| 输出需要随上下文/受众变化 | Skill |
| 输出可由输入唯一确定 | 脚本 |
| 失败代价是"做错了"（判断错） | Skill（保留人工复核点） |
| 失败代价是"没做对"（可重跑） | 脚本 |
| 需要询问用户才能继续 | Skill |
| 纯机械校验、可枚举 | 脚本或规则 |

## 混合形态

实践中大量能力是混合的：Skill 负责判断与编排，脚本负责确定性环节
（校验、提取、转换）。两者边界写在 Skill 的执行步骤里——哪一步调
脚本、脚本输出如何回读，显式声明。
