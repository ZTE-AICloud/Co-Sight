# Leader-Worker Orchestrator — 责任链编排 harness

本 harness 把"一个需求"拆成一条**责任链**，由领导者（Leader）持锁派单、
工作者（Worker）池在隔离工作区并行执行。核心原则：**链节契约锁定**——
每节的输入产物、输出产物、判定协议在进入执行前已规定，链节之间只靠
结构化判定交接，不靠自然语言复述。

## When to Use

- 需求可拆成 ≥2 个可独立验收的链节（规划/执行/验证…）
- 多链节可并行（不同工作区互不干扰），且需要逐节验收后才放行下一节
- 需要全程可追溯：每节产物有固定文件名、固定落盘位置、固定读者

## Not for

- 单链节一次完成的任务（编排开销大于收益）
- 需要领导者临场语义裁决的流程（本 harness 领导者只做机械路由）

## 角色与职责（两件）

### 1. 领导者（唯一持锁）

- **独占选举**：一场会话恰好一个领导者；拿不到锁的实例自动降级为工作者
- **机械路由**：只按上一节回传的判定 JSON 选下一节与承担角色，不重评内容
- **合并校验**：链收尾时对全部产物做契约校验（产物齐全 / 格式合规），
  不通过则整链回退到首个失败链节
- **孤儿回收**：工作者失联时回收其未完成任务，重新入队

### 2. 工作者池（隔离执行）

- 每工作者一个隔离工作区 + 独立会话，互不可见对方未提交产物
- 工作者用可区分化名（worker-01 / worker-02…）注册，断连自动注销
- 崩溃自动重启（上限 3 次，超限标记失联交领导者回收）

## 责任链（五节契约）

```
Plan ──→ Build ──→ Verify ──→ Review ──→ Accept
blueprint   traceability    verification   review     acceptance
 .md        -map.md+证据/    -map.md+证据/  -judgment  -report.md
            │               │              .md        .md
            ▼               ▼              ▼          ▼
      下游读者: Verify/   Review/Accept   Accept    (链关闭)
      Review/Accept
```

每节固定三件套：**输入产物名 / 输出产物名 / 判定协议**。进入链节前先读上游
产物——缺失即 BLOCKED，上报领导者，不脑补继续。

## 判定协议（五选一变体）

每节完成时工作者回传结构化判定（JSON）：

| 判定 | 语义 | 领导者动作 |
|------|------|-----------|
| `pass` | 产物合格，按链推进 | 路由下一节 |
| `pass_with_notes` | 合格但有必须随链传递的注记 | 路由下一节，附注记 |
| `needs_rework` | 本节未过，附失败理由 | 本节重派原工作者 |
| `blocked` | 上游产物缺失/环境不可用 | 上报并暂停该链 |
| `escalate` | 超出契约覆盖范围 | 交人类决策者 |

规则：判定必须是五选一之一，理由字段非空；领导者不接收五选一之外的值。

## 工作者执行序列（八步）

1. 解析消息（链节、任务号、链号）
2. 按链节选指令模板（plan / execute / verify 指令文件之一）
3. 执行链节任务（独立会话）
4. 自评：用独立 fork 会话复核产物（不自评自产——fork 会话读产物、按本节
   验收清单逐项判定，解析失败重试 ≤3 次）
5. 自动提交本工作区改动（带任务号提交信息）
6. 组装判定 JSON + 产物索引，回传领导者
7. 落盘本节产物到约定目录（供下游链节读取）
8. 等待下一条消息或注销

## 协调后端（外部件位）

编排状态（任务队列 / 点对点消息 / 实例注册表）由外部协调后端承载，本
harness 不绑定实现：

- 单机场景：进程内消息传递（队列 + 路由 + 注册表三抽象）
- 多机场景：分布式锁 + 持久队列（如 ZooKeeper 一族）
- 契约不变：消息体与判定 JSON 的 schema、协议版本号由本 harness 定义，
  后端只负责可靠送达

## 目录记忆规则（不可协商）

1. 工作者全部产物落 `workspaces/{worker_name}/{date}/`，当日目录必须有一份
   `NOTES.md` 记录已完成子任务
2. 链节产物用责任链表中的固定文件名，禁止改名——下游按名读取
3. 读上游产物从约定目录读；写产物写到约定目录

## 维护约定

- 新增链节 = 责任链表加一行（输入/输出/判定三件套）+ 对应指令文件一件，
  不动既有链节
- 判定协议五变体增删 = 协议版本号 +1，旧版本判定不再被领导者接收
- 协调后端替换不动链节契约
