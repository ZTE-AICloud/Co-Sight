# AgentGenesis 运行时评分细则

> 来源: phases/phase5-runtime-eval.md — 评分协议
> 用途: 4 维度 × 5 级的人工/自动评分参考

---

## correctness — 准确性 (权重 40%)

Agent 找出的问题/结论是否准确？无误报？

| 分数 | 标准 |
|:----:|------|
| 5 | 全部 expected_output items 被正确识别，0 误报。每个发现准确对应到具体代码位置 |
| 4 | 主要发现正确，≤1 个微小误报（如规则编号正确但行号偏移 1-2 行） |
| 3 | 核心发现正确但存在误报（≤3 个）。或部分发现表述模糊无法验证 |
| 2 | 大量误报（>3 个），或关键 security/critical 发现为误报。核心结论存疑 |
| 1 | 几乎全错。误报为主，或 Agent 报告了完全不存在的漏洞/问题 |

---

## completeness — 完整性 (权重 30%)

Agent 是否覆盖了所有预期的关键发现？无遗漏？

| 分数 | 标准 |
|:----:|------|
| 5 | 100% required items 命中 + 全部 optional items 命中。超出预期的额外有价值发现 |
| 4 | ≥80% required items 命中。1 个 required 遗漏但非关键类别 |
| 3 | ≥60% required items 命中。遗漏 2 个 required 或 1 个关键类别遗漏 |
| 2 | ≥30% required items 命中。大量遗漏，关键漏洞未被检出 |
| 1 | <30% required items 命中。几乎未检出任何预期问题 |

---

## format_compliance — 格式合规 (权重 15%)

输出格式是否符合声明的 Schema/模板？是否可机器解析？

| 分数 | 标准 |
|:----:|------|
| 5 | 完全符合输出 Schema。Markdown 表格对齐、代码块标注语言、章节层次分明 |
| 4 | 基本符合，微小偏差（如表格缺少 1 列、章节标题层级偏差 1 级） |
| 3 | 可辨认预期结构但偏差明显（如缺少整个子章节、格式混用） |
| 2 | 结构破碎，关键字段缺失。需要人工解读才能提取信息 |
| 1 | 无结构，纯自由文本。无法对照 Schema 解析 |

---

## actionability — 可操作性 (权重 15%)

建议/报告是否可直接用于决策或修复？

| 分数 | 标准 |
|:----:|------|
| 5 | 每条建议包含：具体操作步骤 + 代码示例 + 预期效果。开发者可直接执行 |
| 4 | 大部分建议有具体操作，个别建议缺少代码示例但方向明确 |
| 3 | 半数建议可操作，其余为方向性指导（如"建议优化性能"） |
| 2 | 多数建议泛泛而谈。少量具体建议（≤2 条） |
| 1 | 无可执行建议。全部为泛泛表述（如"请修复此漏洞"） |

---

## 加权总分计算

```
weighted_score = correctness × 0.40 + completeness × 0.30
               + format_compliance × 0.15 + actionability × 0.15
```

## 通过阈值

| 指标 | 阈值 |
|------|:---:|
| 加权总分 | ≥ 3.5 |
| correctness (单维度) | ≥ 3.0 |
| completeness (单维度) | ≥ 3.0 |
