# 十二类 Agent 任务模式速查

> 来源: design/AgentGenesis-6月/Agent任务模式分析与执行模型.md
> 覆盖: 研发场景(6类) + 运维场景(3类) + 个人办公场景(3类)

## 研发场景

### 第一类: 探索与定义型
- **典型场景**: 产品设计、UX设计、需求分析
- **核心特征**: 高模糊性、高创造性、强主观性。产出是"认知共识"。
- **AgentGenesis 模式映射**: WF1-Proposal-Driven + K2-Document-Grounded + IH2-Interactive-Clarify
- **关键澄清问题**:
  1. 目标用户是谁？在什么场景下使用？
  2. 当前最大的痛点是什么？（能量化吗？如"对账时间 4h→30min"）
  3. 解决后预期带来什么价值？（有可度量指标吗？）
  4. 是否有现成的竞品或参考？
  5. 决策截止时间是什么？（不能无限精雕细琢）
- **管理本质**: 管"认知一致性"，而非管"进度"

### 第二类: 实施与构建型
- **典型场景**: 方案设计、编码开发
- **核心特征**: 高逻辑性、高复杂度、依赖深度心流
- **AgentGenesis 模式映射**: W1-Pipeline + G1-Reviewer-Gate + CD2-Safety-First + IT1-Enforced
- **关键澄清问题**:
  1. 技术栈有没有硬约束？（语言、框架、数据库、部署环境）
  2. 是否有现有代码库需要兼容？代码量多大？
  3. 接口契约（API/Proto）是否已定义？还是需要 Agent 设计？
  4. 模块粒度偏好？（单体/微服务/模块化单体）
  5. 有哪些架构约束？（如"禁止引入非团队维护的第三方库"）
- **管理本质**: 管"流体验"和"技术债利息"

### 第三类: 验证与校验型
- **典型场景**: 测试设计、系统验收、功能验收
- **核心特征**: 系统性思维、逆向破坏性、依赖环境稳定
- **AgentGenesis 模式映射**: G1-Reviewer-Gate + CD1-Input-Gating + DF1-Schema-Enforced
- **关键澄清问题**:
  1. 核心测试链路是哪些？（P0 级别不可失败的功能）
  2. 测试环境是否与生产对齐？（环境差异是最大坑）
  3. 缺陷分级 SLA？（P0 多久修复？P1 多久修复？）
  4. 需要哪些测试类型？（冒烟/系统/混沌/UAT/探索性）
  5. 验收标准是什么？（如"冒烟通过率 100% 才能提测"）
- **管理本质**: 管"风险覆盖度"，而非管"测了多少条"

### 第四类: 效能与基建型
- **典型场景**: 自动化测试、CI/CD 工具链、开发工具
- **核心特征**: 长期投资属性、高维护成本、ROI 驱动
- **AgentGenesis 模式映射**: W1-Pipeline + K4-Rule-Driven + CD1-Input-Gating
- **关键澄清问题**:
  1. 哪些用例值得自动化？（变更频率低 + 执行频率高 + 重复性高）
  2. 自动化覆盖率目标？（接口 ≥ 70%，UI ≤ 30%）
  3. 维护预算？（每个迭代预留 20-30% 时间修脚本）
  4. 失败时的熔断策略？（自愈几次后人工介入？推荐 ≤ 3 次）
- **管理本质**: 管"ROI"

### 第五类: 共识与传达型
- **典型场景**: Showcase、演示、周报同步
- **核心特征**: 信息翻译、信任建立。Agent 最不擅长的领域。
- **AgentGenesis 模式映射**: IH3-Plan-Approval + IV1-Progress-Streaming
- **关键澄清问题**:
  1. 听众是谁？（CTO / 业务方 / 开发者）
  2. 核心信息是什么？（3 句话能说清吗？）
  3. 有哪些已知风险需要主动坦诚？
- **管理本质**: 管"信息差"和"信任账户"。Agent 可汇总数据，但**人类翻译和信任建立不可替代**

### 第六类: 路由与分发型
- **典型场景**: 意图路由、命令分发、多技能调度、插件入口
- **核心特征**: 输入异构、路由表驱动、低延迟要求、插槽可扩展
- **AgentGenesis 模式映射**: W2-Router + K4-Rule-Driven + CD1-Input-Gating
- **关键澄清问题**:
  1. 路由键是什么？（意图/命令/文件类型/用户角色）
  2. 分发目标集合多大？（固定清单还是动态注册）
  3. 未命中路由时的行为？（默认兜底/追问用户/拒绝执行）
  4. 路由规则由谁维护？（人工表/自动生成/混合）
  5. 多目标同时命中时需要消歧吗？（优先级规则是什么）
- **管理本质**: 管"路由准确率"——误路由比不路由代价更高

## 运维场景

### 第七类: 监测与响应型
- **典型场景**: 监控告警、日志巡检、指标异常检测
- **核心特征**: 高时效性、事件驱动、7×24 不间断
- **AgentGenesis 模式映射**: W1-Pipeline + G1-Reviewer-Gate + CD1-Input-Gating + IV1-Progress-Streaming
- **关键澄清问题**:
  1. 监控哪些指标？（基础设施/应用/业务三层）
  2. 告警规则是什么？（P0 哪些？P1 哪些？阈值多少？）
  3. 告警频率预期？（日均几次？误报容忍度？）
  4. 告警后的动作？（自动执行/推送到人/自动+人工）
  5. 需要哪些数据源？（Prometheus、ELK、APM、自定义指标）
- **管理本质**: 管"告警精度"——误报太多人类会忽略，漏报太多没价值

### 第八类: 故障诊断与恢复型
- **典型场景**: 线上故障排查、根因定位、服务恢复
- **核心特征**: 不确定性高、有时效压力、需要系统拓扑知识
- **AgentGenesis 模式映射**: W2-Router + K3-KB-Backed + SM1-FSM + CD3-Knowledge-Boundary
- **关键澄清问题**:
  1. 系统拓扑是否已有建模？（CMDB、服务依赖图）
  2. 典型故障模式有哪些？（网络超时/磁盘满/内存泄漏/数据库死锁）
  3. 故障恢复 SLA？（MTTD 多久？MTR 多久？）
  4. 哪些恢复操作允许自动化？哪些必须人工审批？
  5. 历史故障数据是否有记录？（可用于学习）
- **管理本质**: 管"SLA"——MTTD（平均检测时间）和 MTR（平均修复时间）

### 第九类: 变更执行型
- **典型场景**: 部署发布、配置变更、安全补丁、扩容缩容
- **核心特征**: 流程固定但风险高、需要回滚预案、审批链
- **AgentGenesis 模式映射**: W1-Pipeline + G1-Reviewer-Gate + CD2-Safety-First + WF5-Contract-Lock
- **关键澄清问题**:
  1. 变更审批流程是什么？（谁审批？什么级别需要审批？）
  2. 回滚策略是什么？（自动回滚条件？一键回滚？）
  3. 变更窗口是什么？（工作日/非工作日？凌晨？）
  4. 变更验证步骤？（冒烟→健康检查→业务指标）
  5. 变更记录的合规要求？（审计日志保留多久？）
- **管理本质**: 管"变更成功率"——目标 > 99%，失败必有回滚

## 个人办公场景

### 第十类: 信息处理与摘要型
- **典型场景**: 邮件分拣、文档摘要、长文提炼、通知过滤
- **核心特征**: 输入量大、非结构化、需要区分优先级
- **AgentGenesis 模式映射**: W3-MapReduce + K1-LLM-Native + IH1-Fire-and-Forget
- **关键澄清问题**:
  1. 信息来源有哪些？（邮件/文档/聊天记录/通知）
  2. 每天处理量多大？（100 封邮件？1000 条通知？）
  3. 哪些类型需要人工决策？哪些可以自动处理？
  4. 输出格式偏好？（一句话摘要 / 结构化 Report / 分类标签）
  5. 隐私和安全约束？（敏感信息不能给外部模型处理）
- **管理本质**: 管"信息信噪比"——把海量信息变成少量需要人类决策的要点

### 第十一类: 安排与协调型
- **典型场景**: 会议安排、日程管理、任务优先级排序
- **核心特征**: 多方博弈、偏好约束、时间敏感
- **AgentGenesis 模式映射**: IH2-Interactive-Clarify + IV1-Progress-Streaming
- **关键澄清问题**:
  1. 参与者的时间偏好？（哪些时段不开放？哪些人必须参加？）
  2. 会议优先级规则？（谁的需求优先级更高？）
  3. 冲突处理策略？（自动解决 / 询问 / 让位）
  4. 需要哪些系统接入？（Google Calendar / Outlook / Slack）
  5. 会前准备？（自动生成议程？收集上次未完成项？）
- **管理本质**: 管"决策疲劳"——减少人类在非核心决策上的精力消耗

### 第十二类: 检索与整合型
- **典型场景**: 竞品调研、技术选型分析、知识整理、资料收集
- **核心特征**: 多源异构、需要交叉验证、结构化输出
- **AgentGenesis 模式映射**: K3-KB-Backed + DP1-Traceable-Lineage + IH1-Fire-and-Forget
- **关键澄清问题**:
  1. 信息源有哪些？（搜索引擎/内部文档/API/数据库）
  2. 时间范围？（最近一周/一个月/不限）
  3. 交叉验证要求？（需要 2 个以上独立来源确认吗？）
  4. 输出格式？（对比表 / 结构化报告 / 带引用的综述）
  5. 置信度要求？（每条结论是否需要标注来源和可信度？）
- **管理本质**: 管"信息质量"——每条结论必须可追溯到源，标注置信度
