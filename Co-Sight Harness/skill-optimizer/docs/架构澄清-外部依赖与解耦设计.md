# skillx-alpha-agents 架构澄清

> 写给其他团队的一页纸:本工具是什么、依赖什么、靠什么解耦业务。

## 一句话定位

**skillx-alpha-agents = 通用 Skill 进化编排器(Harness)**,只负责"评测 → 缺口分析 → 优化 → 再评测"的循环控制与产物管理。**业务细节一行代码都不写**,全部由外部环境 + 运行时参数注入。

## 核心观点:skillx-alpha-agents 是"空壳",业务都在外面

跑一次任务,本工具**只做编排**;评测怎么跑、Skill 在哪、属于哪个 Agent、跑哪些 CASE——**全部由调用方在外部准备,运行时通过 CLI 参数注入**。这意味着:

- **换业务 = 换外部环境 + 改参数,不改一行 Python**
- **本工具不持有任何业务知识**(不识别 `RAN-` / `phase3-eval` / 任何业务 schema)
- **故障定位快**:编排器异常归本工具,业务异常归业务方,边界清晰

## 外部依赖(4 类,缺一不可)

### 1. 评测流水线(最关键,必须稳定可靠)

- **形态**:业务方自有的 Python/Shell 脚本(`run_sdd_eval.py` / `run_batch.py` 等)
- **接入点**:`--pipeline-eval-cmd` + `--pipeline-base-dir`（或 `--pipeline-eval-sh` 替代 `--pipeline-eval-cmd`，明确"纯 shell 不 wrap"）
- **稳定可靠要求**(否则编排器无法判断失败原因):
  - 退出码 0 = 成功,非 0 = 失败
  - 产物落盘到约定目录(`data/phase*-*/*.json` 或业务方自定义)
  - 同 CASE 多次跑结果可重现(无随机种子漂移)
  - 单次超时上限可配置(避免编排器等死)
- **本工具的契约**:只负责"启动 + 捕获退出码 + 读产物",不替业务方兜底重试

### 2. 被测 Skill(优化目标)

- **形态**:一个或多个 `SKILL.md` 文件,放在某个 Agent 的 `skills/` 下
- **接入点**:`--skill-path`(单)或 `--skill-paths`(多,逗号分隔)
- **要求**:必须是文件路径,文件可读写(优化器要打补丁)
- **多 Skill 模式**:联合优化时,各 Skill 一起参与端到端评测,按聚合分数整体推进

### 3. 所在 Agent(联合优化的归属)

- **形态**:业务方 Agent 名称(如 `需求分析Agent`)
- **接入点**:`--agent-name`
- **作用**:决定 workspace 目录结构(`skills/{name}/` 而非 `skill/`)、审查报告命名、配置文件 schema 选择
- **未指定时**:自动从 Skill 父目录推断(`<skill 父目录的父目录名>`)

### 4. 辅助依赖(LLM API / 清理目录 / CASE 列表)

- **LLM API**:跑分数提取 + 优化提案,配置在 `.env` 的 `model.base_url` / `api_key`
- **清理目录**:每轮评测前清空的沙箱目录,通过 `user-config.yaml` 的 `need_cleaned_dir` 声明。**严禁列入多任务共享工作区根**(如 `evolution_workspace`)——它承载其他并行/历史任务的产物,清空会造成不可恢复的数据丢失。代码层 `clean_eval_data_sandbox` 有护栏:检测到目录含 `taskid_*` / `skill_create_*` 等任务产物子目录时会自动跳过,不整体清空;当前任务的 work_dir 由 `_clean_work_dir_if_already_exists` 单独精确清理。
- **CASE 列表**:从 `--pipeline-eval-cmd` / `--pipeline-eval-sh` 透传(如 `--req-id RAN-xxx,xxx`),不二次配置

> **总原则**:这些依赖的"接入方式"在本工具代码里是固定的(都是 CLI 参数或 env);依赖"本身"在外部,业务方自己维护。

## 实际例子:taskid_20260616_121208

```
Agent:     需求分析Agent → 3 个 Skill(特性域变更分析-变更点生成/用例筛选/filesearch-用例召回)
流水线:    python3 run_sdd_eval.py --req-id RAN-5030325,RAN-6640009,RAN-6412296
           --activity 需求分析 --sub-activity 特性域变更分析
轮次:      5 × 1 候选 × 1 run
产物:      /media/vdb/skillx-alpha/evolution_workspace/taskid_20260616_121208/
```

跑这次任务:`scripts/orchestrator.py` 一行没改,所有变化在 4 类外部依赖上。

## 其他团队接入流程(3 步)

1. **准备评测流水线**:确保退出码语义清晰、产物落盘约定路径、可重复跑
2. **指定 Skill + Agent 路径**:`/skill_evolve` 一行命令
3. **CC 二次确认后后台跑**:出问题先看业务方产物,再看编排器日志
