# Skill 全生命周期:效果 / 给谁用 / 收益

> **核心闭环**:`/skill_create`(从 0 到 1)→ `/skill_optimize`(静态体检)→ `/skill_evolve`(动态优化)→ 用户反馈 → 再次 `/skill_create` 增量扩展,4 步闭环可持续。

## 0. 摘要(纯文字版)

**`/skill_create`(从 0 到 1 · 5 颗星)**——**效果**:50 分钟内完成一个比较高可用程度的 Skill 制作。4 阶段流水线自动产出完整 Plugin 目录(SKILL.md + scripts/ + references/ + templates/),无需手工编排。**给谁用**:业务归属 BA(业务分析师)。懂业务但不一定懂工程,框架自动保证 16 章节硬约束、状态机、LLM 断点等规范,BA 只需聚焦业务需求。**收益**:节省 3~5 倍人力。**最关键的是搭建优秀骨架,减少后续维护的返工**——出生时骨架搭得好,后续 optimize/evolve 才有 5~10 倍维护杠杆。

**`/skill_optimize`(上线前体检 · 4 颗星)**——**效果**:30 分钟内完成诊断和优化。Skill 内所有文件全关联性分析,定位 7 类真实问题(元数据/章节结构/脚本错误/幽灵引用等),小修小改、精准修改。**给谁用**:Skill 维护人员。前提是原 Skill 骨架搭得比较好,或结构简单、逻辑简单;大改走 `--mode refactor`。**收益**:节省 2~3 倍人力。静态巡检 + 体检,无需经验丰富的工程师逐文件读 SKILL.md。

**`/skill_evolve`(上线后动态优化 · 5 颗星)**——**效果**:采集线上真实运行的 bad case,挖掘更深层的优化点。**补齐动态优化这个拼图**——有些优化必须实际运行才能发现,静态分析看不到。**给谁用**:上线后维护人员,需业务方提供 eval-cmd 和 CASE 数据。**收益**:节省 3~5 倍人力。聚合分 24.20 → 53.59(2× 突破,实证)。

**3 阶段互补关系**:`/skill_create` 和 `/skill_evolve` 同等重要(5 颗星)——前者决定"出生时有多好",后者决定"上线后能跑多远";`/skill_optimize` 是 4 颗星辅助体检。3 阶段**不可互相替代**。

## 2. 互补关系与不可替代性

`/skill_create` 和 `/skill_evolve` **同等重要**(5 颗星)——前者决定"出生时有多好",后者决定"上线后能跑多远";`/skill_optimize` 是 4 颗星辅助体检,适合"骨架已搭好 / 结构简单"的日常巡检。**3 阶段不可互相替代**:`/skill_create` 不能替代 `/skill_evolve` 的真实运行发现;`/skill_evolve` 不能替代 `/skill_create` 的从 0 设计;`/skill_optimize` 不能替代两者。
