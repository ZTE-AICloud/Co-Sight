# 技能

> 状态：**已定稿**。技能是「一个可被斜杠命令调用的技能目录」，本篇给出技能库扫描端点的请求与响应全貌。扫描是**只读现查**：一次请求内完成，不落库、没有技能表。
> 代码落点：`server/src/modules/skill/*`、`server/src/config/index.ts`（`skillsRoot`）、`server/src/shared/store/agents.repo.ts`（只读 `listByWorkspace`）。
> 验收测试：`server/tests/skills-api.test.ts`。
> 相关篇：[4.03 会话](./4.03-会话.md) §11（目录会话：技能工坊的会话形态）、[4.01 接口总览](./4.01-接口总览.md)、[4.13 智能体技能](./4.13-智能体技能.md)（把库技能复制进智能体产物）、设计依据 [`../03-architecture/10-skill-library.md`](../03-architecture/10-skill-library.md)。

## 1. 端点总表

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/smart-factory/v1/skills` | `?workspaceId=` | `200` `{ root, cwd, items: SkillItem[] }` |

请求与响应一律 `application/json; charset=utf-8`。本文 curl 以 `http://localhost:4100` 为基址，端口取自 `PORT`（缺省 4100）。

## 2. 技能库布局

```text
{COSIGHT_HOME}/smart-factory/
├── builtin-agents/            随包分发、只读；不往这里写用户数据
└── skill-workshop/            ← 工坊会话的 cwd（引擎在这里启动）
    ├── output/skills/         ← 技能库
    │   └── <name>/v1/{SKILL.md,references/,scripts/,templates/}
    └── .agent-genesis/work/   skill-foundry 的过程产物，不是技能库的一部分
```

| 项 | 取值 |
|---|---|
| 配置 | `config.skillsRoot`，env `SKILLS_ROOT`，缺省 `{COSIGHT_HOME}/smart-factory/skill-workshop` |
| 技能库（响应 `root`） | `{skillsRoot}/output/skills/` |
| 工坊会话 cwd（响应 `cwd`） | `{skillsRoot}` |

- **cwd 是 `skill-workshop/`，库在它的 `output/skills/` 下**：skill-foundry 的输出恒为 `<cwd>/output/skills/<name>/vN`，这是技能的固定约定，cwd 目录名与库名解耦。接口同时返回 `root` 与 `cwd`，前端一个都不拼（推导不出 `{COSIGHT_HOME}`，也不要在客户端做 `dirname`）。
- **`.agent-genesis/` 不进扫描面**：它是 skill-foundry 自己的过程目录（工作方案、门禁结果、fast 车道快照），跟着 cwd 走、不是用户资产；扫描只列 `{skillsRoot}/output/skills/*`，它天然不在其中。
- **全局共享**：技能库不属于任何工作区，切换工作区看到同一套 —— 技能是端侧用户的资产，不随工作区分叉。
- **智能体技能**：只算当前工作区、`source='user'` 的智能体；给了 `workspaceId` 才扫。两处来源，都归 `source='agent'`：
  - `<agent.dir>/development/output/skills/<name>/vN` —— 该智能体产出的独立技能；
  - `<agent.dir>/development/output/agents/<name>/<latest vN>/.claude/skills/<name>` —— **当前产物自带的技能**（构建器直接写入，或经 [4.13 装配](./4.13-智能体技能.md) 复制进来）。
- **不扫物化副本**：`preview/`、`evaluation/` 下的 `.claude/skills` 是起 run 前从产物整拷的副本，扫了同一技能会重复出现多次。
- **内置智能体不纳入**：`{COSIGHT_HOME}/smart-factory/builtin-agents/*/.claude/skills` 是随包定义，不是用户资产。

## 3. 请求

```http
GET /api/smart-factory/v1/skills?workspaceId=<uuid>
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `workspaceId` | 否 | uuid 形态，非法 `400`。给了才扫该工作区的智能体技能；不给只返回技能库。工作区不存在或框架不可达 `502`（与 agents 列表同口径） |

请求实例：

```bash
curl -s 'http://localhost:4100/api/smart-factory/v1/skills?workspaceId=8b1f0c2d-4e5a-4b6c-9d7e-1f2a3b4c5d6e'
```

## 4. 响应

响应实例 `200`：

```json
{
  "root": "/home/u/.cosight-harness/smart-factory/skill-workshop/output/skills",
  "cwd": "/home/u/.cosight-harness/smart-factory/skill-workshop",
  "items": [
    {
      "name": "report-gen",
      "path": "/home/u/.cosight-harness/smart-factory/skill-workshop/output/skills/report-gen",
      "source": "library",
      "ownerAgentId": null,
      "ownerName": null,
      "version": "v1",
      "description": "把周报整理成固定格式",
      "updatedAt": "2026-10-22T05:10:00.000Z"
    },
    {
      "name": "code-review",
      "path": "/ws/.smart-factory/agents/agt_xxx/development/output/skills/code-review",
      "source": "agent",
      "ownerAgentId": "agt_xxx",
      "ownerName": "代码审查",
      "version": "v2",
      "description": "",
      "updatedAt": "2026-10-21T11:00:00.000Z"
    },
    {
      "name": "rag-knowledge-search",
      "path": "/ws/.smart-factory/agents/agt_xxx/development/output/agents/rag-agent/v1/.claude/skills/rag-knowledge-search",
      "source": "agent",
      "ownerAgentId": "agt_xxx",
      "ownerName": "RAG 检索智能体",
      "version": "",
      "description": "基于 co-knowledge RAG 服务的知识检索 skill",
      "updatedAt": "2026-10-28T03:28:00.000Z"
    }
  ]
}
```

顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `root` | string | 技能库目录绝对路径（`{skillsRoot}/output/skills`），用于展示与「技能所属目录」 |
| `cwd` | string | 工坊会话根绝对路径（`{skillsRoot}`），**创建目录会话时原样传给 `sessions/create` 的 `cwd`**（见 [4.03 会话](./4.03-会话.md) §11） |
| `items` | SkillItem[] | 技能项，`library` 在前、`agent` 在后 |

`SkillItem` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | `SKILL.md` frontmatter 的 `name`；缺失或解析失败回落为目录名 |
| `path` | string | **技能目录的绝对路径，不是版本目录**；优化时作为目标传给 skill-foundry |
| `source` | `'library'` \| `'agent'` | 来源：技能库 / 智能体产出 |
| `ownerAgentId` | string \| null | `source='agent'` 时为产出该技能的智能体 id；`library` 恒为 `null` |
| `ownerName` | string \| null | 同上智能体的展示名；`library` 恒为 `null` |
| `version` | string | 技能目录下 `v<数字>` 子目录中数字最大的一个（如 `v2`）；没有版本子目录时空串 |
| `description` | string | frontmatter 的 `description`；缺失或解析失败为空串 |
| `updatedAt` | string | 技能目录 mtime 的 ISO 8601 串 |

`source` / `ownerAgentId` / `ownerName` 是**落点判据**（§6），前端不得靠路径字符串猜来源。

## 5. 扫描规则

一次请求内完成，不落库：

1. **技能库**：列 `{skillsRoot}/output/skills/*`，每个目录一项，`source='library'`、`ownerAgentId=null`。库目录不存在（首次使用前还没有产物）按空处理，不报错。
2. **智能体技能**（给了 `workspaceId` 才扫）：查该工作区 `source='user'` 的智能体，逐个扫两个面：
   - `<agent.dir>/development/output/skills/*` —— 产出的独立技能；
   - 当前产物 `<agent.dir>/development/output/agents/<name>/<latest vN>/.claude/skills/*` —— 产物自带技能。版本取最新 `vN`（与运行期一致）；产物目录缺失或布局不唯一（不是恰好一个智能体目录 / 没有 `v*`）时这一面按空处理，不报错。

   两面的目录不存在都按空处理（ENOENT 忽略，其它错误照常抛）；同一条技能在两面都存在时各出一项（与库内同名技能同口径）。
3. **每一项**：
   - `version`：目录内 `v<数字>` 子目录里数字最大的一个（按数字比较，不按字典序 —— `v1` 与 `v10` 并存时取 `v10`）；没有则空串；
   - `name` / `description`：读 `SKILL.md` 的 YAML frontmatter（只读头部 8KB）；解析失败或字段缺失时 `name` 回落为目录名、`description` 为空串 —— **扫描不因一个坏文件整体失败**，其余项不受影响；
   - `updatedAt`：技能目录 mtime（ISO 串）。
4. **排序**：`library` 在前、`agent` 在后；组内按 `updatedAt` 倒序，同毫秒按 `name` 升序兜底。

## 6. 落点判据（供前端，写在这里免得两头对口径）

| source | 优化的落点 |
|---|---|
| `library` | 技能工坊（目录会话，`cwd` = 响应里的 `cwd` 字段） |
| `agent` | 该智能体的设计页（开发阶段），cwd 由 `(agentId, development)` 推导 |

优化目标一律传 **`path` 绝对路径**，不传名字 —— 两路来源可能同名。

同一技能的创建会话与优化会话共用一个 cwd（工坊场景恒为 `{skillsRoot}`），靠会话名区分（优化场固定 `优化 <name>`），不给每个技能单独开 cwd；优化会话的 cwd 不下探到技能目录 —— 库在 `output/skills/` 下，下探会把 `.agent-genesis/work/` 写进技能工程。

## 7. 根目录初始化

服务启动时 ensure `{skillsRoot}/output/skills/` 存在（`mkdir -p`，连同 `{skillsRoot}` 一起建；失败只记日志，不阻断启动）。理由：目录会话的 cwd 必须存在，而 `skill-workshop/` 第一次用时可能还没建过。

## 8. 错误

| HTTP | `error` | 触发条件 |
|---|---|---|
| 400 | `BAD_REQUEST` | `workspaceId` 形态非法（非 uuid） |
| 502 | `BAD_GATEWAY` | `workspaceId` 给了但框架不可达 / 工作区未绑定目录（与 agents 列表同口径） |

库目录不存在返回 `200` + `{ root, cwd, items: [] }`，不报错（首次使用前还没有产物）。
