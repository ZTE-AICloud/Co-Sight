# Smart Factory Web 交接：近期协议与字段变更

> 状态：**已定稿**。本文列出近期后端改动中 smart-factory web 需要跟进的事项。
> 代码落点：`web/src/shared/types/index.ts`、`web/src/shared/api/sessions.ts`、`web/src/shared/live/useLiveSession.ts`、`web/src/shared/live/envelope.ts`、`web/src/features/session-debug/SessionDebugPage.tsx`、`web/src/features/agent-create/useCreationChat.ts`。
> 相关篇：[4.03 会话](./4.03-会话.md)、[4.05 运行](./4.05-运行.md)、[4.06 实时通道](./4.06-实时通道.md)、[4.08 任务中心查询交接](./4.08-任务中心查询交接.md)。

## 1. 结论

先按「现有页面会不会出错」分层，避免把契约同步项误当成线上故障。

### 1.1 现有功能会受影响

- `approvedAll` 从 Run 移到 Session：调试页当前读 `live.run.approvedAll`，会显示「否」。主对话不受影响。
- `sessions/create` 与首帧 `send { agentId }` 现在要求非空 `modelId`：不传或传空串会返回 400。Web 端在 `preview` / `evaluation` 首次建会话前自己解析默认模型（`workspaces/list` 的 `defaultModelId` → `models/list` 的 `activeId` → 列表第一项），解析后仍显式传 `modelId`。
- `agents/create` 带 `init` 时 `init.modelId` 同样必填且非空；空串或缺失会返回 400。
- `subscribe` 补发帧改为 `approval.request` / `tool.interactive`：`openSession` 只拉最近 50 条，早于 50 条的挂起审批会漏。这是边界场景。
- `chat.thinking.delta` 删除：当前 web 只缓冲、不渲染，因此没有可见故障；如果以后要用思考流式，必须改。

### 1.2 契约/类型需要同步

- Session 响应字段 `mode` 改为 `approvalMode`；当前 web 没有读取 `mode`，所以不是运行时中断，但类型必须补 `approvalMode`。
- `send` 响应 `run.status` 改为 `running`；web 的 `applyRun` 已兼容，类型和注释同步即可。
- `send` 响应不再有 `created`；`send { agentId }` 每次都新建会话，`send { sessionId }` 才是续聊。
- `PageResult` 补 `page` / `pageSize`；附加字段，现有代码可忽略。
- Session 补 `messageCount` / `lastMessage` / `firstUserMessage` / `effort` / `resumeSessionId`；按需使用。

### 1.3 不需要改

- REST 错误体、`mode.switch` 请求载荷、`settings.changed` 的 `mode` 键、agent 列表的 `keyword`、`messages/list` 与 `messages/respond`、产物接口、`pageSize` 的 200 上限与非法值回落。

## 2. 现有功能会受影响

### 2.1 会话字段 `mode` 改为 `approvalMode`

后端 `Session` 响应不再返回 `mode`，改为返回 `approvalMode`，取值不变：`read_only` / `workspace_write` / `full_access`。

数据库列仍叫 `mode`，但 HTTP 与 WS 的会话 DTO 只暴露 `approvalMode`。

Web 的 `Session` 类型当前没有 `mode` 字段，因此现有页面不会被运行时读空。

这一项不是当前页面的运行时故障，而是字段契约变更；如果 web 现在没有读会话审批模式，可以只改类型，不改逻辑。

但类型定义必须补 `approvalMode`，不能继续按 `mode` 读取会话。

WS 方法名仍是 `mode.switch`，请求载荷仍是 `{ sessionId, mode }`，响应仍是 `{ sessionId, mode }`。

`settings.changed` 的 `settings` 对象仍用 `mode` 键，与 agent-runtime 保持一致，不要改成 `approvalMode`。

### 2.2 `approvedAll` 从 Run 移到 Session

后端删除了 `Run.approvedAll`，并在 `Session` 上新增 `approvedAll`。

`approved_all` 现在是会话级：

- 用户选择 `approved_all` 后，当前会话的 `approvalMode` 切到 `full_access`，`approvedAll` 置为 `true`。
- 同一个 run 的后续审批自动放行。
- 该会话之后的新 run 继续继承，不再逐条挂起。
- 用户把 `approvalMode` 切到 `read_only` 或 `workspace_write` 时，`approvedAll` 自动清零。

Web 需要改的地方：

- `web/src/shared/api/sessions.ts` 的 `Run` 类型删除 `approvedAll`。
- `Session` 类型新增 `approvedAll: boolean`。
- `web/src/features/session-debug/SessionDebugPage.tsx:598` 当前读 `live.run.approvedAll`，改为 `live.session.approvedAll`。
- 同一行的文案「是（本 run）」改为「是（本会话）」。

审批选项文案「本会话全部允许」与新的会话级语义一致，不需要改文案。

### 2.3 `chat.thinking.delta` 改为 `chat.thinking`

后端只发送一个思考事件 `chat.thinking`，带三个阶段：

```json
{
  "sessionId": "sess_xxx",
  "runId": "run_xxx",
  "parentRunId": null,
  "phase": "start | delta | stop",
  "text": "仅 phase=delta 时出现",
  "at": "2026-10-20T02:13:07.415Z"
}
```

旧的 `chat.thinking.delta` 不再发送。

当前 web 只缓冲、不渲染 thinking；如果不需要思考流式，可以删掉旧 handler；如果要展示，必须改。

Web 需要改的地方：

- `web/src/shared/live/useLiveSession.ts:268` 的注释改为「thinking 走 chat.thinking」。
- `web/src/shared/live/useLiveSession.ts:276` 的 `case 'chat.thinking.delta'` 改为 `case 'chat.thinking'`。
- `phase === 'delta'` 时把 `text` 追加到 thinking 缓冲。
- `phase === 'start'` / `'stop'` 不带正文，不要追加。
- `chat.delta` 仍然只带正文，且 `messageType` 恒为 `'text'`。

### 2.4 `subscribe` 补发帧改为兼容事件

后端在 `subscribe.result` 之后补发的挂起帧，已经从 `message` 改为：

- `approval.request`
- `tool.interactive`

Web 当前的 `useLiveSession` 只处理 `message` 事件，不处理这两个兼容事件。

`openSession` 在订阅后只拉最近 50 条消息，如果挂起的审批早于这 50 条，会看不到。

这是边界场景的回归风险，不是每次都发生。

建议二选一：

1. 在 `openSession` 订阅成功后补一次 `messagesApi.list({ sessionId, status: 'pending', limit: 200 })` 并合并。
2. 在 `onEvent` 中处理 `approval.request` / `tool.interactive`，按 `approvalId` / `toolCallId` 转成挂起卡片。

方案 1 改动更小，也复用现有 `refetchPending`。

### 2.5 `send` 语义与响应

WS `send` 的两个入口现在严格区分：

- `send { sessionId, prompt }`：续聊已有会话，使用会话的 `modelId` / `approvalMode` / `effort`；携带 `modelId` / `mode` / `effort` 会返回 `VALIDATION`。
- `send { agentId, modelId, mode?, effort?, prompt }`：**每次新建一条 runtime 会话**，不复用已有会话；`modelId` 必填非空，`mode` 缺省 `workspace_write`，`effort` 缺省 `high`。
  `sessions/create` 同样要求非空 `modelId`（预览 / 评估的默认模型由 Web 端解析后传入）。

响应现在是：

```json
{
  "sessionId": "sess_xxx",
  "runId": "run_xxx",
  "instanceId": "inst_xxx",
  "status": "running",
  "effort": "high",
  "modelId": "模型 uuid",
  "modelName": "供应商模型名",
  "modelFellBack": false,
  "message": {},
  "run": {}
}
```

其中 `run.status` 是 `running`，不再是 `pending`；响应**没有** `created` 字段。

`run.started` 在响应之前广播，因此事件可能先于响应到达。

Web 需要改的地方：

- `web/src/shared/api/sessions.ts` 的 `SendResult` 类型补顶层字段：`sessionId`、`runId`、`instanceId`、`status`、`effort`、`modelId`、`modelName`、`modelFellBack`；删除 `created`。
- `web/src/shared/api/sessions.ts` 的 `create` 调用必须传 `modelId`（预览 / 评估的默认模型由 Web 端按工作区默认 → 框架生效 → 列表第一项解析后传入）；新建对话走 `send { agentId, modelId, mode?, effort? }`，续聊走 `send { sessionId }`。
- `web/src/shared/api/sessions.ts:321` 的注释「run.status 恒为 pending」改为「run.status 为 running」。
- `web/src/shared/live/useLiveSession.ts:28`、`:194`、`:502` 的 pending 说明同步更新。
- 现有 `applyRun` 的状态前进方向已经能处理 `running`，不需要改逻辑。

### 2.6 WS 响应方法与错误码

后端响应方法改为：

- 普通请求：`<request>.result`，例如 `send.result`、`mode.switch.result`。
- `ping`：`pong`。

WS 错误码改为：

- `VALIDATION`
- `NOT_FOUND`
- `CONFLICT`
- `INTERNAL`

不再发送 `BAD_REQUEST` 与 `INTERNAL_ERROR`。

Web 的 `LiveClient` 按 `envelope.id` 匹配响应，不按 `method` 匹配，因此运行时不受影响。

需要更新的是注释与判断：

- `web/src/shared/live/envelope.ts:11` 的「没有 .result 后缀」改为新规则。
- `web/src/shared/live/envelope.ts:31` 的错误码列表改为 `VALIDATION` / `NOT_FOUND` / `CONFLICT` / `INTERNAL` / `SLOW_CONSUMER`。
- 如果业务代码里判断 `BAD_REQUEST` / `INTERNAL_ERROR`，改为新码；当前 `web/src` 没有这类判断。

`pong.serverTime` 是毫秒时间戳数字，Web 当前忽略该字段即可。

`CONFLICT` 的语义：审批应答冲突、run 已终态，以及活跃顶层 run 冲突（本端点条件见 [`4.04 消息`](./4.04-消息.md) §5 与 [`4.03 会话`](./4.03-会话.md) §5）。
`runtime` 的不同会话可并发，`send { agentId }` 的并发首帧都能成功；完整不变量见 [`02-data-model.md`](../03-architecture/02-data-model.md) §6。

### 2.7 子 run 事件与 `runs/children`

后端新增：

- `task.started`：子 run 开始。
- `task.notified`：子 run 结束，`status` 为 `completed` / `failed` / `stopped`。
- `GET /runs/children?runId=&page=&pageSize=`：返回直接子 run。

`runs/list` 现在只返回顶层 run，子 run 不再混入。

如果 Web 暂时不展示子 agent，可以忽略这些事件，现有页面不受影响。

如果要展示子 agent，需要：

- 在 `Run` 类型上保留 `parentRunId` / `parentToolUseId` / `subagentType` / `delegationDepth` / `taskId`。
- 在 `runsApi` 增加 `children(runId, page, pageSize)`。
- 处理 `task.started` / `task.notified`，用 `runId` 维护子 run 状态。
- 注意 `task.notified.status` 是 `completed` / `failed` / `stopped`，不要和本地 `Run.status` 的 `succeeded` / `failed` / `aborted` 混用。

## 3. 建议改

### 3.1 分页响应补 `page` / `pageSize`

后端的分页响应现在是：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

涉及：

- `GET /agents`
- `GET /sessions/list`
- `GET /runs/list`
- `GET /runs/children`
- `GET /evaluations/list`
- `GET /evaluations/cases/list`

Web 的 `PageResult` 在 `web/src/shared/types/index.ts:17`，当前只有 `items` / `total`。

建议补 `page` / `pageSize`，任何分页 UI 直接用服务端回显值。

注意：`GET /artifacts/list` 是目录平铺，不分页，仍是 `{ items, total }`。

Web 的 `web/src/shared/api/artifacts.ts:69` 不要继续用 `PageResult<ArtifactEntry>`，改成 `{ items: ArtifactEntry[]; total: number }`。

### 3.2 Session 派生字段

后端 Session 响应新增：

- `messageCount`：会话全部消息数，所有类型都算。
- `lastMessage`：最近一条 `type='text'` 消息的纯文本；列表填充，详情 / 创建 / 更新恒为 `null`。
- `firstUserMessage`：第一条 `role='user'` 且 `type='text'` 消息的纯文本；列表填充，详情 / 创建 / 更新恒为 `null`。

Web 可以在会话列表显示消息数与最后一条正文。

`lastMessage` / `firstUserMessage` 都是纯文本，不需要再解析 JSON。

### 3.3 Session 其他字段

Session 响应还完整返回：

- `modelId`，恒非空（没有空串 auto 语义）
- `effort`
- `resumeSessionId`
- `approvalMode`
- `approvedAll`
- `messageCount`
- `lastMessage`
- `firstUserMessage`

Web 的 `Session` 类型当前只有 `id` / `instanceId` / `name` / `status` / `modelId` / `instance` / 时间。

建议把上述字段补齐，避免以后读取时缺类型。

### 3.4 会话列表过滤

后端 Session 列表新增：

- `instanceId`
- `status`，支持逗号分隔多值
- `name`，子串
- `id`，逗号分隔多值
- `createdFrom` / `createdTo`，ISO 时间
- `type`，`development` / `preview` / `runtime` / `evaluation` / `all`，支持逗号分隔
- `stage` / `type` 都不传、也没给 `instanceId` / `cwd` / `id` / `resumeSessionId` 时，**默认只返回 `runtime` 会话**（`agentId` 不取消默认）；设计页按阶段显式传，工坊传 `stage=development`（配 `cwd`）
- `subjectType`，目前只支持 `agent`
- `subjectId`，等价于 `agentId`

现有 `agentId` / `stage` / `resumeSessionId` 保持不变。

Web 如果不需要这些过滤，可以不改；类型上可以按需补。

### 3.5 `settings.changed` 与 `chat.retry`

Web 当前不处理 `settings.changed`。

如果希望其它客户端切换模型 / 模式 / 强度后当前页面实时更新，可以处理该事件。

`settings.changed` 的 `settings` 仍是 `{ mode, effort, modelId }`，不是 `approvalMode`。

`chat.retry` 是新增的引擎重试事件，包含 `attempt` / `maxRetries` / `errorStatus` / `error`，可选展示。

## 6. 不需要改

- REST 错误体仍是 `{ error, message }`，不是 agent-runtime 的 `{ code, message, data, reason }`。
- `mode.switch` 方法名与 `{ mode }` 载荷不变。
- `settings.changed` 的 `settings` 键仍是 `mode`。
- `agents` 列表仍用 `keyword` 搜索，不新增 `name` / `id` / `description` 过滤。
- `messages/list`、`messages/respond` 形状不变；`messages/send` 的语义与响应变化见 §2.5。
- `sessions/:sessionId/update` 仍只收 `modelId`，但空串不再合法；`sessions/delete`、`sessions/abort` 形状不变。
- `sessions/create` 仍返回完整的 `Session`，但现在必须带非空 `modelId`。
- `artifacts/list`、`artifacts/file`、`artifacts/download` 形状不变。
- `pageSize` 仍是缺省 20、上限 200、非法值回落，不改成 400。
- `agentId` 前缀仍是 `agt_`，不改成 `agent_`。
- 不引入 `versionId`。

## 7. 验收

Web 侧至少执行：

```bash
cd web
npm run typecheck
```

手工验收：

1. 打开会话，确认会话快照能显示 `approvalMode` 与 `approvedAll`。
2. 在调试页确认「允许所有」读的是会话级 `approvedAll`，文案为「本会话」。
3. 选择「本会话全部允许」后，当前 run 后续审批不再挂起；会话详情显示 `approvalMode=full_access`、`approvedAll=true`；新 run 也不再逐条挂起。
4. 把审批模式切到 `workspace_write`，确认 `approvedAll` 变为 `false`。
5. 制造一条早于最近 50 条消息的挂起审批，重连或重新进入会话，确认审批卡仍能出现。
6. 观察思考事件，确认 `chat.thinking` 的 `start` / `delta` / `stop` 不再被当成未知事件丢弃。
7. 发送消息，确认 `send` 返回后 run 状态是 `running`，界面不回到「pending」，响应里没有 `created`。
8. 如果有子 agent 展示，确认 `task.started` / `task.notified` 与 `runs/children` 的状态能收敛。
9. `sessions/create` 不带 `modelId` 返回 400；带上非空 `modelId` 后创建成功，Session 的 `modelId` 非空。
10. 连续两次首帧 `send { agentId, modelId }` 得到不同的 `sessionId`；用第一次的 `sessionId` 续聊成功；续聊时携带 `modelId` 返回 `VALIDATION`。
