# 功能接口文档

> 状态：**草案**。本文是**单份整合视图**：把全部功能域（工作区、智能体、会话、消息、运行、产物、文件、模型、探活、WebSocket）的接口形状汇总在一篇里，供对接方一次读完。
> 代码落点：`server/src/app.ts`（路由挂载）、`server/src/modules/*/**.controller.ts`、`server/src/shared/live/ws-gateway.ts`。
> 依据与细节：与已定稿各篇（[4.01](./4.01-接口总览.md) ~ [4.08](./4.08-接口与商用版本差异.md)）及 OpenAPI（[`5.01`](../05-openapi/5.01-agent-openapi.yaml) / [`5.02`](../05-openapi/5.02-file-openapi.yaml)）冲突时，**以各篇为准**，本文只负责「一份读全」。

## 1. 通用约定

- **基址** `/api/smart-factory/v1`，REST 与 WebSocket 同端口。端口来自 `PORT`（缺省 `4100`），监听地址 `HOST`（缺省 `0.0.0.0`）。开发态前端经 vite 代理 `/api` 转发，前端只写相对路径。
- **方法**：只用 `GET` / `POST`。动作走后缀：`/create` `/update` `/delete` `/abort` `/send` `/respond` `/list` `/detail`。
- **成功响应**一律 `200`，没有 `201` / `204`。
- **id 传法**：`agents` 域资源身份进路径（`/agents/{agentId}/update`，ADR 0002）；其余集合级端点 id 进 query（GET）或请求体（POST）；`sessions/:sessionId/update` 照 agents 模式走路径。
- **分页**：`page`（缺省 1）、`pageSize`（缺省 20，上限 200）；响应 `{ items, total }`。消息域用游标（见 §6.1）。
- **时间**一律 ISO 字符串。请求体 JSON 上限 2mb，`CORS_ORIGIN` 缺省 `*`。
- **鉴权**：无。本服务只在本机使用；对框架（Cosight）的访问用模块令牌，调用方无感。

**错误响应**统一 `{ error: <CODE>, message: <中文可读> }`：

| HTTP | CODE | 何时 |
|---|---|---|
| 400 | `BAD_REQUEST` | 参数缺失、形态非法、枚举非法、JSON 解析失败、超过 2mb |
| 404 | `NOT_FOUND` | 资源不存在或无匹配路由 |
| 409 | `CONFLICT` | 状态冲突（已有活跃 run、已结算、已终态等） |
| 413 | `PAYLOAD_TOO_LARGE` | 产物读文本超 2MB、上传超 10MB |
| 502 | `BAD_GATEWAY` | 依赖的框架工作区不可解析（agents / artifacts / workspaces） |
| 502 | `FRAMEWORK_UNAVAILABLE` | 模型代理上游失败（框架没起、令牌缺失/被拒、协议不识别） |
| 500 | `INTERNAL_ERROR` | 未处理异常 |

## 4. 智能体 agents

契约另见 [`../05-openapi/5.01-agent-openapi.yaml`](../05-openapi/5.01-agent-openapi.yaml)。**资源身份一律进路径**。

### Agent 对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 全局主键，同时是产物目录名 |
| workspaceId | string | 框架工作区 id，建后不可改 |
| name | string | 1–40 字，同一工作区内唯一 |
| description | string | ≤120 字，可空 |
| tags | string[] | 单个 1–10 字、不含 `" \ % _`、最多 10 个、去重保序，缺省 `[]` |
| icon | string | 封面图 URL，只管长度 ≤512，缺省 `''`（前端落名称首字头像） |
| status | string \| null | 派生产物状态：`not_started` / `building` / `blocked` / `failed` / `completed`；内置智能体恒为 `completed`（开箱即用）。普通行与 `GET /agents/{id}/production` 同源 |
| createdAt / updatedAt | string | ISO |
| dir | string | 现算不入库：`<工作区 directory>/.smart-factory/agents/{id}` |

### 4.1 GET /agents —— 列表

| query | 说明 |
|---|---|
| keyword | 名称模糊匹配 |
| tag | **精确匹配**（非子串），只收一个 |
| workspaceId | uuid，精确过滤 |
| page / pageSize | 通用分页 |

→ `{ items: Agent[], total }`。

### 4.2 POST /agents —— 创建

```json
{ "workspaceId": "<必填 uuid>", "name": "必填 ≤40 字", "description": "可选 ≤120", "tags": ["可选"], "icon": "可选 ≤512" }
```

→ `Agent`。`400` 形态非法；`409` 与同工作区已有智能体重名；`502` 工作区在框架里不存在或未绑定目录。建行成功而建目录失败时回滚删行。

### 4.3 GET /agents/:agentId —— 详情

→ `Agent`；`404` 不存在。

### 4.4 POST /agents/:agentId/update —— 更新

请求体只带要改的字段，**至少给一个**否则 `400`：`name` / `description` / `tags` / `icon` / `status`。

- 「没给」= 字段缺失或 `null`；`description: ""`、`tags: []`、`icon: ""` 是**清空**，不是「不改」。
- 身份与 `workspaceId` 不可改，传了按多余字段忽略。

→ `Agent`；`404` 不存在；`502` 工作区不可解析（此时不改任何行）。

### 4.5 POST /agents/:agentId/delete —— 删除

**无请求体**。→ `{}`。

`404` 不存在；`409` 内置智能体不可删；`502` 工作区不可解析（什么都不删）。四个 stage 任一实例有活跃 run 时先停掉这些会话（等价于逐个 abort）再删，不返回 `409`。删除先停运行、再删盘、后删库；不幂等，重复删 `404`。

## 5. 会话 sessions

### Session 对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| instanceId | string | |
| name | string | 缺省 `''` |
| status | string | `not_started` / `in_progress` / `completed` |
| modelId | string | 会话级模型 id；**空串 = 跟随本机 Claude Code 配置**，起 run 时原样下发 SDK |
| createdAt / updatedAt | string | |
| instance | Instance | 内联，见下 |

**Instance**（无独立资源路径，由 `(agentId, stage)` get-or-create）：`{ id, agentId, stage, engine, createdAt, updatedAt }`，`stage ∈ development / preview / runtime / evaluation`。

### 5.1 GET /sessions/list

| query | 说明 |
|---|---|
| agentId | 过滤；未知 id 是**空页**不是 404（取数才 404） |
| stage | 四值枚举，空串视为未传 |
| page / pageSize | 通用分页 |

→ `{ items: Session[], total }`。

### 5.2 POST /sessions/create

```json
{ "agentId": "必填", "stage": "缺省 development", "name": "缺省 ''", "modelId": "缺省 ''" }
```

→ `Session`。`404` 未知智能体；`409` 该实例已有活跃 run。

### 5.3 GET /sessions/detail?sessionId=

→ `Session`；`404`。

### 5.4 POST /sessions/:sessionId/update —— 切换会话模型

唯一可变字段：`{ "modelId": "<id 或空串>" }`；空串 = 清除回跟随本机配置。run 间隙生效，正跑的 run 不受影响。

→ `Session`；`404`；`409` 有活跃 run；`400` 没给 `modelId`。

### 5.5 POST /sessions/delete

```json
{ "sessionId": "必填" }
```

→ `{}`。级联删消息与运行记录；`404`；`409` 有活跃 run（先 abort）。

### 5.6 POST /sessions/abort

```json
{ "sessionId": "必填" }
```

→ 中止后的 `Run`（等价于中止它当前的活跃 run）。`404`；`409` 没有活跃 run。

## 6. 消息 messages

### Message 对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | |
| sessionId / runId | string / string\|null | |
| seq | number | 会话内递增；分页游标就是它 |
| role | string | `user` / `assistant` / `system` |
| type | string | `text` / `thinking` / `tool_use` / `tool_result` / `approval` / `tool_interactive` / `error` / `status` |
| status | string\|null | `pending` / `approved` / `approved_all` / `rejected` / `answered` / `aborted`；非交互类恒 null |
| content | object | 形状按 type，见下 |
| createdAt | string | |

**content 形状**（库里 JSON 字符串，接口层恒为对象）：

- `text`：`{ "text": "..." }`；`error`：`{ "message": "..." }`。
- `approval`：`{ toolCallId?, toolName?, title, description?, input?, allowAll?, decision?, decisionSource? }`。挂起时只有前半；`allowAll` 缺省可「本会话全部允许」，仅引擎明确禁止时 `false`；结算后追加 `decision ∈ approved / approved_all / rejected / aborted` 与 `decisionSource ∈ user / approved_all_auto / abort / restart`。
- `tool_interactive`：`{ toolCallId?, toolName?, questions: [{ header, question, options?: [{ label, description? }], multiSelect? }], answers?: { "<question 原文>": ["选项", ...] } }`。

### 6.1 GET /messages/list

| query | 说明 |
|---|---|
| sessionId / runId | **必给且只给一个**，否则 `400` |
| afterSeq / beforeSeq | 向下续拉 / 向上翻页，**互斥**，同给 `400` |
| limit | 缺省 50，上限 200 |
| status | 六值枚举，空串视为未传 |

→ `{ items: Message[], nextAfterSeq: number | null }`。seq 升序；**无游标 = 最近 limit 条**；`nextAfterSeq` 仅在返回条数等于 limit 时非 null。

### 6.2 POST /messages/send

```json
{ "sessionId": "必填", "prompt": "必填" }
```

→ `{ "message": <user 消息>, "run": <新 run（pending，waiting=null）> }`。落 user 消息、会话转 `in_progress`、起 run 并后台驱动引擎。`404`；`409` 已有活跃 run（先于任何写入，无副作用）。

### 6.3 POST /messages/respond —— 结算挂起

```json
{ "messageId": "必填", "decision": "approved | approved_all | rejected", "answers": { "问题原文": ["选项"] } }
```

- `approval` 消息：必给 `decision` 三选一；`approved_all` 会置 run 级开关（本 run 后续审批自动通过，新 run 复位）。
- `tool_interactive` 消息：必给 `answers`，形状 `{ 问题原文: [选项字符串] }`，空对象 = 未作答。

→ 结算后的 `Message`。`404` 不存在或非交互类；`409` 已结算；`400` 载荷与 `type` 不匹配。

## 7. 运行 runs

### Run 对象

| 字段 | 类型 | 说明 |
|---|---|---|
| id / sessionId / instanceId | string | |

| error | string\|null | failed 时的可读原因 |
| approvedAll | boolean | 「允许所有」只管本 run，新 run 默认回到逐条审批 |
| startedAt / finishedAt | string\|null | |

### 7.1 GET /runs/list?sessionId=&page=&pageSize=

→ `{ items: Run[], total }`；`404` 未知会话。

### 7.2 GET /runs/detail?runId=

→ `Run`；`404`。

### 7.3 POST /runs/abort

```json
{ "runId": "必填" }
```

→ 中止后的 `Run`；同时结算该 run 全部挂起（status → `aborted`）。`404`；`409` 已终态（重复中止稳定 409）。

## 8. 产物 artifacts

四个 stage 目录的只读视图：`development` / `preview` / `runtime` / `evaluation`（runtime 的根在开发产物里，按候选链与最新 vN 现算）。目录就是真相，不进库。三个端点共用参数：

| query | 说明 |
|---|---|
| stage | 四值枚举，必填 |
| agentId | 必填 |
| path | 相对 stage 根，缺省根；`..`、绝对路径、逃出根的 symlink → `400` |

`502` 工作区不可解析。**产物目录不存在 → `404`**（不自动物化，物化只在运行链路触发）。

### 8.1 GET /artifacts/list

→ `{ items: ArtifactEntry[], total }`。目录项平铺、不分页；目录在前文件在后，按名称排序。

**ArtifactEntry**：`{ name, type: "dir"|"file", size, mtime }`；目录 `size` 恒 `0`，symlink 只报链接自身。

### 8.2 GET /artifacts/file

`path` 必填。→ `{ name, size, mtime, content }`；content 为 utf-8 全文（去 BOM）。超过 `ARTIFACT_MAX_FILE_BYTES`（缺省 2MB）→ `413`；二进制不校验，读坏自负。

### 8.3 GET /artifacts/download

`path` 必填。→ 原始文件流，`Content-Disposition: attachment`；**不受大小上限**。

## 9. 通用文件 files

契约另见 [`../05-openapi/5.02-file-openapi.yaml`](../05-openapi/5.02-file-openapi.yaml)。存储名即对外 id：`fil_<uuid>(.扩展名)`，扩展名消毒后 ≤10 位字母数字。

### 9.1 POST /files —— 上传

multipart/form-data，字段名 **`file`**，单文件上限 10MB（`FILES_MAX_FILE_BYTES`）。

→ `{ "name": "fil_xxx.png", "url": "/api/smart-factory/v1/files/fil_xxx.png", "size": 12345 }`。`400` 缺 file / 报文不对；`413` 超限。

### 9.2 GET /files/:fileId —— 读取

→ 原始字节流；Content-Type 按扩展名映射，表外一律 `application/octet-stream`；恒带 `X-Content-Type-Options: nosniff`。`400` 存储名形态非法；`404` 不存在。文件不进数据库，删库不影响已传文件。

## 10. 模型 models（框架只读代理）

模型由框架（Cosight）维护，本服务**只代理 `GET /models` 列表**：不新增、不修改、不删除，也不代理会返回明文密钥的 `/active` 与 `/{id}`。

### GET /models/list

→ `{ items: ModelSummary[], activeId: string | null }`（`activeId` = 当前生效模型，没有则 null）。

**ModelSummary**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 会话级 `modelId` 的取值来源 |
| provider / protocol | string | `protocol ∈ anthropic / openai`，决定用哪套 SDK |
| label | string | 界面展示名 |
| modelName | string | 发给供应商的 model 字段 |
| baseUrl | string\|null | null = 供应商官方地址 |
| hasApiKey / isActive | boolean | 不含任何密钥或掩码字段 |
| createdAt / updatedAt | string | |

失败一律 `502 FRAMEWORK_UNAVAILABLE`，`message` 为可操作中文（查框架是否启动、查 `{cosightHome}/.module-token` 等），前端可直接展示。

## 11. WebSocket 实时通道

入口：`ws://localhost:3000/api/smart-factory/v1/ws`（与 REST 同端口同前缀）。

### 11.1 信封

所有帧共用：`{ id, type: "request"|"response"|"event", method, timestamp, payload?, error?: { code, message } | null }`。上行必须是 `type: "request"`；解析失败回 `type=response`、id=`"unknown"`、code=`BAD_REQUEST` 的错误帧。

**响应帧**：`type=response`，`id` 回显请求 id；成功带 `payload`、`error: null`；失败 `error: { code, message }`（code 同 REST 错误码）。

### 11.2 上行方法（客户端 → 服务端）

| method | payload | 响应 payload |
|---|---|---|
| `subscribe` | `{ sessionId }` | `{ subscribed: true, sessionId, status }`；**响应之后**补发该会话当前全部挂起消息（`message` 事件）；会话不存在 → 404 错误帧 |
| `unsubscribe` | `{ sessionId }` | `{ unsubscribed: true }` |
| `send` | `{ sessionId, prompt }` | `{ message, run }`，同 REST `/messages/send`；**隐式订阅**该会话，不必先 subscribe |
| `run.abort` | `{ runId }` | `{ run }`，同 REST `/runs/abort` |
| `message.respond` | `{ messageId, decision?, answers? }` | `{ message }`，同 REST `/messages/respond` |
| `ping` | — | `{ pong: true }` |

未知 method → `BAD_REQUEST` 错误帧。

### 11.3 下行事件（服务端 → 客户端）

| method | payload | 说明 |
|---|---|---|
| `connection.ready` | `{ connectionId }` | 连接建立后立即推一条 |
| `session.status` | `{ sessionId, status }` | 会话状态变化 |
| `run.started` | `Run`（含 waiting） | 运行开始 |
| `run.status` | `Run`（含 waiting） | 运行状态变化，终态也走这条 |
| `message` | `Message` | 消息新建或更新，**upsert 语义**，按 id 覆盖渲染 |
| `chat.delta` | `{ sessionId, runId, messageType, delta }` | 流式增量，**瞬态不落库不回放** |
| `error` | `{ code, message }` | 连接级错误；`SLOW_CONSUMER` 时服务端随后断开 |

事件 `id` 形如 `evt_<ts>_<n>`。

### 11.4 通道行为

- **无回放**：服务端不缓冲历史事件。断线重连 / 刷新页面：REST 拉历史消息（§6.1）+ 重新 `subscribe` 补挂起；重复订阅重复补发是允许的，前端按消息 id upsert。
- **心跳**：服务端不发 ping。客户端按 `WS_HEARTBEAT_MS`（缺省 30000ms）间隔发 `ping` 帧；超过 **2 倍间隔**没有任何上行帧，服务端 `close(1000, "心跳超时")`。
- **背压**：单连接发送缓冲超过 `WS_MAX_BUFFERED_BYTES`（缺省 4MB）→ 推一条 `error`（code `SLOW_CONSUMER`）后断开。
- **挂起等待**：审批 / 交互的应答不设超时，出口只有应答、中止、服务重启；服务退出时会把全部挂起结算为 `aborted`。

## 13. 刻意不存在的接口

- **实例（instance）无资源路径**：由 `(agentId, stage)` get-or-create，只在 session 响应内联。
- **模型无写接口**：不代理框架的 `/active`、`/{id}`（明文密钥），本服务也不提供增删改。
- **工作区无写接口**：创建、绑目录、切换都在框架界面完成。
- **WS 上无历史消息**：历史一律走 REST；WS 不回放。
- 删除接口不做幂等「已达成即成功」：目标不存在一律 `404`。
