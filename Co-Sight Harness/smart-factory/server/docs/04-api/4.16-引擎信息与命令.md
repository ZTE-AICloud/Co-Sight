# 引擎信息与命令（`/` 菜单）

> 状态：**已实现**（2026-10-30）。两个只读端点：`/` 菜单里的全部技能与命令、当前 Claude Code 的自身信息。
> 代码落点：`server/src/modules/engine/*`（service / controller / routes）、
> `server/src/shared/engine/claude-adapter.ts`（`commands` / `info` 与只读探测）、
> `server/src/shared/engine/port.ts`（`EngineSlashCommand` / `EngineInfo`）。
> 验收测试：`server/tests/engine-api.test.ts`。
> 相关篇：[4.12 技能（技能库扫描）](./4.12-技能.md)、[4.14 可执行技能与命令（智能体详情）](./4.14-可执行技能与命令.md)、
> [4.04 消息（发送）](./4.04-消息.md)。

## 1. 端点

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/engine/commands/list` | `?cwd=` 可选 | `200` `{ engine, cwd, items: EngineSlashCommand[] }` |
| GET | `/engine/detail` | `?cwd=` 可选 | `200` `EngineInfo` |

两个端点都**只读**：不发起模型调用、不落会话、不写数据库。

`/engine/commands/list` **不下发 Claude Code 自带命令**（SDK 标 `builtin` 的项）：
model、mcp、clear、compact、config、usage 这类终端 / 会话管理命令，以及 code-review、
security-review、dataviz 这类官方内置技能，在产品前端的语义与执行方式都不对。只返回
**用户 / 项目 / 插件**提供的技能与命令（本机当前 72 条里剩 24 条）。过滤在 service 层做，
适配器仍返回引擎全量；将来要放开某一类时改这一处即可。

## 2. 数据从哪来：引擎的 initialize 回执，不是扫盘

`/` 菜单由引擎自己拼：内置命令、user / project 技能、插件技能与命令、动态工作流命令混在一张表里。
扫 `.claude/skills` 只能看到其中一部分，也还原不出别名（`aliases`）、参数提示（`argumentHint`）
与内置标记（`builtin`）。所以服务端经适配器起一个**只读探测进程**，取引擎的 initialize 回执：

- `prompt` 永不产出 → 不产生回合；
- `persistSession: false` → 不写会话文件；
- `disableAllHooks: true` → 不跑本机 `SessionStart` hooks（否则每打开一次菜单都会执行用户钩子）；
- `strictMcpConfig: true` → 与真实运行时会话一致，MCP 服务器不参与，清单里不会多出本机 MCP 的 prompt 命令；
- 回执到手立即关进程；超过 15 秒未回执按失败处理。

结论：**数据源就是终端里敲 `/` 看到的自动补全**；端点再按产品口径过滤掉引擎自带命令（见 §1），
并按服务端当前引擎（`ENGINE`）取数。

同一 `cwd` 的探测结果缓存 30 秒，并发请求共用一次进程启动（一次约 1–2 秒、200MB+ 内存）。
失败不进缓存，下一次请求重新探测。

## 3. `cwd` 决定「项目级」条目的范围

| 传参 | 生效范围 |
|---|---|
| 不给 / 空串 | 主目录（`~/.claude` 的技能、命令、插件）= 本机用户级配置 |
| 绝对路径（可带 `~/`） | 该目录 + user 级配置；目录自己的 `.claude/skills`、`.claude/commands` 一并出现 |

校验与 `/fs/*` 同源（`shared/workspace/local-path.ts`）：形态非法 / 不是目录 `400`，不存在 `404`。
响应里的 `cwd` 是解析后的真实绝对路径（已解 symlink）。

前端应按**会话的工作目录**传 `cwd`：预览 / 运行时是智能体产物目录，构建期是工作台目录，
不知道就不传（拿本机用户级清单）。

## 4. `EngineSlashCommand`

```json
{
  "name": "skill-optimizer:skill_optimize",
  "description": "Skill 内容优化(LLM 多维评分闭环) + 结构重构…",
  "argumentHint": "--mode {optimize|refactor} (--skill-path PATH | --agent-path DIR)",
  "aliases": ["skill_optimize"]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 不带前导 `/` 的命令名；插件技能 / 命令形如 `plugin:skill` |
| `description` | string | 引擎给的说明，可能带 `(user)` / `(project)` 之类的来源后缀；缺失为空串 |
| `argumentHint` | string | 参数提示；没有为空串 |
| `aliases` | string[]? | 能解析到同一条命令的别名；没有则**省略**该字段 |

`EngineSlashCommand` 在适配器层还有可选的 `builtin` 标记；端点把 `builtin: true` 的项整条过滤掉，
所以**响应里不会出现该字段**。

技能不以独立字段出现：引擎就是按「一条 `/` 命令」注册的，`name` 即技能名或 `plugin:skill`。
需要按智能体产物筛技能、看 SKILL.md 元数据（版本、路径）时用 [4.14](./4.14-可执行技能与命令.md) / [4.13](./4.13-智能体技能.md)，不要从本端点反推。

## 5. `EngineInfo`

```json
{
  "engine": "claude-cli",
  "cwd": "/home/me/.claude/work",
  "version": "2.1.311",
  "commandCount": 24,
  "available": true
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `engine` | string | 适配器标识（`claude-cli` / `fake`），即 `ENGINE` |
| `cwd` | string | 探测目录（真实绝对路径），语义见 §3 |
| `version` | string | Claude Code 版本；老版本不报时为空串 |
| `commandCount` | number | `/` 菜单里**可见**的条目数（已排除引擎自带命令，与列表端点同口径；整表走 `/engine/commands/list`，不重复下发） |
| `available` | boolean? | CLI 是否可用；缺省视为可用 |
| `reason` | string? | 不可用原因（CLI 未安装、探测失败等） |
| `installHint` | string? | 安装 / 升级指引 |

CLI 未安装时本端点仍返回 **200**：`available:false`，`version` 为空串，`commandCount` 为 `0`，
并带 `reason` / `installHint`。设置面板据此显示安装指引，而不是把整块配置打成错误态。

**刻意不返回模型、账号与输出风格。** 产品起 run 用的模型与凭据来自 Cosight Harness 配置
（`/models/list` 与 `modelId`），Claude Code 本机 settings 里的 model / account 与真实运行无关，
放进来只会误导；输出风格同理，产品没有这一层展示。

## 6. 错误

| 状态 | 场景 | `message` 示例 |
|---|---|---|
| 400 | `cwd` 不是绝对路径 / 不是目录 | `path 必须是绝对路径："relative/path"` |
| 404 | `cwd` 不存在 | `路径 /missing 不存在` |
| 502 | 探测进程起不来、超时（15s）或回执异常 | `读取 Claude Code 失败：Claude Code 在 15000ms 内没有返回初始化结果` |
| 502 | CLI 未安装（仅 `/engine/commands/list`；`/engine/detail` 走 200 + `available:false`） | `读取 Claude Code 失败：未找到 Claude Code CLI（claude）。请安装：npm install -g @anthropic-ai/claude-code` |
| 502 | 适配器未实现该项能力（`commands` / `info` 可选） | `当前引擎 <engine> 不提供命令清单` |

错误体形状见 [4.02 通用规范](./4.02-通用规范.md) §10；`messageKey` 用 `error.bad_gateway.default`（探测失败）
或路径校验的既有键，前端未翻译时回落到中文 `message`。

## 7. 与其它清单的边界

| 端点 | 看什么 | 用途 |
|---|---|---|
| `GET /engine/commands/list` | 引擎 `/` 菜单里产品可见的部分（用户 / 项目 / 插件；不含引擎自带命令） | 发送框的 `/` 自动补全 |
| `GET /agents/{agentId}` 的 `skills` / `commands` | 只扫该智能体产物目录 + 运行时插件 | 智能体详情里的「可执行清单」 |
| `GET /skills` | 技能库 / 智能体产出的技能目录 | 技能装配与管理 |
| `GET /models/list` | 框架配置的可用模型（含密钥状态） | 选 `modelId` |

本端点**不**代替后三者：它回答「在这台机器、这个目录下，引擎认哪些 `/` 命令」。
