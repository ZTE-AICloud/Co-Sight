> 状态：**已定稿**。会话是「一段对话」，是消息与运行的父级，本篇给出 6 个会话端点的请求与响应全貌。

## 1. 端点总表

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/smart-factory/v1/sessions/list` | `?agentId=&subjectType=&subjectId=&instanceId=&cwd=&stage=&type=&status=&name=&id=&resumeSessionId=&createdFrom=&createdTo=&page=&pageSize=` | `200` `{ items: Session[], total: number, page: number, pageSize: number }` |
| POST | `/api/smart-factory/v1/sessions/create` | `{ agentId 或 cwd（二选一）, modelId, stage?, name?, resetSandbox? }` | `200` `Session` |
| GET | `/api/smart-factory/v1/sessions/detail` | `?sessionId=` | `200` `Session` |
| POST | `/api/smart-factory/v1/sessions/:sessionId/update` | `{ modelId }`（非空） | `200` `Session` |
| POST | `/api/smart-factory/v1/sessions/delete` | `{ sessionId }` | `200` `{}` |
| POST | `/api/smart-factory/v1/sessions/abort` | `{ sessionId }` | `200` `Run` |

请求与响应一律 `application/json; charset=utf-8`。
本文 curl 以 `http://localhost:4100` 为基址，端口取自 `PORT`（缺省 4100）。
id 的传法遵循[通用规范](./4.02-通用规范.md)：集合级端点路径不放 id - 查询类 id 进 query 参数，写操作 id 进请求体；个体形态（`sessions/:sessionId/update`，与 agents 的 `/agents/{agentId}/update` 同款）允许 id 进路径。id 必填而缺失返回 `400`。
id 是不透明字符串（形态 `<前缀>_<uuid>`），前端不得解析其内容。

## 2. Session 与 Instance 的关系

- **Instance 是「哪个智能体（或哪个目录）、哪个阶段、用哪个引擎」的身份**，有两种形态：智能体实例由 `(agentId, stage)` 唯一确定；目录实例只有 `cwd`、没有 `agentId`（技能工坊等场景，见 §11）。
- 会话存 `instanceId`，**不抄写**实例的任何配置。
  要判断「这次运行用哪个智能体、哪个阶段、哪个引擎」，一律从 `session.instance` 取；运行目录由服务端按工作区与阶段解析，DTO 不下发（目录布局见 [`../03-architecture/07-artifact.md`](../03-architecture/07-artifact.md) §2），前端不要自己拼路径或另存一份配置。
- **get-or-create**：`sessions/create` 按 `(agentId, stage)` 找不到实例就建一个，并发插入由唯一约束兜底后重查返回已有行。
  没有 `/instances/*` 端点，实例只在 session 响应里内联返回。
- **共用实例**：智能体创建向导与普通开发**共用同一个 development 实例与目录**。
  要按智能体列会话，走 `sessions/list?agentId=&stage=`；**不带 `stage` 时只列 `runtime` 会话**（§5 过滤语义）。
- **stage 取值**：`development` / `preview` / `runtime` / `evaluation` 四值，`sessions/create` 缺省 `development`。目录实例（cwd 形态，§11）用的是**同一套取值**（工坊在做开发，就是 `development`）；「目录实例 vs 智能体实例」看 `instance.agentId` 是否为空，不看 stage。
  **内置智能体（`source: 'builtin'`）只认 `runtime`**：其它取值（含缺省）一律 `409`（见 [`08-agent.md`](../03-architecture/08-agent.md) §8）。
- **目录**：先由 `agents` 表取 `workspaceId`，再经框架模块面 `GET /api/framework/v1/workspaces/{id}` 取 `directory`，得到
  `agentRoot = <workspace.directory>/.smart-factory/agents/{agentId}/`。四个 stage 的 cwd 是：

  | stage | cwd |
  |---|---|
  | `development` | `agentRoot/development/` |
  | `preview` | `agentRoot/preview/` |
  | `runtime` | `agentRoot/development/output/agents/{agentName}/{latest vN}/`，原地使用 |
  | `evaluation` | `agentRoot/evaluation/agent/`（沙箱根下的被测副本；`e2e-test-*` 报告与它同级） |

- **路径解析失败**：`workspace.directory` 为 `null`、工作区不存在或框架不可达时明确报错，不猜路径。解析发生在 `send` 内、建 run 之前；失败时 `send` 直接返回错误，**不建 run、不落用户消息、不改会话状态**（见 [`4.06 实时通道`](./4.06-实时通道.md) §4.3）。
- **预览 / 评估物化**：`sessions/create` 不做物化，也不碰磁盘；**每次 `send` 建 run 前 ensure** 一次：以 development cwd 为基准，先要求产物完成（`.agent-genesis/work/{agentName}/orchestrator-state.yaml` 流程收尾，且 `gate-results/*.json` 的 verdict 为 `PASS` / `CONCERNS`；full 认 `pipeline_status=COMPLETED`，fast 认收尾步 `step-f1-fast-build` / `step-f2-fast-optimize`），再在 `output/agents` 下取唯一子目录作为 `agentName`，版本取最新 `v*`；源最新 mtime 未变则跳过（沙箱内的改动保留），变了则清空目标后整体拷贝；生产状态缺失或未完成、交付门禁未过、源缺失、候选歧义或没有版本目录时本次 `send` 返回错误，不建 run；development 有活跃 run 时同样拒绝（`409`）。mtime 标记放在 `agentRoot/.state/`。同一 `(agentId, stage)` 只有一个沙箱；细节见 [`03-session-run.md`](../03-architecture/03-session-run.md) §1.4，可读状态见 [`4.10-智能体产物状态.md`](./4.10-智能体产物状态.md)。
- **活跃顶层 run 名额**：`sessions/create` 在非 `runtime` 阶段面对同 `(agentId, stage)` 已有活跃顶层 run 时返回 `409`；`runtime` 不因实例已有活跃 run 拒绝，不同会话可并发。
  子 run 不占名额；完整不变量与跨阶段守卫见 [`02-data-model.md`](../03-architecture/02-data-model.md) §6 与 [`03-session-run.md`](../03-architecture/03-session-run.md) §1.4。

### 2.1 send 首帧：按 agentId 新建 runtime 会话 / 自由对话新建目录会话

WS `send` 有三种形态，`sessionId` 与 `agentId` **至多给一个**（REST `messages/send` 同样接受，见 [`4.04 消息`](./4.04-消息.md) §5）：

- `send { sessionId, prompt }`：续聊已有会话，使用该会话的 `modelId` / `approvalMode` / `effort`。
  请求里出现 `modelId` / `mode` / `effort` 任一字段直接 `400`（WS `VALIDATION`）。
- `send { agentId, modelId, mode?, effort?, prompt }`：**每次都会新建一条 `runtime` 会话**，不复用任何已有会话。
- `send { modelId, mode?, effort?, prompt }`（两者都不给）：**自由对话**，每次新建一条目录会话（`agentId=null`、`stage='runtime'`）。它和智能体的 runtime 会话一起出现在默认的「历史运行会话」里，靠 `instance.agentId` 是否为空区分。
  cwd 取框架当前生效工作区的目录；没有生效工作区时落到 `{COSIGHT_HOME}/smart-factory/chat`（按需创建）。
  除 cwd 解析外，起跑与后续链路与智能体会话完全相同；目录实例是实例级仲裁，同一 cwd 同时只能有一个活跃顶层 run。

`agentId` 首帧的固定行为：

1. 校验 `agentId` 形态并查 `agents` 表；不存在返回 `404`（WS `NOT_FOUND`），不建实例、会话或 run。
2. 校验 `modelId` 必填、非空且可运行（缺失、空串、非字符串或不可用 `400`，框架不可达 `502`），再按 `(agentId, runtime)` get-or-create 实例。
3. 新建会话：`mode` 缺省 `workspace_write`，`effort` 缺省 `high`，取值非法 `400`。
   三个字段都落在新会话上，`status='not_started'`、`resumeSessionId=null`。
4. 起跑条件解析与活跃 run 仲裁：模型解析失败返回 `400` / `502`（见 §3.1）；新会话没有活跃 run，runtime 也不看实例级名额，因此并发首帧都能通过仲裁。
   产物门禁失败按 [`4.04 消息`](./4.04-消息.md) §5 返回 `404` / `409`；任何失败都会**删除刚建的会话**，不留空会话。
5. 成功后首轮 run 使用新会话的 `modelId` / `approvalMode` / `effort`。
6. 响应顶层带 `sessionId` / `runId` / `instanceId` / `status`（恒 `'running'`）/ `effort` / `modelId` / `modelName` / `modelFellBack`（恒 `false`），另带 `message` / `run`，客户端不必再查会话列表；响应**没有** `created` 字段。

因此一个 runtime 实例可以有多条会话：每次 `send { agentId }` 都是新对话，要续聊同一条对话必须带上一次响应返回的 `sessionId`。
会话的 `approvedAll` 是会话级状态：新 run 继承它；把它关掉的唯一方式是经 `mode.switch` 切到非 `full_access` 的审批模式（见 §9.1）。

## 3. 字段表

### 3.1 Session

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 会话 id，形态 `sess_<uuid>` |
| `instanceId` | string | 所属实例 id，创建后不可变 |
| `name` | string | 会话名，缺省空串；本期没有改名端点。创建时给过就保持原样；仍为空时，run 收口后由引擎会话标题（Claude Code 的自动摘要 / 自定义名）补上，补名成功广播 `session.named`，超过 60 字截断 |
| `status` | `'not_started'` \| `'in_progress'` \| `'completed'` | 会话是否还活着 |
| `modelId` | string | 会话级框架模型 uuid（非模型名），**任何会话都非空**，没有自动解析或回退。建会话时必填（§5）；建后只能经 `sessions/:sessionId/update` 或 WS `model.switch` 改成另一个非空 uuid，不支持清空。起 run 前服务端按它调框架详情 `GET /api/framework/v1/models/{id}` 取 `modelName` / `baseUrl` / `apiKey`：详情 404/422、`protocol` 非 `anthropic`、`apiKey` 或 `modelName` 为空都按 `400` 返回；框架网络异常 / 5xx 按 `502` 返回。候选清单来自 `GET /models/list`；创建会话、更新会话与 `model.switch` 会校验该 id 在列表中且可运行（不存在 / 协议不符 / 无密钥 `400`，框架不可达 `502`） |
| `resumeSessionId` | string \| null | 引擎接续标识，缺省 `null` = 开新引擎会话。首次 run 由引擎产出后服务端自动落库，下一次 run 原样下发给引擎做多轮 resume；provider 相关，只对最后写入的 provider 有效。客户端只读，不可设置 |
| `approvalMode` | `'read_only'` \| `'workspace_write'` \| `'full_access'` | 会话级审批模式，缺省 `workspace_write`；映射到引擎权限模式，下个 run 生效（§9.1）。DTO 字段名是 `approvalMode`，数据库列名仍是 `mode`；线路上的 `mode.switch` 与 `settings.changed.settings.mode` 保留 `mode` 这个名字 |
| `approvedAll` | boolean | 会话级「允许所有」开关，缺省 `false`。用户选 `approved_all` 时置真，同时 `approvalMode` 置 `full_access`；新 run 继承。把 `approvalMode` 切到任何非 `full_access` 的值会复位为 `false`（§9.1） |
| `effort` | `'low'` \| `'medium'` \| `'high'` \| `'xhigh'` \| `'max'` | 会话级推理强度，缺省 `high`；下个 run 生效（§9.1） |
| `messageCount` | number | **派生字段**：该会话全部消息的条数，所有 `type` 都计入；每次响应现算，没有消息时为 `0`。所有 Session 响应都带它 |
| `lastMessage` | string \| null | **派生字段**：最新一条 `type='text'` 消息的 `content.text`；该字段不是字符串或没有文本消息时为 `null`。按 `seq` 降序取最新一条。列表填充本字段；`create` / `detail` / `update` 恒为 `null` |
| `firstUserMessage` | string \| null | **派生字段**：第一条 `role='user'` 且 `type='text'` 消息的 `content.text`；该字段不是字符串或没有符合条件的消息时为 `null`。按 `seq` 升序取最早一条。列表填充本字段；`create` / `detail` / `update` 恒为 `null` |
| `instance` | Instance | 内联实例对象，前端取 agentId / stage / engine 的唯一来源；不含目录 |
| `createdAt` | string | ISO 8601，如 `2026-10-15T02:13:07.415Z` |
| `updatedAt` | string | ISO 8601，状态变更会刷新它 |

`status` 的迁移只有三条：

```text
not_started --(起 run)--> in_progress --(无活跃 run)--> completed
                          <--(再次发消息复活)----------
```

没有 `failed` / `aborted` 会话状态，一次 run 的成败记在 run 上。

## 4. 获取会话列表

```text
GET /api/smart-factory/v1/sessions/list
```

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agentId` | string | 否 | 按智能体目录名精确过滤；会做形态校验，非法即 `400` |
| `subjectType` | string | 否 | 主体类型，只接受 `agent`；其它取值 `400`。本服务没有 skill 主体 |
| `subjectId` | string | 否 | `agentId` 的别名（agent-runtime 口径）；与 `agentId` 同时给时以本参数为准，两者取值不同则 `400`；形态按 `agentId` 校验 |
| `instanceId` | string | 否 | 按实例 id 精确过滤；与 `agentId` / `stage`（含 `type`）取交集，交集为空时返回空页 |
| `cwd` | string | 否 | 按目录实例的 cwd **精确**过滤（§11）；与 `agentId` / `stage` 取交集；必须是绝对路径，否则 `400`。symlink 目录以创建时落库的真实路径为准 |
| `stage` | string | 否 | `development` / `preview` / `runtime` / `evaluation`；不在枚举内即 `400`。**缺省 `runtime`**，取消默认的规则见下方「默认阶段」 |
| `type` | string | 否 | `stage` 的逗号分隔别名：`development` / `preview` / `runtime` / `evaluation`，或 `all`。`all` 取消阶段过滤（与其他值同时出现时 `all` 吸收其余值）；非法取值 `400`。与 `stage` 同时给时，`type` 必须包含该 `stage` 或为 `all`，否则 `400` |
| `status` | string | 否 | 逗号分隔的会话状态：`not_started` / `in_progress` / `completed`，按 IN 匹配；任一取值非法即 `400`；空串视为未传 |
| `name` | string | 否 | 按会话名子串过滤（`contains`，ASCII 大小写不敏感）；空串视为未传 |
| `id` | string | 否 | 逗号分隔的会话 id，按 IN 精确匹配；空串视为未传 |
| `resumeSessionId` | string | 否 | 按引擎 resume 标识精确过滤；支持逗号分隔多值（按 IN 匹配），用于反查 `sessionId` |
| `createdFrom` | string | 否 | ISO 8601 日期时间，过滤 `createdAt >= createdFrom`；非法值 `400`，`message` 回显字段名 |
| `createdTo` | string | 否 | ISO 8601 日期时间，过滤 `createdAt <= createdTo`；非法值 `400`，`message` 回显字段名 |
| `page` | number | 否 | 页码，从 1 起，缺省 1 |
| `pageSize` | number | 否 | 每页条数，缺省 20，上限 200（超出按 200 截断） |

过滤语义：

- **默认阶段是 `runtime`**：既没给 `stage` / `type`，也没给任何**精确定位参数**时，只返回运行（runtime）会话 —— 界面的「历史运行会话」就是不带阶段参数的这一次请求。
  精确定位参数是 `instanceId` / `cwd` / `id` / `resumeSessionId`：给了其中任一个就**不套默认阶段**，否则 development / preview / evaluation 会话与工坊（目录实例）会话会被悄悄筛掉。
  `agentId`（与 `subjectId`）只是过滤、不是定位，**不取消默认**：`?agentId=X` 返回该智能体的 runtime 会话；要看开发 / 预览 / 评估会话必须显式给 `stage`（如 `?agentId=X&stage=development`），或者按实例查（`?instanceId=`）。目录实例按 `?cwd=` 查：自由对话本身就是 `runtime`（默认列表已包含），工坊是 `development`（`?cwd=&stage=development`）；`instance.agentId` 为 `null` 即目录实例。
- 所有过滤条件按 AND 组合；空串参数一律视为未传。
- `subjectType`、`subjectId` 为 agent-runtime 对齐参数：`subjectId` 等价于 `agentId`；`subjectType=agent` 只命中智能体实例（排除自由对话等目录实例）。
- `subjectId` 覆盖 `agentId`：两者都出现且取值相同时正常过滤，取值不同时 `400 BAD_REQUEST`，不做二选一猜测。
- `instanceId` 与 `agentId` / `stage` 取交集；交集为空时返回 `200` 空页（`items: []`、`total: 0`），不是 `404`。
- `cwd` 只命中目录实例（智能体实例的 `cwd` 为 `null`，天然不会命中）；与 `agentId` / `stage` 取交集，交集为空时同样是 `200` 空页。
- `type` 与 `stage` 都是阶段过滤：只给 `stage` 时按单值过滤；只给 `type` 时按逗号分隔的集合过滤；两者同时给时 `type` 必须覆盖 `stage` 或为 `all`。过滤按 `type` 的集合执行，`all` 取消阶段过滤（同时给出 `stage` 也不再生效）。
- `agentId` / `stage` 的过滤经实例关联完成；`resumeSessionId` 可单独使用，不要求同时给 `agentId` / `stage`。
- `resumeSessionId` 不要求全局唯一；同一标识命中多条时全部返回，按 `updatedAt` 降序。
- 排序固定为 `updatedAt` 降序，**最近有活动的会话在最前**（改名、状态变更、补 `resumeSessionId` 都会刷新 `updatedAt`）；同毫秒按 `id` 升序兜底。
- 响应 `total` 是**过滤后的总条数**，与 `items.length` 无关。
- 响应回显校验后的 `page` / `pageSize`（含缺省与截断后的值），前端不必自己保存请求值。

## 5. 新建会话

```text
POST /api/smart-factory/v1/sessions/create
```

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agentId` | string | 与 `cwd` 二选一 | 智能体形态必填：智能体 id（同时是 `agentRoot` 下的目录名），正则 `^[a-z0-9][a-z0-9._-]{0,63}$`（小写字母或数字开头、总长 1-64 的单段目录名），且见下方附加规则。与 `cwd` 恰好给一个，同时给或都不给 `400` |
| `cwd` | string | 与 `agentId` 二选一 | 目录形态必填（§11）：绝对路径、必须存在且是目录，服务端 `realpath` 后落库 |
| `stage` | string | 否 | `development` / `preview` / `runtime` / `evaluation`，缺省 `development` |
| `name` | string | 否 | 会话名，缺省空串 |
| `modelId` | string | 是 | 会话级框架模型 uuid，必填、非空且可运行；空串、非字符串或缺失均 `400`，不在模型列表、协议不符或无密钥也 `400`，框架不可达 `502`。没有工作区默认 / 框架生效 / 本机配置回退，候选清单来自 `GET /models/list`。Web 端会在 `preview` / `evaluation` 首次建会话前自行解析默认模型（工作区默认 → 框架生效 → 列表第一项），解析后仍显式传进来；服务端不感知这条链 |
| `resetSandbox` | boolean | 否 | 建会话前清空该阶段沙箱（「重新开始预览」/「重新评估」用）：删掉 `<agentRoot>/<stage>/` 整个目录与物化标记，下一次 run 前按最新产物整体重拷。评估的旧报告（`e2e-test-*` / `eval_results/`）在沙箱根下，会一并删掉。只支持 `preview` / `evaluation`，其它阶段 `400`；非布尔值 `400` |

`agentId` 附加规则（跨平台安全，均返回 `400`）：

- **只允许小写**：`a-z0-9` 起头，其后为 `a-z0-9`、`.`、`_`、`-`；大写字母一律拒绝（如 `Bad`）。
- **拒绝 Windows 保留名**：`con` / `prn` / `aux` / `nul` / `com1`-`com9` / `lpt1`-`lpt9`（小写形态），以及带扩展名的变体（如 `con.txt`、`com1.log`）；`console`、`com10` 这类仅是前缀命中的名字不受影响。
- **拒绝以点结尾**：如 `abc.`（Windows 上会静默丢掉结尾点）。

语义要点：

- **先查 `agents` 表、再建实例**：`agents` 表是智能体存在的唯一权威，未知 `agentId` 一律 `404`（`智能体 <agentId> 不存在`）且不留下实例行。目录形态（`cwd`）不查 `agents` 表，见 §11。
- **创建不碰磁盘**：`sessions/create` 不预先校验工作区目录或产物目录是否存在，也不做预览 / 评估物化。这些在首次 `send` 内、建 run 前解析；失败时 `send` 返回错误，不建 run、不落用户消息、不改会话状态（见 §2 与 [`4.06 实时通道`](./4.06-实时通道.md) §4.3）。创建时唯一的一次框架调用是模型可运行性校验。**唯一例外是 `resetSandbox = true`**：它按调用方要求删掉该阶段沙箱（含评估旧报告），这是「重建沙箱」这个动作本身，不是物化。
- **`resetSandbox` 的时机**：排在活跃 run 检查之后、落会话行之前。同阶段已有活跃 run 时与建会话一样 `409`，且**不删沙箱**（正在跑的那份不能动）—— 调用方按「退回最近一场」处理即可。
- 新会话的 `status` 恒为 `not_started`，`resumeSessionId` 恒为 `null`；`modelId` 落请求传入的非空值，建后可经 `sessions/:sessionId/update` 切换成另一个非空模型（见 §9）。
  `modelId` 必须可运行：服务端查框架模型列表，模型不存在、`protocol` 非 `anthropic` 或没有配置 API 密钥都返回 `400`；框架不可达返回 `502`，且不留下会话行。首次 `send` 再按模型详情解析 `modelName` / `baseUrl` / `apiKey`，详情 404/422 或字段缺失返回 `400`，框架不可达返回 `502`。
- `approvalMode` 缺省 `workspace_write`、`approvedAll` 缺省 `false`、`effort` 缺省 `high`；`create` 不接受这三个字段，审批模式建后经 WS `mode.switch` 切换（见 §9.1）。
- `messageCount` 恒为 `0`（新会话还没有消息），`lastMessage` / `firstUserMessage` 恒为 `null`。
- 校验与副作用顺序：入参校验（`agentId` 形态 → `stage` → `modelId` 必填非空 → `resetSandbox` 形态与阶段）→ **查 `agents` 表（未知即 404）** → 模型可运行性校验（不可用 `400`、框架不可达 `502`）→ 实例 get-or-create → 活跃 run 检查（仅非 `runtime` 阶段）→ `resetSandbox` 清空沙箱 → 落会话行。
  因此 `400` / `404` / `409` / `502` 都不会留下会话行（`409` 时实例行可能已被 get-or-create 建出，`404` 时连实例行都没有）。目录形态（`cwd`）另有互斥判定与校验顺序，见 §11.1。
- `409` 的判定：非 `runtime` 阶段落在**实例**上，该实例已有活跃 run 就拒绝，与是哪个会话在跑无关；`runtime` 阶段不因实例已有活跃 run 拒绝，新建的会话还没有活跃 run。

### 9.1 WS 切换方法（model.switch / mode.switch / effort.switch）

WS 提供三个会话字段切换方法，语义统一：

- **下个 run 生效**：只改库里的会话字段；正在跑的 run 在起跑时已读定 `modelId` / `approvalMode` / `effort`，**不受影响，也不会被中断**。
- **不返回 `CONFLICT`**：活跃 run 存续时也允许切换。这与 REST `sessions/:sessionId/update` 的 409 不同，REST 更新保持原语义；需要「不停当前 run、只改下轮」时用 WS 切换。
- 切换后服务端返回完整 `Session`（`messageCount` 为真实条数，`lastMessage` / `firstUserMessage` 恒为 `null`）；WS 响应的 `payload` 仍按 [4.06](./4.06-实时通道.md) 的窄形状（如 `{ sessionId, mode }`）。
- `mode.switch` 的线路字段名仍是 `mode`，它改的是 Session 的 `approvalMode`。
  **把 `approvalMode` 切到任何非 `full_access` 的值会把 `approvedAll` 复位为 `false`**；切到 `full_access` 不会自动把 `approvedAll` 置真（只有用户的 `approved_all` 决策会）。
- 入参校验：

| 方法 | 字段 | 取值 |
|---|---|---|
| `model.switch` | `modelId` | 非空字符串（框架模型 uuid），空串或非字符串 `400`；切换时校验模型可运行，不存在、协议不是 `anthropic` 或没有配置 API 密钥返回 `400`，框架不可达 / 5xx 返回 `502`，失败不改动会话。不支持清空模型 |
| `mode.switch` | `mode` | `read_only` / `workspace_write` / `full_access` |
| `effort.switch` | `effort` | `low` / `medium` / `high` / `xhigh` / `max` |

- 错误：缺字段或取值非法 `400 BAD_REQUEST`；会话不存在 `404 NOT_FOUND`。

## 10. 错误码汇总

| HTTP | `error` | 出现在 |
|---|---|---|
| 400 | `BAD_REQUEST` | `sessions/list` 的 `agentId` / `subjectId` 形态非法、`subjectType` 不是 `agent`、`stage` / `type` / `status` 非法、`type` 与 `stage` 冲突、`createdFrom` / `createdTo` 非法、`cwd` 不是绝对路径；`sessions/create` 的 `agentId` 与 `cwd` 互斥校验（同时给或都不给）、`agentId` 缺失或形态非法、枚举非法、目录形态 `cwd` 相对路径或不是目录、`modelId` 缺失 / 空串 / 非字符串 / 不可运行；`sessions/detail` 的 `sessionId` 缺失与 `sessions/delete`、`sessions/abort` 的 id 缺失；`sessions/:sessionId/update` 的路径 id 缺失或 `modelId` 未给 / 空串 / 非字符串 / 不可运行；WS `model.switch` 的 `modelId` 空串、非字符串或不可运行 |
| 404 | `NOT_FOUND` | `sessions/create` 的 `agentId` 不在 `agents` 表里、目录形态 `cwd` 不存在；`sessions/detail` / `sessions/delete` / `sessions/:sessionId/update` / `sessions/abort` 的会话不存在；未匹配到任何路由 |
| 409 | `CONFLICT` | `sessions/create` 在非 `runtime` 阶段面对已有活跃 run 的实例（`runtime` 不因实例下已有活跃 run 拒绝；目录实例（`agentId=null`、`stage='development'`）属非 runtime，同一 cwd 至多一个活跃顶层 run，见 §11.2）；`sessions/delete` 面对有活跃 run 的会话；`sessions/:sessionId/update` 面对有活跃 run 的会话；`sessions/abort` 面对没有活跃 run 的会话 |
| 502 | `FRAMEWORK_UNAVAILABLE` | `sessions/create` / `sessions/:sessionId/update` / WS `model.switch` 的模型可运行性校验遇到框架不可达 / 5xx | 框架返回的错误说明 |

错误响应体统一为 `{ "error": "<码>", "message": "<中文兜底>", "messageKey": "<i18n 键>", "params": { ... } | null }`，由错误中间件产出；`messageKey` / `params` 的含义与降级规则见 [`4.02-通用规范.md`](./4.02-通用规范.md) §10.1。

## 11. 目录会话（cwd 形态）

技能工坊等场景要在**工作区之外的一个目录**里跑会话（skill-foundry 的产物就是那个目录下的 `output/skills/`，见 [`4.12-技能.md`](./4.12-技能.md) §2）。目录会话不给工坊造智能体：实例支持「有 `cwd`、没有 `agentId`」的形态，会话落在任意已存在的目录上。数据层对照见 [`../03-architecture/02-data-model.md`](../03-architecture/02-data-model.md) §2（`instances` 两种形态）。

- `sessions/create` 两种形态**互斥**：`agentId` 与 `cwd` 恰好给一个，同时给或都不给 `400`。
- 目录实例没有专用 stage，取值按**用途**：工坊（创建 / 优化技能）= `development`，自由对话 = `runtime`。因此目录实例的身份是 `(cwd, stage)` —— 同一个目录可以同时有一个工坊实例和一个自由对话实例。「目录 vs 智能体」看 `instance.agentId` 是否为 `null`。
- 副作用：`?stage=development` 会同时命中智能体的开发会话与工坊会话（带 `cwd` 区分）；`?stage=runtime`（默认）会同时命中智能体的 runtime 会话与自由对话（看 `agentId` 区分）。
- DTO 变化：`instance.agentId` 由 `string` 变 `string | null`，新增 `instance.cwd: string | null`（§3.2）。WS 下行事件里的 instance 走同一个 DTO，无单独形状。

### 11.1 创建：`POST /sessions/create` 的 cwd 形态

请求体（与 §5 同端点，`agentId` 形态见 §5）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cwd` | string | 与 `agentId` 二选一 | 绝对路径、必须存在且是目录；服务端 `realpath` 后落库（symlink 解掉，之后列表过滤按真实路径）。路径校验与 `/fs/*` 同口径：形态非法 `400`、合法但不存在 `404`、不是目录 `400`；不做白名单（与 `/fs/*` 同口径），支持 `~/` 展开 |
| `modelId` | string | 是 | 规则不变：必填、非空且可运行（`400` / `502`，见 §5） |
| `name` | string | 否 | 缺省空串。**同一技能的创建会话与优化会话共用一个 cwd，靠会话名区分（优化场固定 `优化 <name>`），不给每个技能单独开 cwd** |
| `agentId` | string | 互斥 | 与 `cwd` 恰好给一个，同时给或都不给 `400`（`messageKey: error.bad_request.agent_or_cwd`） |
| `stage` | — | 不读取 | 目录实例 `stage` 恒为 `development`；请求里传了也不生效 |

语义要点：

- **不查 `agents` 表、不查内置智能体、不做物化**：目录形态全程不触碰 agents 表，创建也不在 cwd 之外碰磁盘。`artifacts/*` 不适用目录实例（没有 `agentId`），目录内文件浏览走 `/fs/*`。
- **实例 get-or-create**：目录实例按 `cwd` 唯一（`uq_instances_cwd` 部分唯一索引，并发插入撞约束后重查）。同一 cwd 建第二个会话返回 `200`，两条会话共用同一 `instanceId`。
- **创建时 409 预检**：工坊的目录实例是 `development`（非 runtime），已有活跃顶层 run 时创建直接 `409`；自由对话是 `runtime`，按会话隔离，不因此拒绝（与 agentId 形态同一实例级互斥，见 §11.2）。
- 校验与副作用顺序：互斥判定 → `cwd` 路径校验（`realpath`）→ `modelId` 必填非空 → 模型可运行性校验（`400` / `502`）→ 实例 get-or-create → 活跃 run 预检 → 落会话行。与 §5 同理，`400` / `404` / `409` / `502` 都不会留下会话行。

请求实例（`cwd` 取自 `GET /skills` 响应的 `cwd` 字段，原样传入、客户端不拼路径）：

```bash
curl -s -X POST 'http://localhost:4100/api/smart-factory/v1/sessions/create' \

```

### 11.2 实例级互斥：同一 cwd 至多一个活跃顶层 run

`runs.stage` 从实例抄来，既有部分唯一索引的条件是 `stage <> 'runtime'`（[`../03-architecture/02-data-model.md`](../03-architecture/02-data-model.md) §6）。工坊的目录实例是 `development`（非 runtime），因此**免费继承「同一实例至多一个活跃顶层 run」的约束**：A 会话的 run 活跃期间，同实例（同 cwd）的 B 会话 `send` 被 `409` 拦下，服务层无需补检查。若取 `runtime` 则默认允许并行，两场会话同时改同一个技能目录会互相踩 —— 这也是自由对话（`runtime`）允许同一工作区并行、而工坊必须串行的原因。

### 11.3 列表：`GET /sessions/list?cwd=`

- `cwd` 按目录实例的 cwd **精确**过滤，与 `agentId` / `stage` 取交集；智能体实例的 `cwd` 为 `null`，天然不在命中范围。必须是绝对路径，否则 `400`。
- `sessions/list?cwd=<技能库根>` 是**该目录下所有用途**的会话（工坊 + 可能的自由对话）；工坊历史要 `?cwd=<技能库根>&stage=development`，`cwd` 是精确定位参数，会取消默认的 `runtime` 阶段。
- symlink 目录以创建时落库的真实路径（`realpath`）为准：传符号链接路径查不到，传真实路径能查到。
- 历史会话因此不需要任何新端点：换一个 `cwd` 值就是换一段历史。

### 11.4 起 run：跳过工作区解析

目录实例的 `cwd` 在创建时已定，`send` 起跑时直接使用：

- **跳过**工作区解析、阶段 cwd 推导与预览 / 评估物化 —— **框架不可达不再影响目录会话**，run 照常完成（技能库在框架之外，这正是技能线要的）；
- 适配器与模型解析不变：`modelId` 仍按 §3.1 在起 run 前解析，详情缺失 `400`、框架不可达 `502`，不建 run；
- 活跃 run 仲裁不变：session 级与实例级（非 runtime）两条部分唯一索引照常生效。
