## 1. 定位与读者

`04-api/` 下各篇是 REST/WS 公共接口形状的权威；agents 与 files 两域以 `05-openapi/` 为准（见文首）。读者有两类，读同一份契约：

- **前端实现者**：按各篇给出的路径、请求体与响应形状写代码，不需要读后端源码。
- **脚本与命令行调用方**：curl、Node 脚本、E2E 用例按同一份契约构造请求。

设计依据在 [`../03-architecture/`](../03-architecture/)：为什么这样定写到那里，接口长什么样写在这里。
两者冲突时以 `04-api/` 为准，改的是后端实现，不是让调用方迁就。

## 2. 基址与信道

- **基址** `/api/smart-factory/v1`，REST 与 WebSocket 同一端口、同一前缀。
  - REST：`http://localhost:4100/api/smart-factory/v1/...`
  - WS：`ws://localhost:4100/api/smart-factory/v1/ws`
- 端口来自 `PORT`（缺省 `4100`），监听地址来自 `HOST`（缺省 `0.0.0.0`）。
- 开发态前端经 vite 代理 `/api` 转发到后端，前端代码只写相对路径；代理配置（含 WS 的 `ws: true`）见 `web/vite.config.ts`。
- **分工**：REST 承载全部 CRUD 与查询，包括历史消息与挂起状态；WS 承载实时上下行，另保留兼容只读方法 `history` 供商用客户端取历史。**历史与查询以 REST 为权威**。
- WS **不回放**实时事件：断线重连或刷新页面时用 REST 补齐；商用客户端也可用 WS `history`（`content` 为字符串），见 [`./4.06-实时通道.md`](./4.06-实时通道.md) §4.4。
- 实例（instance）没有自己的资源路径：它由 `(agentId, stage)` get-or-create，只在 session 响应里内联返回。

### 4.2 WebSocket

入口固定一条：`ws://localhost:4100/api/smart-factory/v1/ws`，与 REST 同端口同前缀。

上行方法（客户端发，`method` 取值）：

| method | 层 | 一句话 |
|---|---|---|
| `subscribe` | 原生 | 订阅会话级扇出，并在响应之后补发该会话当前挂起的审批与交互 |
| `unsubscribe` | 原生 | 取消订阅该会话 |
| `send` | 原生 | 落 user 消息并起 run，自动订阅该会话；payload 给 `sessionId` 或 `agentId`（至多一个），两者都不给是自由对话（新建目录会话）；新建会话的分支都必填 `modelId`，响应带顶层 `sessionId` / `runId` / `instanceId` |
| `history` | 兼容 | 按 `limit` / `offset` 取历史，`content` 为字符串，响应 `method` 为 `history.result` |
| `approval.respond` | 兼容 | 按 `approvalId`（审批消息 id）结算审批 |
| `tool.respond` | 兼容 | 按 `toolCallId` 结算交互，`answers` 支持数组或对象 |
| `model.switch` | 兼容 | 切换会话模型，下个 run 生效，活跃 run 不中断 |
| `mode.switch` | 兼容 | 切换审批模式，下个 run 生效 |
| `effort.switch` | 兼容 | 切换推理强度，下个 run 生效 |
| `message.respond` | 原生 | 按 `messageId` 结算审批或交互，与 REST 同一条服务路径 |
| `run.abort` | 原生 | 中止运行 |
| `ping` | 原生 | 保活，响应 method 为 `pong`、payload 为 `{ serverTime }` |

下行事件（服务端推，`method` 取值）：

| method | 层 | 一句话 |
|---|---|---|
| `connection.ready` | 原生 | 连接建立后立即推一条，载荷带 `connectionId` |
| `session.status` | 原生 | 会话状态变化（`not_started` / `in_progress` / `completed`） |
| `run.started` | 原生 | 顶层运行开始 |
| `run.status` | 原生 | 顶层运行状态变化，终态也走这一条 |
| `task.started` | 原生 | 子 agent 任务开始，子 run 随之创建 |
| `task.notified` | 原生 | 子 agent 任务结束，子 run 落终态 |
| `message` | 原生 | 一条消息的新建或更新，**upsert 语义**，按 `id` 覆盖渲染 |
| `chat.delta` | 原生 | 正文流式增量，**瞬态不落库**，只用于边收边渲染 |
| `chat.thinking` | 兼容 | 思考阶段 `start` / `delta` / `stop`（`delta` 带 `text`），**瞬态不落库**；旧的 `chat.thinking.delta` 已移除 |
| `chat.final` | 兼容 | 成功顶层 run 的终稿 `{content}` |
| `chat.error` | 兼容 | 失败顶层 run 的错误 `{message}` |
| `chat.aborted` | 兼容 | 中止顶层 run 的 `{reason}` |
| `approval.request` | 兼容 | 审批挂起通知，`approvalId` 即审批消息 id |
| `tool.interactive` | 兼容 | 交互挂起通知，带 `toolCallId` |
| `tool.executing` | 兼容 | 工具开始执行 |
| `tool.executed` | 兼容 | 工具执行结果 |
| `error` | 原生 | 连接级错误（如 `SLOW_CONSUMER`，服务端随后断开） |

`interactive.timeout` 刻意不实现：审批与交互没有超时，服务端不会发出该事件。

信封形状、每条方法的载荷、心跳与背压阈值见 [`./4.06-实时通道.md`](./4.06-实时通道.md)。

### 4.3 探活

`GET /api/smart-factory/v1/health` 是唯一没有单独篇章的端点，形状固定：

```bash
curl -s http://localhost:4100/api/smart-factory/v1/health
```

```json
{
  "status": "ok",
  "service": "smart-factory-server",
  "version": "0.1.0",
  "time": "2026-10-15T06:00:00.000Z"
}
```

它不查数据库、不依赖引擎，只回答「进程活着」。

### 4.4 模型（框架只读代理）

`GET /models/list` 返回 `{ items, activeId }`，数据来自框架的 `GET /api/framework/v1/models`（权威：`Cosight-Harness-开源/model-config-api.md`）。本服务自己读 `$COSIGHT_HOME/.module-token` 并请求回环地址，**浏览器不直接接触框架，也拿不到 `apiKey`**；`/active` 与 `/{id}` 不对外代理，其中 `/{id}` 只由服务端在起 run 时调用，用于解析 `modelName` / `baseUrl` / `apiKey`，密钥不进任何接口响应、日志与错误消息。

`items` 每项的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 框架模型 uuid，会话的 `modelId` 存的就是它；会话 `modelId` 恒非空，只能经 `sessions/create`、`sessions/:sessionId/update`、WS `model.switch` 或 `send` 新建会话（`agentId` / 自由对话，只作用于新会话）选择与切换，没有默认模型回退（服务端不猜模型；Web 端会在 `preview` / `evaluation` 建会话前自行解析，再显式传入） |
| `provider` | string | 供应商标识 |
| `protocol` | `'anthropic'` \| `'openai'` | 线协议；起 run 只接受 `anthropic` |
| `label` | string | 界面展示名 |
| `modelName` | string | 发给供应商的 model 字段，不是显示名 |
| `baseUrl` | string \| null | API 地址；`null` = 用该供应商官方地址 |
| `hasApiKey` | boolean | 是否已配密钥；列表不含 `apiKey` 本身 |
| `isActive` | boolean | 是否为当前生效模型 |
| `createdAt` / `updatedAt` | string | ISO 8601 |

上游不可用（框架没起、令牌缺失或不对、被四道门挡住、响应不合法）一律 `502 FRAMEWORK_UNAVAILABLE`，`message` 是可直接展示的中文排障提示。

### 4.5 工作区列表

`GET /api/smart-factory/v1/workspaces/list` 代理框架模块面的工作区列表，供前端与 e2e 取 `workspaceId`：

```bash
curl -s http://localhost:4100/api/smart-factory/v1/workspaces/list
```

```json
{
  "items": [
    {
      "id": "8b1f0c2d-4e5a-4b6c-9d7e-1f2a3b4c5d6e",
      "name": "周报助手开发",
      "defaultModelId": "a7cf0154-020b-4f97-b2bc-5ab8eb3bf0b5"
    }
  ],
  "activeId": "8b1f0c2d-4e5a-4b6c-9d7e-1f2a3b4c5d6e"
}
```

- 上游是 `GET /api/framework/v1/workspaces`；本服务透出 `id` / `name` / `defaultModelId` 与 `activeId`，**不下发 `directory`**，也不透出 `defaultAgentId`。`defaultModelId` 原样转发框架的值（`null` = 沿用框架全局当前模型），供 Web 端在 `preview` / `evaluation` 首次建会话时解析默认模型；服务端自己不用它、也不替调用方选模型。
- 无分页、无过滤参数；`activeId` 为 `null` 表示框架没有生效工作区。
- 框架不可达、令牌无效或上游非 2xx 时返回 `502 BAD_GATEWAY`，`message` 保留上游原因。

### 4.6 可监控目录清单（观测端）

`GET /api/smart-factory/v1/workspaces/directories/list` 是给本机观测端（cosight-viewer）的只读清单。
它在上节的工作区之上补两样观测端才需要的东西：`directory`（会话按 `cwd` 归属工作区）与**一条「内置与技能开发目录」**
（不属于任何框架工作区的会话都落在 `{COSIGHT_HOME}/smart-factory/` 下）。该条目**不按来源分条**：
观测端按目录前缀归属会话，给根一条即可覆盖全部，也避免把内置专家混进以工作区为项目的列表。

> 它**不是**框架启动时建的那个「默认工作区」（`framework/server/src/seed/seed.ts` 里的真实工作区行，
> 目录在 `{COSIGHT_HOME}/workspaces/{slug}`）。两者名字必须不同：观测端的筛选下拉会把它们并排渲染，
> 同名会让人以为是一回事。

```bash
curl -s http://localhost:4100/api/smart-factory/v1/workspaces/directories/list
```

```json
{
  "items": [
    {
      "id": "8b1f0c2d-4e5a-4b6c-9d7e-1f2a3b4c5d6e",
      "name": "周报助手开发",
      "directory": "/home/u/work/weekly",
      "defaultModelId": "a7cf0154-020b-4f97-b2bc-5ab8eb3bf0b5",
      "kind": "workspace"
    },
    {
      "id": "default",
      "name": "内置与技能开发目录",
      "directory": "/home/u/.cosight-harness/smart-factory",
      "defaultModelId": null,
      "kind": "default"
    }
  ],
  "activeId": "8b1f0c2d-4e5a-4b6c-9d7e-1f2a3b4c5d6e"
}
```

- `items` = 框架工作区（顺序同上游，`directory` 可为 `null`）+ 内置与技能开发目录一条（恒在最后）。
- `kind` 区分条目来源：`workspace` / `default`。本条目 `id` 固定 `default`、`name` 固定 `内置与技能开发目录`
  （展示文案；`id` / `kind` 才是判别依据，观测端不要按 `name` 判）；
  `directory` 是 `{COSIGHT_HOME}/smart-factory`（symlink 已解），其下三类会话都能被前缀命中：
  - 内置专家 runtime cwd：`builtin-agents/{id}/`
  - 技能开发目录会话：`skill-workshop/`
  - 没有生效工作区时的自由对话：`chat/`

  以上按缺省目录布局；用 `SKILLS_ROOT` / `CHAT_ROOT` 把目录挪到 `smart-factory/` 之外时本条目覆盖不到，
  需要另行扩展清单（本期不做）。
- 只暴露 `{COSIGHT_HOME}/smart-factory/`：`{COSIGHT_HOME}` 本身还有 `.module-token`、数据库与模块，不进观测清单。
- `activeId` 只来自框架，本条目永不生效；`defaultModelId` 原样转发，本条目恒 `null`。
- 框架不可达、令牌无效或上游非 2xx 时与 `/workspaces/list` 同口径返回 `502 BAD_GATEWAY`，不做降级。
- 本端点只读，不提供工作区创建 / 绑定目录 / 切换（那些仍在框架界面）。

## 5. 刻意不存在的接口

以下路径不是「暂未实现」，而是设计上不做；调用它们一律 `404 NOT_FOUND`（`api-contract.test.ts` 把 `instances/*` 钉死）。

| 路径 | 现状与原因 |
|---|---|
| `/instances/*` | instance 由 `(agentId, stage)` 自动 get-or-create，没有独立 CRUD；要按智能体查，用 `sessions/list?agentId=&stage=`，实例在 session 响应里内联 |
| `/runs/events`（SSE） | 实时统一走 WS，一条连接复用多会话；不并行维护第二条推送信道 |
| `/workspaces/*` 除 `/workspaces/list` | 本服务只读工作区 id 与名称；工作区的创建、绑定目录与切换在框架界面完成 |

## 6. 改动接口前的验收

契约是唯一权威，改动顺序是**先改文档再改代码**，改完 review 一致（[`../README.md`](../README.md) §5）。
合入前逐项过：

- `cd server && npm run typecheck`：0 报错。
- `cd server && npm test`：全绿；改哪篇先跑该篇「验收测试」映射的文件，合入前跑全量。
- 端到端：`smart-factory/` 下 `node scripts/dev.mjs e2e`（fake 引擎）。
- 引擎相关改动加跑真引擎：`ENGINE=claude-cli SF_PROMPT="用 Write 工具创建文件 a.txt" node scripts/dev.mjs e2e`，并确认挂起期间 `runs/abort` 能立刻打断。
- 接口形状改动（路径、请求体、响应字段、错误码、游标）另需 `server/tests/api-contract.test.ts` 通过，该文件覆盖 id 传法、分页与游标、错误码与「刻意不存在的接口」四类边界。

这些命令与前端的构建 / 测试无关：前端改动不触发本节的验收，接口形状变了才触发。
