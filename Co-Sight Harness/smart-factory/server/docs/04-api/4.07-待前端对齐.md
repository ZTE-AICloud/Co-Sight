## 1. 文件浏览接口（列目录 / 读文件）+ 发送框附件（**已闭环**）

- **前端现状（2026-10-20 已接入）**：
  - 发送框的「添加文件」换成真选择器：`web/src/shared/components/FilePicker.tsx` + `web/src/shared/api/fs.ts`，`MOCK_PATHS` 已删。
  - 选中的文件是**绝对路径**，随消息发给后端（WS `send` 的 `attachments: [{ path }]`）；历史里由消息自己的 `content.files` 渲染 chip（`shared/live/map-message.ts`），不再有本地临时状态。
  - 阶段 ① 右栏的文件树仍走 `/artifacts/*`（`FileViewer.tsx`），与本次的 `/fs/*` 是两套：前者看**智能体产物**，后者看**操作者本机**。
- **后端现状**：
  - 智能体产物：`/artifacts/*` 三个端点（`server/src/modules/artifact/*`），入参 `stage` + `agentId` + `path`，形状见 [`../03-architecture/07-artifact.md`](../03-architecture/07-artifact.md)。
  - 操作者本机：`/fs/*` 四个端点（`server/src/modules/fs/*`），前两个用于选路径，后两个用于对话里的文件引用预览 ——

    | 端点 | 入参 | 返回 |
    |---|---|---|
    | `GET /fs/roots` | 无 | `{ items: [{ label, path, workspaceId, active }] }`，快捷入口：主目录 + 框架登记的工作区 |
    | `GET /fs/list` | `?path=` 绝对路径（缺省主目录） | `{ path, parent, items: [{ name, path, type, size, mtime }], truncated }`，只列一层；条目超过 2000 条时 `truncated=true`（只返回前面一部分） |
    | `GET /fs/read` | `?path=` 绝对路径（支持 `~/`） | `{ path, name, size, mtime, content }`，UTF-8、去 BOM；超 `ARTIFACT_MAX_FILE_BYTES`（默认 2 MiB）`413`，前 8 KiB 含 NUL `415` |
    | `GET /fs/raw/*splat` | 路径分段：`/fs/raw/<绝对路径去掉开头 />` | 原始字节流；`Content-Type` 按扩展名，恒带 `X-Content-Type-Options: nosniff`、`Cache-Control: no-store`、`Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-downloads`；不受文本上限约束 |

    解析在 `server/src/shared/workspace/local-path.ts`：**先 `realpath` 再 stat**，整机任意绝对路径都能列 / 读（主目录 / 工作区只是快捷入口，不是边界）；相对路径、不存在 / 类型不符的路径分别回 `400` / `404`。`~` 在服务端展开一次，前端不必自己拼主目录。`parent` 一路给到文件系统根。`send` 的附件校验与这里是同一份实现。
- **`raw` 为什么用路径分段**：HTML 预览要在 iframe 里加载相对资源。`?path=` 形态下 `./style.css` 会被解析成 `/fs/style.css`（查询串丢失）；分段形态下它自然落到 `/fs/raw/.../style.css`。
- **安全前提**：`/fs/*` 无鉴权，等于整机文件树只读暴露，只应部署在可信网络。
- **约定**：端侧形态下**没有上传**。`/files`（上传）只服务封面图这类要长期保存的静态资源；附件永远是路径，引擎用 Read 工具自己读。

每个会话的 `modelId` 恒非空，没有工作区默认 / 框架生效 / 本机配置回退，也不能清空。Web 端在 `preview` / `evaluation` 首次建会话前会自己解析默认模型，再显式传进来；服务端不感知。
起 run 前服务端调框架详情 `GET /api/framework/v1/models/{id}` 取 `modelName` / `baseUrl` / `apiKey`：详情 404/422、`protocol` 非 `anthropic`、`apiKey` 或 `modelName` 为空返回 `400`；框架不可达 / 5xx 返回 `502`，都不建 run（见 [`../03-architecture/04-engine.md`](../03-architecture/04-engine.md) §3）。
密钥只存在于服务端内存与引擎子进程环境，不落库、不下发前端、不进日志与错误消息，`GET /models/list` 提供不含密钥的候选（框架只读代理）。
- **建议落地方式**：切换器选中项取其 `id`，`sessions/create` 与首帧 `send`（带不带 `agentId` 都一样）都必须带上 `modelId`；运行中切换用 WS `model.switch`（不打断当前 run），run 间隙也可用 REST `sessions/:sessionId/update`；候选列表来自 `GET /models/list`（`shared/api/models.ts` 对接）。

### 9.1 上行方法

| 商用客户端的调用 | 状态 | 本服务的形状 |
|---|---|---|
| `send` 首帧 `{ prompt, versionId }` | 已实现（字段改名） | 本开源版**没有 `versionId` 概念，用 `agentId` 取代**：`send { agentId, modelId, mode?, effort?, prompt }`，`modelId` 必填且非空，`mode` 缺省 `workspace_write`、`effort` 缺省 `high`。**每次首帧都新建一条 runtime 会话**，不复用已有会话；三个字段落在新会话上，首轮 run 使用它们，`resumeSessionId` 为 `null`。**`agentId` 可省**：省掉即自由对话，每次新建一条目录会话（cwd = 当前工作区目录，没有工作区落 `{COSIGHT_HOME}/smart-factory/chat`），`modelId` 同样必填。建 run 前先解析引擎 / 工作区 / cwd / 模型，失败直接返回错误且不建 run；本次新建的会话会被删除。响应 `send.result` 顶层带 `sessionId` / `runId` / `instanceId` / `status`（恒 `"running"`）/ `effort` / `modelId` / `modelName` / `modelFellBack`（恒 `false`），另带 `message` / `run`（`run.status` 同为 `running`），**没有 `created`**；`run.started` 在响应前广播（run 已被并发中止时不发） |
| `send` 续聊 `{ prompt, sessionId }` | 已实现 | 响应 `send.result` 顶层带 `runId`，客户端原写法可直接读；其余字段与首帧相同（含 `status:'running'` / `effort` / `modelId` / `modelName` / `modelFellBack:false` / `message` / `run`）。续聊不能携带 `modelId` / `mode` / `effort`，三者一律取会话当前值，带了返回 `VALIDATION` |
| `history` `{ sessionId, limit, offset, includeTelemetry }` | 已实现 | 响应 `history.result`，载荷 `{ sessionId, messages, total }`，`total` 为该会话全部消息条数；`content` 为字符串；`offset` 从最新往前跳过；`includeTelemetry` 接收但忽略 |

| `tool.respond` `{ toolCallId, answers }` | 已实现 | `answers` 支持 `[{question, answer}]` 数组与 `{问题原文:[选项]}` 对象；响应 `{ toolCallId, received: true }`，结算结果走 `message` 事件 |
| `model.switch` / `mode.switch` / `effort.switch` | 已实现 | 只改会话字段，**下个 run 生效，活跃 run 不中断**；不返回 `CONFLICT`；`model.switch` 的 `modelId` 必须非空、不能清空；响应 `{ sessionId, modelId, appliesTo: "nextRun" }` / `{ sessionId, mode }` / `{ sessionId, effort }`；其它订阅端收到 `settings.changed` |
| `run.abort` / `ping` | 已实现 | `run.abort` 响应 `{ runId, aborted: true }`（`runId` 为解析后的顶层 run）；`ping` 响应 `method: "pong"`、载荷 `{ serverTime }` |

## 10. 子 agent 展示契约（待前端实现）

- **前端现状**：尚无子 agent 会话与状态展示；现有页面只按顶层 run 渲染正文与审批。
- **后端现状**：子 run 血缘、`task.started` / `task.notified` 事件与 `runs/children` 端点按下面的契约提供；顶层 run 的现有事件与字段不变。
- **建议落地方式**：按下表实现；`task.*` 不属于 viewer 兼容层，忽略也不会影响现有渲染。

| 场景 | 依据 | 前端动作 |
|---|---|---|
| 子 agent 开始 | WS `task.started` | 以 `runId` 为键建子 agent 块，按 `parentRunId` 挂到父块下；标题用 `subagentType` 与可选的 `description`，按 `delegationDepth` 缩进。不要等内容消息到达才建块。wire 的工具调用 id 字段是 `toolCallId`（REST `Run` DTO 叫 `parentToolUseId`） |
| 子 agent 结束 | WS `task.notified` | 按 `runId` 把块收敛为 wire 值 `completed` / `failed` / `stopped`（对应 DB/REST 的 `succeeded` / `failed` / `aborted`）；展示可选的 `summary`，`failed` 展示可选的 `error`。终态后不再为它保留流式占位 |
| 内容归属（带 `parentRunId`） | `chat.delta` / `chat.thinking` / `tool.*` / `approval.request` / `tool.interactive` | 事件里的 `runId` 是子 run 时挂到对应子块；payload 里的 `parentRunId` 可直接定位父块。审批与交互结算仍按 `approvalId` / `toolCallId`，不要按 `runId` 结算。`chat.final` / `chat.error` / `chat.aborted` 只表示顶层 run，不用于子 run 收敛 |
| 内容归属（不带 `parentRunId`） | `message` | 只带 `runId`；父 run 关系用 `task.started` 建立的 `runId → parentRunId` 映射定位，断线后可用 `runs/children` 补全 |
| 断线重连 | REST `runs/list` + `runs/children` | 先 `runs/list?sessionId=` 拿顶层 run，再对需要展示的顶层 run 调 `runs/children?runId=&page=&pageSize=`，按 `startedAt` 升序补块。子 run 的 `waiting` 用于展示子 agent 正在等待审批 |
| 状态边界 | `run.started` / `run.status` | 只更新顶层 run 与顶层忙碌态；子 agent 状态只信 `task.*` 与 `runs/children` |

- 子 agent 正文转发跟随 SDK 默认（0.3.300 `forwardSubagentText=false`），不要假设每个子 run 都有正文；`task.started` 之后允许先出现空块。
- 更深层级：子 run 也可能有子 run，拿子 run 的 `id` 再调一次 `runs/children` 逐层展开。

## 13. 智能体列表 / 详情返回 `runtimeDir`（2026-10-22 已接入）

- **后端现状**：`Agent` DTO 新增 `runtimeDir: string | null`（必返，见 [5.01 契约](../05-openapi/5.01-agent-openapi.yaml)），
  表示智能体**运行时的工作目录**（runtime 会话的 cwd），服务端现算、不入库：
  内置智能体 = 定义目录本身（与 `dir` 相同）；普通智能体 = development 产物中最新版本目录

- **null 的语义**：产物尚未生成、布局不完整或交付门禁未通过时为 `null` —— 即「此刻还没有可运行的目录」，

- **建议落地方式**：前端「使用 / 运行」入口按 `runtimeDir` 是否为 null 灰显或提示「产物未就绪」，
  不要自己拼路径，也不要把 `dir` 当 cwd 用（`dir` 是智能体根目录，不是运行目录）。

## 14. 智能体列表按产物状态筛选（2026-10-28 已接入）

- **后端**：`GET /agents?status=` 收 `not_started` / `building` / `blocked` / `failed` / `completed` 五个取值
  （枚举外 400，空串视为未传），与 `keyword` / `tag` / `workspaceId` / `source` 是 AND 关系。
  `status` 仍是现算的派生字段、库里没有这一列，所以这条路径先取全量、过滤后再切页 ——
  `total` 是过滤后的全量（机制见 [08-agent.md §2](../03-architecture/08-agent.md)）。
  `Agent.status` 的 `null`（读盘失败的降级值）不是一种状态，传不进来。
- **前端（已实现）**：专家页工具条在来源 chip 右边多一组状态 chip（全部 / 已就绪 / 生成中 / 未开始 /
  已暂停 / 生成失败），换状态回到第 1 页；状态也计入「清空筛选」与空态措辞。词表复用卡片上那行状态。
