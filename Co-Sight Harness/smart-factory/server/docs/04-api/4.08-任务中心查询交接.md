# 任务中心查询交接：智能体与会话

> 状态：**已定稿**。本文对比 smart-factory 与 agent-runtime 的智能体 / 会话查询接口，给出任务中心直连 smart-factory 时的字段映射与改造清单。
> 代码落点：`server/src/modules/agent/*`、`server/src/modules/session/*`、`server/src/shared/types/index.ts`。
> 相关篇：[`4.01-接口总览.md`](./4.01-接口总览.md)、[`4.03-会话.md`](./4.03-会话.md)、[`../05-openapi/5.01-agent-openapi.yaml`](../05-openapi/5.01-agent-openapi.yaml)。

## 1. 结论

**查询能力已基本对齐，路径与少量口径仍不同。**

会话列表的过滤参数、分页信封、Session 审批与派生字段已经与 agent-runtime 对齐；任务中心直连时仍不能只换 base URL，需要按第 5 节处理路径、错误体与剩余口径差异。

### 1.1 已对齐

- 分页信封：智能体列表与会话列表都返回 `{ items, total, page, pageSize }`，并回显校验后的 `page` / `pageSize`。
- 会话列表过滤：`subjectType` / `subjectId` / `instanceId` / `type` / `status` / `name` / `id` / `resumeSessionId` / `createdFrom` / `createdTo` 均已支持；`subjectId` 与 `agentId` 等价。
- 会话字段：`approvalMode` / `approvedAll` / `messageCount` / `lastMessage` / `firstUserMessage` 均已下发。
- 会话 `modelId` 恒非空：`sessions/create` 必填，切换只能改成另一个非空模型，没有 auto / 回退语义（Web 端会在预览 / 评估建会话前自行解析默认模型，再显式传入）。
- `approvedAll` 已从 Run 移到 Session，会话级语义与 agent-runtime 一致。
- `lastMessage` / `firstUserMessage` 仅列表填充，详情 / 创建 / 更新恒为 `null`，与 agent-runtime 一致。

### 1.2 仍不同

| 类别 | 差异 |
|---|---|
| 路径 | smart-factory 是 `/api/smart-factory/v1`；agent-runtime 是 `/api/agent-runtime/v1`。会话列表是 `/sessions/list`，详情 id 走 query |
| agent 搜索 | agent-runtime 用 `name`；smart-factory 用 `keyword`（匹配 `name` / `id` / `description`） |
| 错误体 | smart-factory 是 `{error,message}`；agent-runtime 是 `{code:200,message,data,reason}` |
| 分页口径 | 信封一致；`pageSize` 上限 200 vs 100，非法值回落默认 vs 400 |
| 默认类型 | 两边都在无精确定位参数时默认只看 `runtime`。**差别在 `subjectId` / `agentId`**：agent-runtime 给了它就取消默认、返回该主体全部阶段；smart-factory 的 `agentId` 只是过滤、不取消默认（`?agentId=` 仍只给 runtime） |
| 版本 | agent-runtime 的 `versionId` 与响应 `subjectVersionId` 在 smart-factory 不存在 |
| 主体类型 | smart-factory 只支持 `subjectType=agent`，没有 skill 主体 |
| agent 响应 | smart-factory 没有 agent 级 `modelId` / `versions`，多 `workspaceId` / `tags` / `status` / `dir` |
| id 前缀 | agent 是 `agent_` vs `agt_`；session / instance / run / message 前缀一致 |

## 2. 智能体查询

### 2.1 端点映射

| 能力 | agent-runtime | smart-factory | 是否一致 |
|---|---|---|---|
| 列表 | `GET /api/agent-runtime/v1/agents` | `GET /api/smart-factory/v1/agents` | 路径同名，前缀不同 |
| 详情 | `GET /api/agent-runtime/v1/agents/{agentId}` | `GET /api/smart-factory/v1/agents/{agentId}` | 路径同名，前缀与响应不同 |

### 2.2 列表参数

| 参数 | agent-runtime | smart-factory | 说明 |
|---|---|---|---|
| 名称搜索 | `name` | `keyword` | agent-runtime 只匹配 `name`；smart-factory 匹配 `name` / `id` / `description` |
| 状态 | 不支持 | 不支持 | 状态是派生字段，不是筛选参数；见下文字段映射 |
| 标签 | 不支持 | `tag` | 精确匹配一个标签 |
| 工作区 | 不支持 | `workspaceId` | 精确过滤框架工作区 |
| 分页 | `page` / `pageSize` | `page` / `pageSize` | 默认 1 / 20；上限 100 vs 200 |
| 权限范围 | 按登录身份的租户 / owner 收敛 | 无鉴权、无 owner 维度 | smart-factory 是端侧本地单用户 |

### 2.3 响应信封

两侧现在都是：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

`page` / `pageSize` 是校验后的实际取值（缺省、回落、截断之后），任务中心可以直接用于翻页状态。

### 2.4 Agent 字段映射

| agent-runtime `AgentDto` / `AgentDetailDto` | smart-factory `Agent` | 说明 |
|---|---|---|
| `id` | `id` | 前缀不同：`agent_` vs `agt_` |
| `name` | `name` | 一致 |
| `icon` | `icon` | 一致 |
| `description` | `description` | 一致 |
| `modelId` | 无 | smart-factory 的模型是会话级；agent 列表 / 详情不返回默认模型 |
| `versions` | 无 | smart-factory 没有版本概念；详情不返回 `versions` |
| `createdAt` / `updatedAt` | `createdAt` / `updatedAt` | 一致 |
| 无 | `workspaceId` | smart-factory 额外返回框架工作区 id |
| 无 | `tags` | smart-factory 额外返回标签数组 |
| 无 | `status` | smart-factory 额外返回派生状态：`not_started` / `building` / `blocked` / `failed` / `completed`；内置智能体恒为 `completed`，`null` 仅表示该条状态读取失败 |
| 无 | `dir` | smart-factory 额外返回智能体产物根目录，前端不应自己拼路径 |

### 2.6 详情差异

agent-runtime 的详情返回基础字段 + `versions` 数组。
smart-factory 的详情与列表项同形，没有 `versions`，也没有 agent 级 `modelId`。
任务中心如果依赖「当前版本 / 发布状态」，需要改成读取 session 或不展示版本信息。

## 3. 会话查询

### 3.1 端点映射

| 能力 | agent-runtime | smart-factory | 是否一致 |
|---|---|---|---|
| 列表 | `GET /api/agent-runtime/v1/sessions` | `GET /api/smart-factory/v1/sessions/list` | 路径不同 |
| 详情 | `GET /api/agent-runtime/v1/sessions/{id}` | `GET /api/smart-factory/v1/sessions/detail?sessionId={id}` | 详情 id 从路径改成 query |

### 3.2 列表参数

| 参数 | agent-runtime | smart-factory | 说明 |
|---|---|---|---|
| 主体类型 | `subjectType` | `subjectType` | 已对齐；smart-factory 只接受 `agent`，其它值 400 |
| 主体 id | `subjectId` | `subjectId` / `agentId` | 已对齐；两个名字等价，同时给且不同时 400，`subjectId` 优先 |
| 实例 | `instanceId` | `instanceId` | 已对齐；与 `agentId` / `stage` 取交集 |
| 阶段 / 类型 | `type` | `type` / `stage` | 已对齐；`type` 是 `stage` 的逗号分隔别名，`all` 取消阶段过滤；smart-factory 多一个 `evaluation` |
| 状态 | `status` | `status` | 已对齐；逗号分隔多值 |
| 名称 | `name` | `name` | 已对齐；子串匹配 |
| 会话 id | `id` | `id` | 已对齐；逗号分隔多值，IN 匹配 |
| 版本 | `versionId` | 不支持 | smart-factory 没有版本概念 |
| resume 标识 | `resumeSessionId` | `resumeSessionId` | 已对齐；smart-factory 支持逗号分隔多值 |
| 创建时间范围 | `createdFrom` / `createdTo` | `createdFrom` / `createdTo` | 已对齐；ISO 日期时间，非法 400 |
| 分页 | `page` / `pageSize` | `page` / `pageSize` | 默认 1 / 20；上限 100 vs 200 |

补充：

- **默认类型**：两边在「没有任何精确定位参数」时都默认只看 `runtime`。取消默认的参数**不完全一致**：
  - agent-runtime：`subjectId` / `instanceId` / `versionId` / `id` / `resumeSessionId`；
  - smart-factory：`instanceId` / `cwd` / `id` / `resumeSessionId`。`subjectId` / `agentId` **不取消**——它只按主体过滤，`sessions/list?subjectId=` 返回的是该智能体的 runtime 会话；要全部阶段得显式给 `type=all` / `stage`，或按 `instanceId` 查。
  - 任务中心若要「该主体的全部会话」，不能只依赖 agent-runtime 的旧口径，需要显式传 `type=all`。
- 不要假设一个智能体只有一条会话：每次 `send { agentId }` 都会新建一条 runtime 会话。
- `runtime` 里还有**自由对话**（`send` 不带 `agentId`，目录实例、`instance.agentId` 为 `null`）。任务中心只要智能体会话时传 `subjectType=agent`：它等价于「只命中智能体实例」，会把自由对话排除。
- `type` 与 `stage` 同时给时，`type` 必须包含该 `stage` 或为 `all`，否则 400；实际过滤按 `type` 的集合执行。
- `status` 的取值是 `not_started` / `in_progress` / `completed`；`type` 的取值是 `development` / `preview` / `runtime` / `evaluation` / `all`。
- `subjectId` / `agentId` 会做形态校验，非法 400；`subjectType=agent` 排除目录实例（自由对话）。
- 所有过滤条件按 AND 组合；空串视为未传。

### 3.3 响应信封

两侧现在都是：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

### 3.4 Session 字段映射

| agent-runtime `SessionDto` | smart-factory `Session` | 说明 |
|---|---|---|
| `id` | `id` | 都是 `sess_` 前缀 |
| `instanceId` | `instanceId` | 一致 |
| `subjectType` | 无 | smart-factory 只有 agent；筛选参数支持，响应不回显 |
| `subjectId` | 无 | 用 `instance.agentId` 替代 |
| `subjectVersionId` | 无 | smart-factory 没有版本 |
| `name` | `name` | smart-factory 允许空串，且没有改名端点 |
| `modelId` | `modelId` | smart-factory 恒为非空模型 uuid，创建会话时必填；agent-runtime 可用 `null` 表示未指定 |
| `status` | `status` | 都是 `not_started` / `in_progress` / `completed` |
| `effort` | `effort` | 枚举一致 |
| `approvalMode` | `approvalMode` | **已对齐**；库列名仍是 `mode`，但 DTO 字段已改名 |
| `approvedAll` | `approvedAll` | **已对齐**；会话级开关 |
| `resumeSessionId` | `resumeSessionId` | 一致 |
| `lastMessage` | `lastMessage` | **已对齐**；列表填充最新一条 `type='text'` 的正文，详情 / 创建 / 更新恒为 `null` |
| 无 | `firstUserMessage` | 列表填充第一条 `role='user'` 且 `type='text'` 的正文，详情 / 创建 / 更新恒为 `null` |
| `messageCount` | `messageCount` | **已对齐**；统计全部消息类型 |
| `createdAt` / `updatedAt` | `createdAt` / `updatedAt` | 一致 |
| 无 | `instance` | smart-factory 内联实例对象，含 `agentId` / `stage` / `engine` |

### 3.6 详情差异

smart-factory 详情与列表项同形，同样内联 `instance`。
`messageCount` 详情也有值；`lastMessage` / `firstUserMessage` 在详情里恒为 `null`，与 agent-runtime 详情一致。
任务中心在列表展示「最后一条消息 / 消息数」时不再需要额外调 `messages/list`。

### 3.7 runtime 会话是 1:N

一个 `(agentId, runtime)` 实例可以有多条会话：

- 每次 `send { agentId, modelId, mode?, effort? }` 都**新建**一条 runtime 会话，响应返回新的 `sessionId`；重复调用不会复用旧会话。
- 续聊必须 `send { sessionId }`，任务中心必须使用首帧响应里的 `sessionId` 去取消息、运行与详情，不能按 `agentId` 猜一条会话。
- `sessions/create` 也要求非空 `modelId`；所有 Session 响应的 `modelId` 恒非空，没有 `""` 或 `null` 的自动模型语义。
- 若任务中心要列某智能体的全部 runtime 会话，用 `sessions/list?subjectType=agent&subjectId=&type=runtime`，按 `updatedAt` 降序展示（最近有活动的在前）。

## 4. 分页、错误与 id

### 4.1 分页

| 项 | agent-runtime | smart-factory |
|---|---|---|
| 响应字段 | `items` / `total` / `page` / `pageSize` | `items` / `total` / `page` / `pageSize` |
| 默认 page / pageSize | 1 / 20 | 1 / 20 |
| pageSize 上限 | 100 | 200 |
| 非法 page / pageSize | 400 | 回落到默认值 |
| 排序 | agent 列表 `createdAt desc`；会话列表 `createdAt desc` | agent 列表 `updatedAt desc`；会话列表 `createdAt desc` |

### 4.2 错误体

agent-runtime：

```json
{
  "code": 200,
  "message": "会话不存在",
  "data": null,
  "reason": "NOT_FOUND"
}
```

HTTP 状态码承载语义，`code` 恒为 200。

smart-factory：

```json
{
  "error": "NOT_FOUND",
  "message": "会话 sess_xxx 不存在",
  "messageKey": "error.not_found.session",
  "params": { "sessionId": "sess_xxx" }
}
```

HTTP 状态码同样承载语义，但没有 `data` / `reason`，机器码在 `error`。
`messageKey` / `params` 是增量字段：任务中心若只按 `error` 判断，可以直接忽略；
需要给用户看英文时再按 4.02 §10.1 的降级规则翻译。本次不改两边的错误解析器。

### 4.3 id

| 实体 | agent-runtime | smart-factory |
|---|---|---|
| agent | `agent_<uuid>` | `agt_<uuid>` |
| session | `sess_<uuid>` | `sess_<uuid>` |
| instance | `inst_<uuid>` | `inst_<uuid>` |
| run | `run_<uuid>` | `run_<uuid>` |
| message | `msg_<uuid>` | `msg_<uuid>` |

任务中心不能把 `agent_` 前缀写死；id 应作为不透明字符串处理。

## 5. 任务中心改造清单

如果任务中心要直连 smart-factory，至少做以下改动：

| 项 | 现在（agent-runtime） | 改为（smart-factory） |
|---|---|---|
| base URL | `/api/agent-runtime/v1` | `/api/smart-factory/v1` |
| agent 列表搜索 | `?name=` | `?keyword=` |
| agent 详情 | `GET /agents/{id}` | 同路径，但响应没有 `modelId` / `versions` |
| 会话列表 | `GET /sessions?subjectType=agent&subjectId=` | `GET /sessions/list?subjectType=agent&subjectId=`（也可用 `agentId`） |
| runtime 会话 | `type=runtime` | `type=runtime`（含义已对齐），路径换成 `/sessions/list`；一个智能体可有多条，必须按会话 id 处理 |
| 默认类型 | 不传时默认 `runtime` | 不传阶段就返回全部四个阶段；需要 runtime 会话时显式传 `type=runtime` |
| 会话详情 | `GET /sessions/{id}` | `GET /sessions/detail?sessionId={id}` |
| 主体 | `subjectId` / `subjectType` | 已支持；`subjectType` 只能是 `agent`，没有 skill 主体 |
| 审批模式 | `approvalMode` | Session 响应字段是 `approvalMode`；WS `mode.switch` 请求 / 响应仍是 `mode`，`settings.changed.settings.mode` 也保持 `mode` |
| 会话级 approvedAll | `approvedAll` | 已对齐；读 Session，不要再读 Run |
| 模型 | `modelId: null` 表示未指定 | `modelId` 恒为非空模型 uuid；创建会话时必填，没有 auto / 回退 |
| 会话消息数 | `messageCount` | 已对齐，直接读 Session |
| 最后一条消息 | `lastMessage` | 已对齐，列表直接读；详情恒为 `null` |
| 第一条用户消息 | `firstUserMessage` | 列表直接读；详情恒为 `null` |
| 版本 / 发布状态 | `versions` | smart-factory 没有版本概念，隐藏或删除；不要传 `versionId` |
| 分页回显 | `page` / `pageSize` | 已对齐，响应直接回显 |
| pageSize 上限 | 100 | 200（超过 100 也能返回，不要假设最多 100） |
| 错误解析 | `reason` | `error` |

## 6. 不支持与额外字段

### 6.1 agent-runtime 有、smart-factory 没有

- agent 级默认模型 `modelId`
- agent 版本 `versions` 与版本状态
- 会话 `subjectType` / `subjectId` / `subjectVersionId` 响应字段（筛选已支持，响应不回显）
- 会话 `versionId` 过滤
- 默认 `type=runtime` 语义
- 租户 / owner 可见范围
- 统一错误体 `reason`

### 6.2 smart-factory 有、agent-runtime 没有

- agent `workspaceId` / `tags` / `status` / `dir`
- agent 列表 `keyword` / `tag` / `workspaceId` 过滤
- 会话四阶段 `development` / `preview` / `runtime` / `evaluation`
- 会话内联 `instance`
- 会话 `agentId` / `stage` 过滤入口（与 `subjectId` / `type` 等价）
- `resumeSessionId` 多值反查
- `agents/tags` 标签清单

## 8. 如果要做到零改造

如果任务中心希望不改调用代码，剩余的兼容层至少包括：

- `/sessions` 列表别名与 `/sessions/{id}` 详情别名；smart-factory 的集合级路径是 `/sessions/list` 与 `/sessions/detail?sessionId=`。
- agent 列表支持 `name` 别名（当前是 `keyword`，且会匹配 `id` / `description`）。
- 错误体补 `reason` / `data`。
- 分页口径对齐：`pageSize` 上限与非法值行为。信封本身已对齐。
- `versionId` 需要忽略或拒绝：smart-factory 没有版本概念，当前也没有该过滤参数；不能把「忽略」当成「已过滤」。
- agent 响应补 `modelId`，详情补 `versions`；没有版本时返回空数组。
- 会话响应补 `subjectType` / `subjectId` / `subjectVersionId`；其中 `subjectType` 恒为 `agent`。
- 默认类型语义对齐：agent-runtime 无精确定位参数时默认 `runtime`，smart-factory 无默认阶段。
- id 前缀无法同时兼容 `agent_` 与 `agt_`，建议任务中心按不透明字符串处理。

以上是服务端兼容层的候选清单，本期未实现。
任务中心如果接受第 5 节的改造，可以直接使用 smart-factory 当前接口。
