## 1. 端点

| 方法 | 路径 | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/agents/{agentId}` | — | `200` `AgentDetail` = `Agent` + `{ skills, commands }` |

`GET /agents`（列表）、`POST /agents`（create）、`POST /agents/{agentId}/update` 仍返回 `Agent`，
不带这两项 —— 列表一页最多 200 行，不能逐行扫两棵 `.claude` 树。

## 2. 什么叫「可执行」

**引擎会在运行目录的 `.claude` 下自动发现、`/` 菜单里能真正调用的条目。**

```
<runtimeDir>/
├── .claude/skills/<目录名>/SKILL.md        → skill，调用方式是 /<目录名>
└── .claude/commands/ 下的 .md（含子目录）   → command，调用方式是 /<文件名去 .md>
```

`runtimeDir` 是 `Agent` 上已有的字段，口径与 runtime 会话的起跑门禁**同源**：

| 智能体 | `runtimeDir` |
|---|---|
| 内置（`source=builtin`） | 定义目录本身（`{COSIGHT_HOME}/smart-factory/builtin-agents/{id}`） |
| 普通，产物 `completed` | `<dir>/development/output/agents/{agentName}/{vN}`，取最新 `vN` |
| 普通，未生成 / 布局不完整 / 门禁未过 | `null` |

所以本端点**不另做一套就绪判定**：`runtimeDir === null` 时 `skills` / `commands` 都是空数组，
「为什么空」由 `Agent.status` 回答；需要人读原因（`reasons` / 门禁明细）走 `GET /agents/{id}/production`。

插件技能与命令的来源是两块并集：

1. **运行目录自己打开的插件**（`.claude/settings.json` 的 `enabledPlugins`，如 `{"drive@zte-ai-lab": true}`）；
2. **产品运行时能力 `drive@zte-ai-lab`**：安装器按 user scope 装它，引擎不传 `settingSources`、
   SDK 默认加载 user 层 settings，所以**每个**智能体的会话都能调 `/drive:*`。只看「自己声明」
   会漏报 —— 用户智能体的目录里没有这份 settings，但那 5 个技能确实可用。

插件载荷里扫两个目录，名字按引擎的注册方式带插件前缀：

```
<installPath>/skills/<目录名>/SKILL.md      → skills[]，名字是 plugin:skill（如 drive:drive）
<installPath>/commands/ 下的 .md（含子目录） → commands[]，名字是 plugin:command
                                              （如 cosightbot:pkm、cosightbot:soc）
```

显式关闭优先：智能体目录写 `false` / `null` 以目录为准，目录没写再看用户 settings。插件没装
（`{CLAUDE_CONFIG_DIR:-~/.claude}/plugins/installed_plugins.json` 里没有，或载荷目录不在）
就不列——「可执行」只报此刻真能调用到的东西。

只列 **`/` 菜单里点得到的技能**：`SKILL.md` 显式写 `user-invocable: false` 的跳过
（drive 2.3.4 的 17 个 `skills/` 目录里只有 5 个可点，其余是流水线内部子技能）；
缺省视为 `true`，与引擎一致。命令没有这个开关，载荷 `commands/` 下的 `.md` 全部列出。

明确不扫：

- **其余用户自装插件**（`agent-genesis` / `goldeval` / `skill-optimizer`）：构建期工具，不是运行时能力，
  且随机器而异；
- **插件子智能体**：`plugin:agent` 不在「技能和命令」的范围内，暂不列；
- **development 工作台**的 `.claude`：那是构建会话的工作目录，不是产物；
- `.claude/agents/*.md`（子智能体）、hooks、rules：不在「技能和命令」的范围内。

## 3. 响应字段

```json
{
  "id": "agt_xxx",
  "runtimeDir": "/…/development/output/agents/weather-agent/v3",
  "status": "completed",
  "skills": [
    {
      "name": "weather-query",
      "displayName": "weather-query",
      "description": "城市天气查询",
      "version": "1.0",
      "path": "/…/v3/.claude/skills/weather-query",
      "updatedAt": "2026-10-26T06:00:00.000Z"
    }
  ],
  "commands": [
    {
      "name": "weekly-report",
      "namespace": "reports",
      "description": "生成本周周报",
      "path": "/…/v3/.claude/commands/reports/weekly-report.md",
      "updatedAt": "2026-10-26T06:00:00.000Z"
    }
  ]
}
```

### `skills[]`

| 字段 | 说明 |
|---|---|
| `name` | `.claude/skills` 下的目录名，也是 `/` 命令名；插件技能是 `plugin:skill` |
| `displayName` | `SKILL.md` frontmatter 的 `name`；缺失时等于 `name` |
| `description` | frontmatter 的 `description`；缺失为空串 |
| `version` | frontmatter 的 `version`（如 `1.0`）；没有为空串 |
| `path` | 技能目录绝对路径 |
| `updatedAt` | 技能目录 mtime |

与 `GET /agents/{id}/skills` 的 `items` **同型**（同一个 `AgentSkillItem`），只是过滤口径不同（见 §5）。

### `commands[]`

| 字段 | 说明 |
|---|---|
| `name` | 文件名去掉 `.md`，也是 `/` 命令名；插件命令是 `plugin:command` |
| `namespace` | 所在子目录（`/` 连接）；顶层命令为空串。**只用于展示分组，不参与命令名**。插件命令记插件名 |
| `description` | frontmatter 的 `description`；无 frontmatter / 读不到为空串 |
| `path` | 命令文件绝对路径（插件命令指向插件载荷目录） |
| `updatedAt` | 文件 mtime |

命令名只取文件名是 Claude Code 的约定：`commands/ci/build.md` 就是 `/build`，`ci` 只作为
`(project:ci)` 分组标签出现在 `/help` 里，**不生成 `ci:build`**。插件命令的前缀来自插件名：
`<installPath>/commands/pkm.md` 在 `cosightbot@cosight-bot` 下是 `/cosightbot:pkm`。

## 4. 判定规则

| 情形 | 结果 |
|---|---|
| `runtimeDir === null` | `skills: []`、`commands: []`；原因由 `status` / `/production` 回答 |
| 有 `runtimeDir` 但没有 `.claude` | 空数组，不是错误 |
| 技能目录缺 `SKILL.md` | **不返回**（引擎不会发现它）；插件载荷里的技能同一口径 |
| `SKILL.md` 写 `user-invocable: false` | 不返回（`/` 菜单里点不到） |
| 点开头的技能目录 / 命令文件 / 子目录 | 跳过 |
| 声明了插件（含产品默认的 drive）但没装 / 登记缺失 / 载荷目录不可读 | 该插件一条都不列，不报错 |
| 插件在智能体目录或用户 settings 里显式写 `false` / `null` | 不列，显式关闭优先 |
| `settings.json` 缺失或 `enabledPlugins` 形状不对 | 只列 `.claude/skills`、`.claude/commands` 与产品运行时能力，不报错 |
| 命令子目录 | 递归扫描；`namespace` 记录相对 `.claude/commands` 的路径；插件命令记插件名 |
| 不同子目录出现同名命令 | 按相对路径升序保留第一个（同一个 `/<name>` 只有一个真正生效） |
| 插件命令 | 载荷 `commands/` 下的 `.md` 全部列出，名字是 `plugin:command`；与技能同一套「打开且装着才列」规则 |
| 非 `.md` 文件 | 忽略 |
| 单个条目 stat / 读 frontmatter 失败（并发删除等） | 跳过该条，不整体失败 |
| `.claude` 根目录不可读 | 该类退化为空并记 `console.error`，不把详情打成 500（与列表读取产物状态的降级口径一致） |

排序固定：两个数组都按 `name` **字节升序**（不用 locale 比较，响应顺序不随运行环境变）。

跨类同名（一个 skill 和一个 command 都叫 `foo`）服务端不裁决，两个数组各自返回；
前端拼 `/` 菜单时按 command 优先，这是 UI 约定，不是引擎行为。

## 5. 与 `GET /agents/{id}/skills` 的区别

| | 本篇（详情内） | 4.13（`/skills`） |
|---|---|---|
| 问题 | 此刻**能调用什么** | 产物目录里**有什么、怎么装配 / 删除** |
| 内置智能体 | 正常返回（定义目录可执行） | `409`（定义目录只读，不参与装配） |
| 缺 `SKILL.md` 的目录 | 不列（不是可执行技能） | 列出（管理面，要能删掉坏目录） |
| 未就绪 | `200` + 空数组 | `200` + `ready=false` / `reasons` |
| 命令 | 返回 | 不涉及 |

## 6. 前端落点

- **详情弹窗**（`AgentDetailDialog`）：打开时补一次 `agentsApi.detail(agentId)`，加一节「技能与命令」；
  `/` 徽章 + 说明，命令按 `namespace` 分组。
- **预览阶段**的 `/` 词表（`PreviewStage`）可从「只列技能」扩成「技能 + 命令」：
  `skills` → `/name`，`commands` → `/name`。注意**进入预览时要重拉详情** ——
  设计页 mount 时那份详情是产物生成前的，不能直接复用。
