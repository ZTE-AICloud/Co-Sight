# ADR-0003：内置智能体——目录即专家，boot seed 登记进 agents 表

> 状态：**已提议**（2026-10-21）。延续 [`0002-agents-table-in-server.md`](./0002-agents-table-in-server.md)（agents 表与目录权威），不推翻其任何决定。

## 1. 背景与问题

agents 表的每一行都绑一个框架工作区：`workspace_id` 非空、目录挂在 `<workspace.directory>/.smart-factory/agents/{id}/` 下、
目录解析必经框架接口。这条链对「用户在工作区里造智能体」是对的，但对**随产品提供、开箱即用**的智能体不成立：
产品分发的东西没有工作区，登录前就该能列出来、跑起来；当时已有的两份专家目录自己就是完整专家——
`CLAUDE.md`、`.claude/skills`、`runtime/`、`data/` [^note] 齐备，引擎从 cwd 发现它们（「目录即专家」），
硬塞进「工作区产物目录 + development 生产线」既不真实也不可用。

专家页的来源筛选当时只有「自定义」一侧，且来源是靠一颗标签表达的；内置那条线「到底存不存在、
由谁登记、来源怎么表达」在 [4.07](../04-api/4.07-待前端对齐.md) 里挂着待办。本文决定用 `source`
字段（而不是又一颗标签）表达来源，理由见 §3「落选案」。

[^note]: 当时的两份专家目录都带 `CLAUDE.md`、`.claude/skills`、`runtime/`，`data/` 为 gitignore 的运行数据区。

## 2. 决策

1. **表达**：`agents.workspace_id` 改可空（内置行恒 null）+ 新列 `source`（`user` | `builtin`，默认 `user`）。
   来源是**事实**不是标签：只读、仅 runtime、无工作区都由它派生；`tags` 只放用户标签，
   `内置` / `自定义` 是保留字（写进 `tags` 一律 400）。
   id = 定义目录名（稳定 slug，如 `example-builtin-agent`），与收养目录名并列为 `agt_<uuid>` 之外的第三种 id 形态，
   同过 `assertAgentId` 边界。`@@unique([workspaceId, name])` 保留——SQLite 里 NULL 互异，
   内置名不参与工作区内重名判定，重名去重由 seed 按 name 告警丢弃后者。
2. **定义目录**：`{COSIGHT_HOME}/smart-factory/builtin-agents/{id}/`，与工作区产物目录完全分离。
   清单 `agent.json`（name/description/tags/icon 白名单）是元数据权威；来源由行上的 `source` 表达，
   不进清单、不进 tags。定义目录随产品只读分发；`data/` 是专家自己的运行数据区。
3. **boot seed**：`main()` 在收养之后、listen 之前扫描定义根：无行→登记（`workspaceId=null`、`source='builtin'`）；
   清单漂移→按清单刷新（值没变不写 updatedAt）；id 被非内置行占用→告警跳过（用户行原样）；
   **目录消失→内置行级联删除**（连带实例/会话/运行史），日志显式告警。
   零框架调用，单目录失败不挡启动。

## 3. 落选案

- **拷贝进各工作区**：内置目录复制到每个工作区的 `.smart-factory/agents/` 下当普通智能体 ——
  弃。收养会重复登记、删除守卫与「随产品」语义打架、工作区一多拷贝面爆炸。
- **独立 builtin_agents 表**：弃。存在权威仍应是 agents 表（ADR-0002 的延续），
  「表是智能体存在的唯一权威」不被内置线打破，sessions/create 的 404 校验零改动。
- **来源作为 tags 里的一颗标记**：弃。标签是用户可编辑的展示元数据，而来源要驱动授权与生命周期
  （只读 409、仅 runtime、列表 scope、seed 清理）；靠标签等于让客户端决定服务端行为，
  且标签的精确匹配只能靠 JSON 串 `contains`。来源用列，标签用表。
- **允许用户改描述/标签**：弃。seed 每次启动按清单刷新会覆盖用户改动，两边都在写就说不清谁权威；
  要个性化等触发条件出现再重审（§5）。

## 4. 后果

- **正面**：专家页的「内置」来源线落地；企业知识助手薄壳随装随用（能力由另行安装的插件提供）；框架挂了内置仍可列可跑。
- **负面**：`agents.workspace_id` 首次可空（行级类型 `string` → `string | null`，web 端同步）；
  内置行与用户行在同一列表竞争分页位；定义目录消失会连带删运行史；清单漂移刷新会动列表排序键。
- **缓解**：类型面由 TS 全量兜底；混入行为在 5.01 与 4.07 记录；连带删史在 seed 日志显式告警；
  刷新仅在清单真实变化时发生。

## 5. 重新评估的触发条件

- 需要**内置智能体可被用户定制**（覆盖描述/标签）时，「只读」决定要重审；
- 需要**内置多版本/升级通道**（定义目录带版本、seed 做版本迁移）时，seed 语义要扩；
- 出现**多用户/远端**形态时，「定义目录在本地盘 + 无鉴权」前提不再成立，与 ADR-0002 §5 联动重审。
