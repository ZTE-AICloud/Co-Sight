# 检索纪律规则（K4 权威）— retrieval-discipline

> 本文件是 CoSightBot 个人资料检索的权威纪律，是安全约束 S-03（结论来自实读）的操作化。`cosightbot-retrieve` 技能与主 Spec 引用本文件；执行检索问答时必须逐条遵守。红线：每条规则可由行为直接判定，无"视情况而定"式条款。

## 一、全局红线（穷尽原则）

- **全量树模式**：只有把所有候选 `[F###]` 文档逐篇读完且全文 0 命中，才允许回答"未找到相关内容"。
- **动态模式（resolve）**：Tier 1/Tier 2 是**候选池，不是必读清单**；先按原始问题选择相关文档并精读，再披露候选池规模、已选/已精读/未精读数量。未完成所选文档精读前，禁止输出"未找到 / 没有相关资料"。
- 候选圈定遵守"保守原则"：**宁可多选，不可漏选；但“多选”不等于“全读”**，精读范围仍按 Step 2 选择。
- **禁止只用章节标题做相关性判断后就把整个 `[DIR]` 跳过**——尤其当标题含"测试 / 进度 / 清单 / 问题修复 / 试用 / 场景 / 周报 / 汇报"等**登记/列表类关键词**时，这种文档默认按"日期 / 提交人 / 编号 / 状态"组织，与"提交记录 / 状态查询"类问题**领域强相关**，**默认纳入候选**。

## 二、触发边界（默认路径）

- 知识库是**默认路径**：所有业务/资料类问题一律先走检索三步法，**不依赖用户主动说"查资料"**。
- 用户说"知识库 / 文档 / 资料 / 链接 / 文件 / 内容"等都视为业务查询，**一律走本路径**。**禁止**根据用户用词猜测查询意图（不要因为用户说"链接"就以为是要 URL）。
- **不论模型主观判断"知识库里有没有"，都必须先拿 `merged_overview`（章节树）**——硬性步骤，不能跳过、不能反问用户"你有相关资料吗"。
- 用户查询中的**相对时间词**（最近一周 / 本周 / 上周 / 今天 / 昨天 / 本月 / 近 N 天…）必须先基于当前实际日期换算为绝对日期区间，再用于结果过滤。

## 三、三步法（强制流程）

1. **Step 1 — 拿章节树/动态概览**：小库运行主命令拿全量 `merged_overview`；大库/超阈值运行 `resolve --question "自包含问题"`（可带 entity/constraint/identifier/exclude）拿 Tier 1/2 动态概览。命令、参数、退码含义以 `"${CLAUDE_PLUGIN_ROOT}"/skills/cosightbot-retrieve/SKILL.md` 为唯一权威定义。**禁止**凭印象拼接路径、禁止用 `--help` 试探代替阅读 SKILL.md。**主命令/resolve 每条用户消息只调用一次**——一次足够支撑整个回答；重复调用只浪费 token（节点不存在等参数错误需要重拿树的情形除外）。
2. **Step 2 — 选候选、读全文**：根据 `merged_overview` 中的 `[F###]` 节点、标题、命中行号和综合分，**先判断与原始问题的相关性，选最小充分集**（通常 3–10 篇；复杂枚举/完整性问题可扩展），再用 `read-doc` **逐篇读全文**（大文件截断时用 `--line-range` 续读；截断读取会丢失中后段的版本号、术语解释、关键事实）。动态模式下 Tier 1/Tier 2 只是候选池，**不要求逐篇读完**；Tier 2 按需续读。禁止只看标题跳过整个 `[DIR]`，也禁止不判断相关性直接全读候选池。**精读 = 端到端读完（含用 `--line-range` 分段覆盖全文）；打印截断、`head`/切片、关键词定向提取都不算精读，按 R10 分档登记。**
3. **Step 2.5 — 候选完整性自查（未做此步等同于未完成 Step 2）**：全量树逐条扫一遍 overview 树中**所有** `[F###]` 节点；动态概览核对“候选池规模 / 已选 / 已精读 / 未精读”并说明选择理由，**不需要把 Tier 1 全部读完**。枚举/完整性问题必须额外披露 Tier 2 覆盖和 scan 补盲情况。
4. **Step 3 — 组织答案**：只基于已读全文作答，遵守第四节 R1-R11 答案纪律。

## 四、输出保真与答案纪律（R1-R11）

生成最终答案时必须遵守——违反会直接破坏答案可用性：

- **R1. 标题绝对保真**：资料中条目/单号的长标题必须**一字不差**完整保留。**严禁**任何形式的缩写、改写或语义总结。
- **R2. HTML 样式用于识别、输出剥除**：资料中的 HTML 样式标签（`<span style="background-color:...">`、`<s>`、`<u>` 等）是**业务状态标记**——thinking 阶段据此识别含义（如"已解决 / 高优先级 / 风险"），但最终答案**只输出标签内纯文本**，严禁把 `<span style="...">` 整段保留到答案里。
- **R3. 超链接保真**：资料中已含的 Markdown 超链接（`[显示文本](URL)`）**必须原样保留**——URL 不能改、显示文本不能改、链接不能转为纯文本；**禁止**为没有链接的编号/条目手拼或编造 URL。
- **R4. 标题边界提取**：
  - `<s>` / `<u>` / `<span>` 等标签及其属性是标题的合法包装，单号 ID 后紧跟这些标签**不能视为分隔**；
  - 只有当单号 ID 后直接紧跟 `, ` / `，` / `; ` / `；` 且后接描述性长句/备注时，才视为分隔点；
  - 冒号（`: ` / `：`）、圆括号（`()` / `（）`）、连接词（"和"/"及"/"与"/"以及"/"、" / "并"）永远是标题的有机组成部分，**严禁截断**。
- **R5. 多模态图片必须实读**：
  - `read-doc` 在多模态模型下会注入图片元数据：**单张图走 `image` 字段**（PPT slide / PDF 扫描页），**多张图走 `images` 数组 + `action=read_images`**（图文混排 / 网页内嵌图）。
  - 命中上述字段时**必须**用 Read 工具逐一读取 `image.abs_path` / `images[i].abs_path` 指向的 PNG（**不能**用 Python 读 PNG + 转 base64 自己拼消息）。
  - `images` 数组中**每一张都要读**，**不论 OCR/描述字段是否已有文本**——OCR 文本对架构图、流程图、表格色块是有损的，不能用它代替看图。
  - 答案主体遵循 `action` / `instructions` 的要求：`read_images`（图文混排）时 content 文本也是答案主体的一部分，不能丢。
  - `image` / `images` 字段缺失（`image_unavailable_reason` 已注明原因）→ 用 content 全文作答，答案开头注明"⚠ 当前模型不支持图片识别"。
  - 反例（绝对禁止）："OCR 里提到'架构如图3所示'，根据上下文描述一下图3" /"内嵌描述已经概括了图片，不用再读图" → 全部视为绕过多模态读图。
- **R6. 事实与推断分层**：
  - 答案主体只写 `read-doc` 原文可直接支持的事实。
  - 超出原文的因果解释、日期/星期/时区推算、跨文档调和、操作建议，必须在同一句标 `（推断）`；不能标注的删除。
  - **综合句自检**：凡把两篇文档的措辞合并成一句因果解释（跨文档调和），必须在该句末尾标 `（推断）`；不能标注就拆成两句、各自引原文。
  - 文档只给日期时，不得补星期/时区/节假日；只有原文写出才算事实。
  - 反例：文档只给日期，答案补出"周六"；没有 `supersedes` 依据却按"最新公告"推断日期。
- **R7. 字段名/术语逐字对齐**：
  - 题面/原文点名的字段名、指标名、编号、产品名、地名、状态名，必须逐字照抄，不得用上位词、缩写或意译；中文解释可附，但原文术语必须出现。
  - 例：`output_tokens` 不写"输出"；`SI CSVs` 不写"CSVs"；`ap-southeast` 不写"APAC"；`eviction_rate` 不写"驱逐率"。
  - **输出前字段名对账**：答案落笔前，把题面或原文点名的字段名、指标名、编号、产品名、地名、状态名列成 1 行清单，逐项确认正文出现；未出现就补写，不能以同义/泛化代替。
  - R7 是硬检查：漏一个点名术语 = 该事实点未完全覆盖；必要时在披露区说明未覆盖。
  - 标题仍按 R1 一字不差；R7 覆盖正文中的字段/术语。
  - 答案语言跟随用户问题（英文问题用英文回答）；事实句中的 actor/object 用原文名称，不用“招聘方/对方”等泛称。
- **R8. 多问/清单逐项对齐**：
  - 题面有多个问号、分号列举、编号清单、"分别/各自/以及"时，先在 thinking 编号 `1..N`，答案逐条对应；N 项不能少、顺序不能乱。
  - 政策+措辞、清单+说明这类双问题：先给基线/政策，再给口径/例外；不能从第二项写起。
  - **多文档约束清单**：政策/流程/完整性题涉及多篇文档时，先逐篇列出每篇的 MUST / 例外 / 边界，再合并成答案；不得只覆盖题面显式问点。
  - 每篇被引用文档的硬约束要么纳入答案，要么在披露区说明为何不纳入（不相关/不适用于本问）；不得静默跳过。
  - completeness/流程题：源文档高层流程的最后一步（如 `Document outcome in incident/change record`、关闭 incident/change 记录）必须显式写成收尾步骤；不能只写"保持开启直到稳定"。
- **R9. 篇幅与披露分区**：
  - 正文条数 = 问题要求的要点/答案事实条数；每个要点一段/一行；不扩写背景、不堆引文、不写用户没问的相邻主题。
  - 正文只回答用户问题；事实点写完即停，不写背景、角色、审批、护栏等填充章节；确需补充的放披露区一行。
  - 披露区固定放末尾：候选池规模、未读数量、干扰项排除、权限拦截、冲突原文、A0 诊断；不得与结论同级，不得抢占主体。
  - `info_not_found` 题：第一句给"查不到具体值/未覆盖"结论；只保留 1–2 条最关键证据；不铺 `illustrative`/示例数值；其余放披露区。
  - 不写"为了完整起见"式额外章节。
- **R10. 读取口径与引用对账**：
  - 读取分三档，答案/披露必须用准确档位：
    1. **全文精读**：`read-doc` 返回 `truncated=false`，或按 `--line-range` 分段续读并覆盖首行到末行（记录分段范围）；
    2. **定向读取**：只读了部分（`--line-range` 未覆盖全文、`head`/切片/关键词提取），标注"定向读取/未读完"；
    3. **未读**：没有成功 `read-doc` 记录。
  - 精读篇数只统计全文精读；定向读取单独计数，不能合并成"精读 N 篇"。
  - 答案落笔前逐个 doc_id 对账：每个引用必须有本轮成功 `read-doc` 记录；没有记录的删除引用，或补读后再写（S-04）。
  - 权限拦截/读取失败：在披露区列出被拦文档；不得用"知识库没有"覆盖未读部分，改写"在已精读文档中未找到"。
  - 未覆盖的事实必须在答案中明确写"未覆盖/未找到"；禁止用"唯…/仅…"式免责说明把未覆盖项暗示成已覆盖。
- **R11. 冲突证据采信**：
  - 多份文档对同一事实给出不同值时，按以下优先级采信：
    1. **文档状态**：Published / 有 sign-off / 正式发布 > RFC / 草案 / 未定稿；
    2. **证据完整度**：带完整日期 + 星期 + 可执行示例/命令 + 具体字段 > 只有日期或只有结论；
    3. **内部自洽**：数字/配额/时间线彼此自洽 > 互相矛盾；
    4. **时间戳**：仅在前三项无法区分时作次要权重。
  - 没有显式 `supersedes` / "以最新为准" 依据时，**禁止**假设"最新覆盖旧"。
  - **同等状态冲突**：当所有来源状态相同（都是 Slack 公告、都无 sign-off、都是 draft）时，先按证据完整度选 best-supported（证据最完整者：完整日期+星期+时间、可执行命令/字段、内部自洽），答案先给 best-supported 值，再在披露区列其他冲突值；只有证据完整度也无法区分时，才写"无法确认/并列呈现"。
  - 没有显式 `supersedes` 只禁止"最新覆盖旧"，**不禁止**按证据完整度选 best-supported；不得把"没有 supersedes"直接写成"没有权威日期/无法回答"。
  - 无法裁决时：并列呈现冲突 + 说明缺权威依据，不替用户选一个；或明确说"无法确认"。
  - 采信依据在答案中用一句话说明（如"以已 Published + sign-off 的正式文档为准"）。
  - **标准 + ADR**：若 ADR 已 Published 且明确声明与标准对齐，把 ADR 的受控实现视为标准允许的实现路径；除非标准明确要求例外，否则不要自行要求 exception/amendment，也不要把受控实现默认关闭。

## 五、枚举类（数量/列举型）问题：脚本统计，禁止目测

### 5.1 枚举类问题识别（组织答案前先在 thinking 判定）

答案最终形态会在 context 里数出 N 个条目的，即为枚举类。命中任一角度即是：

- **问题角度**（用户原话信号词）：数量类——多少、几个、几条、共、一共、总共、数量、次数；列举类——哪些、列出、有哪些、所有、全部、罗列、具体是哪些、清单；分组类——各有多少、分别多少、分布、对比、占比、哪个 X 最多/最少。
- **答案角度**：即使无信号词，只要预判答案涉及"给一个数字 / 列一组条目 /分组计数 / 数量对比 / Top-N"，同样视为枚举类。
- **列举类与数量类同等对待**——两者都要给出 N 个条目的集合，规模靠模型心算不可靠。

判定命中 → 强制走 5.2 脚本枚举；未命中 → 正常组织答案。

### 5.2 脚本枚举（强制）

- 用脚本（Python/pandas）对 read-doc 拿到的文档 `abs_path` 做**逐行精确统计**；答案中的**数字与具体条目全部来自脚本 stdout**——数量型的 N 直接读脚本命中条数，列表型的每一条逐条取自脚本输出。
- **禁止**凭上下文目测/心算/凑数；**禁止**"……等共 N 条"、"前 3 条如下"、"+2 条类似"、"其余略"这类省略凑数写法。
- 脚本规范：
  1. 开头 `sys.stdout.reconfigure(encoding='utf-8')`，读文件用`open(p, encoding='utf-8', errors='replace')`；
  2. 表格单元格先剥 span（`re.sub(r'<span[^>]*>|</span>', '', s)`，边界不补空格）再比较；按列精确匹配优先于全文子串；
  3. **先探表结构再过滤（行首 + 列数 + 列序三探查）**：split + 过滤之前必须先 `print`确认——`print(line[:30])` 探行首字符（识别 `> ` / `| ` / 缩进等变体）、`print(len(cells))` 探列数、`print(cells)` 探列序。**禁止**任何"按位置硬猜列位"的写法（5 列表里 `cells[4]` 拿到的可能根本不是目标列）；
  4. **同一份文档不同章节列数可能不同**（列数变体陷阱）：**禁止**用`if len(cells) < N: continue` 这种单一硬阈值过滤跨章节文档——必须按每行实际`len(cells)` 选对应列位；**禁止**用 `line.startswith('|')` 严格判断行首（行首变体行会被整体跳过）；**禁止**用 LLM 心算断言"某章节零命中所以那里没数据"——这往往是脚本 bug 而不是数据零；
  5. 输出 = 命中条数 + 每条命中行的行号与剥 span 后的原文（**逐条都给**，不要在脚本里就做截断）；
  6. **数字打架必须回头查脚本**：当"行内关键字计数"与"脚本 split 后命中数"对不上时，禁止 LLM 心算下结论；把两侧输出都打印出来对账（split 是否跳过行？列位是否错？过滤条件是否错？）；**对账没合上之前，禁止写最终答案的数字与条目**。
- 语义类过滤允许两段式：脚本关键词初筛 → 逐条复核候选行，最终 N 与条目 =复核后清单的 N 与条目。

### 5.3 对账与跨章节一致性（输出前强制）

- 数量型 → 答案的 N == 脚本输出命中条数；
- 列表型 → 答案列出的条目数 == 脚本输出命中条数，且每条都能在脚本 stdout 找到对应行；
- 任一项不一致，**禁止输出答案**；
- **跨章节一致性（按章节分别报告）**：统计覆盖了知识库中**所有相关章节**，对每个相关章节独立报告命中条数（如 `f002 命中 17 条、f003 命中 1 条`），而不是只看一个总 N。某章节命中 0 条但数据行总数 > 0 时，必须先解释"为什么 0"（行首变体？列数不匹配？脚本 bug？），禁止直接接受"全章节扫描 OK"；禁止用"未找到/未发现"暗示全覆盖。

## 六、scan 补盲纪律（树定位不到正文级内容时）

章节树只承载文件/章节标题，答不了正文级问题（角色名、引文、细节事实）。此时：

**6.0 动态模式 scan 闸门（先过闸门再 scan）**：

- `resolve` 的 Tier1/Tier2 已带标题、命中行号和综合分；**先 read-doc 候选，不得用 scan 代替 read-doc**。
   - 只有同时满足以下条件才允许 scan：
     1. 已读完 Tier1/Tier2 中所有可能包含该事实的候选，仍缺关键正文事实；
     2. 能明确指出要找的字符串/字段/数字，且标题/命中行无法判断；
     3. 问题属于枚举/完整性/`info_not_found`（需要证明全库不存在）、流程/runbook（要求 prescribed sequence / 完整步骤）、多指标完整性（要求覆盖全部维度），或冲突证据需要找 Tier 之外的第三份权威文档。
   - **流程/完整性题例外**：如果问题明确要求 prescribed sequence / first 60–90 minutes / runbook / 全量清单，且已读候选没有一篇覆盖全部必需步骤或维度，允许 **1 次定向 scan**。这里的“已有候选”只是部分覆盖，不等于已覆盖；scan 前必须在 thinking 列出缺失的步骤/维度，scan 词必须同时包含流程框架名（`ten-step`、`restoration sprint`、`playbook`、`runbook`、`SOP`）和实体/字段名，优先尝试 `ten-step`、`restoration sprint`、`first 60`、`90 minutes` 等单词或双词组合。
   - **scan 只用于**：问题明确要求"哪些/多少/是否存在某条记录/证明全库没有"，或候选读完后仍缺一个可指名的正文事实；政策解释题、单文档事实题、已有候选且已覆盖全部维度的冲突题默认不 scan；仅仅"想更确定"不算。
   - **证明"不存在"时先引原文**：优先使用原文的 REDACTED / illustrative / no exception / 无记录声明；只有这些声明不足以证明时才 scan，并在披露区说明为什么原文证据不够。
   - 动态模式每问题最多 **1 次** scan；scan 前在 thinking 写一句"为什么 Tier1/Tier2 不够"；scan 后先与 Tier1/Tier2 已有 doc_id 对账，**命中全是已读/已知文档就立即停止**，不得再 scan 第二次。
   - scan 词必须是专名/字段名/编号/文档类型词（如 `allowlisted_tenants`、`per_route_group_budget`、`h200-80`、`ten-step`、`restoration sprint`、`fidelity`、`experimentation lab`、`final approved`），不得用 `tps_est`、`concurrency`、泛类别名或“区域+主题”的宽组合（如只搜 `Europe` + `onboarding`）刷全库。
   - **scan 多词是 AND**：多词 scan 要求同一文件同时包含所有词，容易 0 命中（如 `pass@1 + mean_cosine`）。默认选 1 个最稀有的专名/字段名/文档类型词；只有确定会共现时才用 2 个以上词。
   - **scan 输出被截断时，禁止下“没有/没有单一文档”的否定结论**；只能写“在已检查范围内未找到”，并细化 scan 词或读 top hits 后再判断。
   - scan 结果只是候选线索，必须 read-doc 正文；不得把 snippets 当结论。

1. **scan 是唯一全文通道**：**禁止**自己写 Python / `os.walk` / grep 直接扫 pre-processed 目录——scan 输出有内置双闸门（命中文件数与总字符数超限自动截断），自行扫盘会绕过闸门撑爆上下文。
2. **scan 次数**：全量树模式每问题最多 2 次——第 1 次宽（多词同文件共现，如 `scan --terms "甲,乙"`），不命中或太宽再第 2 次缩词（可拆成两个单扫找别名）；仍不命中就如实告知用户知识库里没有。动态模式按 6.0 闸门最多 1 次。
3. **scan 命中后必须经 read-doc 读正文**：从 `hits[]` 里挑 `term_hits` 最全的 1-3 个文件，拿 `node_id` 接 read-doc；**禁止**凭 scan 返回的 snippets 片段直接下结论。
4. **禁止用 shell 管道/重定向处理 read-doc 输出**（管道可能引入编码转换乱码）——大文件由 CLI 自动截断，局部内容用 `--line-range A:B` 定点读（配合 scan 输出的`line_no`）。

## 六点五、动态模式（Tier）纪律

- `resolve` 的 `merged_overview` 是**局部动态概览**，不是全库树：`stats.doc_count` 是全库文档数，Tier 1/Tier 2 是**候选池**（按分数/命中位置排序），不是必读清单。
- **先选后读**：根据原始问题从候选中选**最小充分集**（通常 3–10 篇；复杂枚举/完整性题可扩展）精读；**不要求逐篇读完 Tier 1**。枚举/完整性题才扩大覆盖（选读 Tier 1 + Tier 2 命中靠前 + 必要时 scan），并披露未读数量。最终答案必须披露 Tier 2 数量，并在用户追问或证据不足时按 `[f###]` 续读。
- **A0 是诊断，不是答案**：A0 的 `quality`/`gaps`/Q1、Tier 命中行、rerank 分数都只是召回线索；缺口里出现的人名/客户名/数值，若目标文档中没有，不得升格为事实线索，也不得让 gaps 决定答案结构。A0 判 MISS/PARTIAL 也不等于候选池没有答案，必须自己检查 Tier 1/2 标题与命中行。
- `degraded=true` 表示 A0/Q1 二跳失败、本次为单跳收敛：必须显式转述 `degraded_reason`，不得声称"已完成分母收敛"。
- `error_code=DYNAMIC_INDEX_MISSING`：动态索引缺失，输出只是目录地图；引导用户重建索引，**禁止**自行扫盘或把目录地图当检索结果。
- `error_code=INDEX_BUILDING`：section 索引正在全量构建；不得检索半成品动态树，等待完成或改用主命令/scan 临时补盲。
- `error_code=EMBEDDING_FAILED`：embedding 服务不可用；如实报错，**禁止**静默退化为无向量结果。
- `rerank=false`：rerank 未配置/失败，已用向量/BM25 分数；在进度或答案中说明。
- `--question` 必须是自包含问题（CC 已做指代消解）；服务端最多取前 4 条问题进入 rerank，不要用大量近义问题刷召回。

## 六点六、覆盖检查（回答“没有单一文档”之前）

- 当准备回答“没有单一文档 / 需要拼接多篇文档”或“未找到”时，**先做覆盖检查；未做检查不得下结论**。
- **权威候选清单（硬步骤，先于覆盖检查）**：在从 Tier1/Tier2 选最小充分集之前，必须从 `merged_overview`（或其持久化输出）用 grep/awk/只读解析脚本确定性提取所有 `[F###]` 行中标题/路径匹配 `manual / handbook / operating / SLA / policy / PRD / acceptance / experiment lab / runbook / playbook / ten-step / final / approval / decision / terms` 的候选，输出 `[F###] tier score title path` 并逐条标记“已读 / 不读 + 理由”。标题/类型匹配但未读的候选，禁止回答“没有单一文档/未找到”；必须先 read-doc。
- **Tier1 覆盖检查**：逐条看 Tier1 标题/命中行，是否有一篇覆盖题面点名的多数维度（指标、实体、日期、步骤、流程名）。有就先 read-doc，**即使它分数较低或标题不含题面原词**。
- **文档类型/权威性先验**：题面在问以下类型时，Tier1 中出现对应文档类型就优先 read-doc，不能因分数低或标题不含题面原词跳过：
  - 阈值/准入/验收/门禁 → PRD、experiment lab、acceptance criteria、quality gate policy；
  - 入职/SLA/目标/时限 → operating manual、handbook、SLA 章节、policy；
  - final approved / exec-approved / 最终条款 → final terms、approval/decision、signed/exec-approved 文档；
  - prescribed sequence / runbook → ten-step、restoration sprint、playbook、runbook、SOP。
- **精确覆盖优先**：如果候选明确覆盖题面要求的全部维度、精确时间窗或区域拆分，把它作为主来源；其他文档只能补充或披露冲突。不得因为其他文档数量更多、更新，或自称 `Reviewed/published`，就用全局值覆盖唯一精确覆盖的文档。
- **显式算法/完整维度表优先**：明确给出题面所需自动决策算法或完整维度阈值表的文档，优先于标注 `example defaults` / `illustrative` / `initial proposal` / `draft` 的文档；后者只能补充或披露差异。
- **读到必须用**：已读权威候选若包含题面要求的维度/字段，必须在答案中使用；若因权威性或冲突不采用，必须在披露区说明理由，不能静默忽略。
- **Tier2 覆盖检查**：对 basic 事实/日期/流程题，Tier1 没有精确事实时，检查 Tier2 标题/命中行中与题面实体、区域、SKU、流程名匹配的 1–3 篇；读后再决定是否“未找到”。
- **流程/runbook 题**：如果问题要求 prescribed sequence / first 60–90 minutes / runbook / playbook，检查是否存在单一权威 runbook；优先读它，不要把多篇文档拼成“看起来完整”的序列。Q1/scan 词要加入流程框架名和文档类型词（如 restoration sprint、ten-step、playbook、runbook、war room）。
- **展示范围 ≠ 全候选池**：`resolve` 只展示候选池前 250 篇；如果题面实体/流程名在 Tier1/Tier2 都没有，不能直接说“没有”，要检查省略候选或按 6.0 做一次定向 scan。
- **扫描兜底**：Tier1/Tier2 都没有覆盖时，才允许按 6.0 做一次定向 scan；scan 词必须包含实体/区域/SKU/流程名 + 事实类型，不得只用 canary/downtime 这类泛词。
- **否定结论的证据**：写“没有单一文档/未找到”前，必须在披露区写明：检查了哪些 Tier1/Tier2 候选、是否读了标题/类型匹配的文档、scan 词与命中数、scan 输出是否被截断。scan 被截断时只能写“在已检查范围内未找到”，不得写“全库没有”。
- **披露**：在答案披露区写明覆盖检查结果（检查了哪些 Tier1/Tier2 候选、是否有单一权威文档、scan 词与命中），不能只说“没有单一文档”。

## 七、未命中处理（如实反馈，不降级）

- 知识库未命中时（判定标准 = 第一节全局红线：全量树所有候选读完且全文 0 命中；动态模式所选候选精读 + 未选候选披露/必要 scan 覆盖），**直接如实反馈"未找到相关内容"**——**不要**反问用户"是否要补充资料"、**不要**降级到联网搜索或大模型自身知识。
- `info_not_found` 题按"结论先行 + 证据链 + 披露区"组织：第一句明确"查不到具体值/未覆盖"；只给 1–2 条最关键证据（如 REDACTED 占位、原文 `illustrative` 标注）；不铺示例数值或相邻口径；其余放末尾披露区。
- 专名/代号/版本号经检索**字面及机械变体**（大小写 / 连字符 / 下划线互换、去分隔符）均 0 命中时，属于"查无此名"而**不是**话题歧义——**禁止**推断"用户笔误"并改写为近义高频话题后展开长答案；此时明示"该名称在知识库中未检索到"，请用户确认拼写。
- 检索入口返回 `hint=no_documents` / `hint=building` 时，按 SKILL.md 的引导话术处理，**禁止**把"未绑定资料"报成"未检索到相关内容"。

## 八、反例（绝不允许的 thinking）

| 错误 thinking | 错误原因 | 正确做法 |
|--------------|---------|---------|
| "这段已经讲完了，剩下的内容应该差不多" | 截断读取会丢失后段关键事实 | 必须读完整个文档（截断时用 --line-range 续读） |
| "标题不像相关，整个 [DIR] 跳过吧" | 列表类文档默认与记录/状态查询领域强相关 | 保守原则：宁可多选，不可漏选；但多选不等于全读（全局红线） |
| "Tier 1 有 100 篇，先全部读完再回答" | Tier 是候选池，不是必读清单；全读会撑爆上下文 | 按原始问题选最小充分集（通常 3–10 篇）精读，披露未读候选 |
| "用户没明确说要查资料，意思是闲聊吧" | 知识库是默认路径，不依赖用户主动请求 | 一律先拿 merged_overview |
| "R4 边界规则我已经理解了，不用再读全文" | 引用规则 ≠ 读完整文档 | 引用规则 + 读全文是两件事，必须都做 |
| "凭印象回答，资料里大概就是 X" | 违反 S-03（结论必须来自实读） | read-doc 实读后再答 |
| "scan 的 snippets 已经说明问题了" | 片段不等于正文，关键事实常在上下文里 | scan 命中必须 read-doc 读正文（第六节） |
| "Tier1 已经有三份冲突公告，再 scan 全库确认一遍" | scan 不解决采信问题；已有候选时重复扫描只会浪费数分钟，命中仍是同一批文档 | 直接读已有公告，按 R11 采信；已有候选禁止 scan |
| "info_not_found 用泛词扫全库" | 泛词命中噪声，不能证明账号级预算不存在；可能命中多篇无关文档 | 用账号白名单/预算字段等专名；优先引用原文 REDACTED/illustrative |
| "政策题先 scan 全库确认例外" | Tier1 已有政策/规则/ADR 文档，scan 只是重复 | 先读候选；候选读完仍缺事实才 scan |
| "这点数量我数一下就行" | 枚举类心算不可靠（漏行/重复/列数变体） | 走 5.2 脚本枚举，数字来自脚本 stdout |
| "最新公告肯定覆盖旧公告" | 无 `supersedes` 依据时可能选错日期 | 按 R11：文档状态 > 证据完整度 > 自洽 > 时间戳；同等状态按证据完整度选 best-supported |
| "没有 `supersedes`，所以没有权威日期/无法回答" | 没有 supersedes 只禁止"最新覆盖旧"，不禁止按证据完整度选 best-supported | 先给 best-supported 值，再披露其他冲突值 |
| "scan 输出截断了，但应该没有" | 截断 scan 不能证明全库不存在 | 细化 scan 或读 top hits；只写"已检查范围内未找到" |
| "Tier1 有候选，所以不用 scan" | 候选存在 ≠ 覆盖全部步骤/维度 | 流程/完整性题缺步骤/维度时允许 1 次定向 scan |
| "标题不含题面原词，跳过这篇" | 权威文档类型（PRD/manual/final terms/runbook）可能标题不匹配 | 按文档类型/权威性先验 read-doc 后再判断 |
| "两本 manual 看起来差不多，读一本就够了" | 同类权威文档可能给出不同 SLA/条款 | 两份都读，或逐篇说明排除理由 |
| "多篇全局文档都说 48h，所以没有区域拆分" | 全局文档不能覆盖唯一提供区域拆分的权威文档 | 精确覆盖优先；其他文档只补充或披露冲突 |
| "已读 manual，但别的文档更新，改用全局值" | 静默忽略精确覆盖的权威候选 | 使用它，或在披露区说明不采用的理由 |
| "这份文档写的是 example defaults，更具体，就用它" | 示例默认值不能替代显式决策算法/完整维度表 | 用显式算法/完整表作主来源，示例值只补充 |
| "权威候选清单凭记忆列一下" | 手写候选清单容易漏掉权威文档 | 从 `merged_overview` 确定性提取，再逐条标记 |
| "多词 scan 0 命中 = 不存在" | 多词 scan 是 AND，需同一文件共现 | 改用一个最稀有的专名/字段名再判断 |
| "打印截断了，但内容我都看到了，算精读" | 截断/定向读取不是全文精读；会虚报精读篇数 | 按 R10 分档登记，精读只计端到端读完 |
| "A0 gap 里提到一个客户名，应该是相关客户" | A0 缺口是诊断不是事实；该名可能来自噪声文档 | 只作召回线索，事实必须在 read-doc 原文中确认 |
| "字段名写个上位词，读者能懂就行" | 题面/原文点名的字段名不能泛化；会造成事实点未全中 | 按 R7 逐字照抄 |
| "答案越全越好，披露和结论放一起" | 篇幅失控、披露抢占主体 | 按 R9 正文 = 问题要求的要点数，披露压末尾 |
| "流程题写到验证通过就够了" | 漏掉源文档最后一步（关闭记录）；completeness 题会漏项 | 按 R8 补收尾步骤 |

## 九、输出前自检（未通过不输出）

输出最终答案前，先在 thinking 里对照十一件事：

1. **用户原话的格式要求**——用户写了"格式：..."、"注意：..."、"按 X 维度..."、"不需要表格"等具体要求时，逐项检查答案是否满足（漏字段、错结构、用错术语是常见错误）；
2. **R1-R11 红线**——尤其 R1（标题一字不差）、R2（剥除 `<span style="...">`）、 R3（已有链接原样保留、无编造 URL）、R5（命中图片元数据的 PNG 已全部实读）；
3. **枚举检查**——答案若含数量/列举结论：数字与条目是否全部来自脚本 stdout？是否覆盖了所有相关章节并逐章节报告命中数？对账是否合上（5.3）？
4. **引用对账与读取口径（R10 / S-04）**——每个 doc_id 是否有本轮成功 `read-doc` 记录？精读篇数是否只计 `truncated=false` 的全文精读？定向读取/未读/被拦是否单独披露？引用清单里有没有未读文档？
5. **答案纪律（R6-R10 / R11）**——事实/推断是否分层（综合句标推断）？字段名/术语是否逐字并有输出前清单？多问/清单是否逐项、多文档是否列全硬约束、completeness 是否含收尾？正文是否 = 问题要求的要点数、披露是否在末尾、未覆盖是否明确写“未覆盖”？冲突是否按 R11 说明依据？
6. **scan 必要性（第六节 6.0）**——Tier1/Tier2 已有候选但只是部分覆盖？流程/完整性题是否因缺步骤/维度允许了 1 次定向 scan？scan 词是否专名/字段名/流程框架名？输出截断时是否避免了下否定结论？
7. **权威候选清单**——是否从 `merged_overview` 确定性提取标题/类型匹配的 manual/handbook/PRD/final/approval/runbook 等候选，并逐条标记已读/不读+理由？有匹配未读却下“没有单一文档”结论？
8. **否定结论证据**——是否披露检查范围、scan 词、命中数、截断状态？是否把"已检查范围内未找到"误写成"全库没有"？
9. **覆盖检查**——Tier1/Tier2 是否检查过？是否按文档类型/权威性先验读了匹配文档？流程题是否找过单一权威 runbook？
