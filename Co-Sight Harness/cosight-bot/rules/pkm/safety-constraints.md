# 安全约束规则（K4 权威）— safety-constraints

> 本文件是 CoSightBot PKM 安全约束的权威判定标准，与 `/cosightbot:pkm` 命令安全约束表一一对应。红线：每条规则可由输入/行为直接判定，无"视情况而定"式条款。

## 规则列表

| # | 规则 | 判定信号 | 判定 |
|---|------|---------|------|
| S-01 | 检索只读 | `cosightbot-retrieve` 技能内出现任何写索引/构建命令（common_build/common_update） | 即违规：检索技能只允许 overview_resolver 的 read-doc/scan/主命令 |
| S-02 | 构建必须实跑 | 声称"已构建/已入库"但本轮未真实执行构建入口（runner 子进程）并消费退出码 | 即违规：判定无效，必须真实执行 |
| S-03 | 结论来自实读 | 知识问答的答案引用的文档未经过 read-doc 实际读取 | 即违规：答案无效，重新走三步法（章节树 → 读全文 → 组织答案） |
| S-04 | 引文禁编造 | 输出含 `[F###]`/文件来源标注，但对应节点/文档未被读取过 | 即违规：删除引文或重读文档 |
| S-05 | 脚本失败阻断 | 脚本非零退出后继续流程、或以"看起来没问题"替代脚本判定 | 即违规：阻断当前步骤并报告用户 |

## 检查清单 + 通过标准

- [ ] 本轮所有"已完成"声称都有真实命令执行与退出码佐证
- [ ] 所有知识问答的结论可回溯到 read-doc 读取记录
- [ ] 所有来源标注指向实际读取过的文档
- [ ] 无脚本失败被静默吞掉

**通过标准**：S-01~S-05 全部满足；任一违规为 Hard 违规 → 阻断当前流程，修复后重验。
