
#错误：文件保存操作未合并导致的重复工具调用
 
问题性质：非功能性问题，属于性能优化类告警。
原因分析：Agent 在生成多个版本内容时，将完整报告和精简报告分别保存为独立文件，导致同一 step 内重复调用 
 优化方案：
将完整报告和精简报告整合到同一个 Markdown 文件中，通过不同标题分区保存，避免多次调用 file_saver，提高执行效率。



#错误：在调用 search_wiki 工具时，程序通过 wikipedia.summary() 请求 Wikipedia 接口。由于接口返回了空响应或非 JSON 格式内容，第三方库在执行 r.json() 解析时触发 JSONDecodeError，导致工具调用失败。

问题性质：该问题属于外部接口响应异常导致的异常处理不完整问题，不属于核心业务逻辑错误。
修复方案：将 `search_wiki()` 恢复为基于 `wikipedia` Python 包的 Wikipedia 查询；同步清理工具元数据中的 Baidu Baike 描述；捕获网络异常、JSON 解析异常、空响应等问题，失败时返回可读错误字符串，不向 Agent 执行层抛异常。



#错误：回放页面没有返回工作区按钮，离开工作区之后会删除状态暂存导致任务截断

问题性质：前端页面跳转与运行状态管理冲突
原因分析：回放页面和当前工作区共用了同一套浏览器运行环境与本地状态，但原来的页面切换方式没有隔离二者。点击回放历史会直接通过 window.location.href 跳转到 replay.html。这样会导致当前工作区页面被卸载，正在运行的任务页面不再保留。同时，首页加载时又会执行 localStorage.clear()，把任务恢复所依赖的状态一起清掉
优化方案:不再让回放页面破坏当前工作区，而是将回放历史以内嵌 overlay 的方式打开，并对前后端状态恢复和异常处理进行加固
问题：在内嵌的overlay上的回放页面中，如果再点击回放页面会内嵌新的overlay，且无法返回到最初工作区



# file_read 误读 workspace 目录导致 PermissionError

原因分析:file_read 当前未在读取前判断目标路径是文件还是目录。当 Agent 将 workspace 目录路径传给 file_read 时，工具直接执行 open(absolute_path)，导致目录被误当作文件读取，从而触发 PermissionError。
优化方案：在 file_read 执行 open() 前增加路径类型校验：
如果路径不存在，返回“文件不存在”提示。
如果路径是目录，返回“目标是目录，请指定具体文件路径”，并可附带目录下的文件列表。
只有当路径是普通文件时，才执行 open() 读取。
同时应优化 Agent 的工具使用提示，要求读取文件时传入具体文件路径，例如 .md、.txt、.json 文件，而不是 workspace 根目录。



#错误：Agent 搜索/抓取到无效网页内容后，仍将 step 标记为完成，导致工作流显示 100% 成功，但最终报告没有真正生成。

性质：工作流完成判定错误，属于任务状态管理和结果有效性校验问题。
原因：系统没有识别 Google 跳转页、403、404、人机验证页、反爬页面等无效内容，并且最终报告类任务没有强制检查 `.md` 报告文件是否生成。
修复方案：增加无效网页内容识别逻辑；报告类 step 必须检测是否生成 `.md` 文件；未生成最终报告时不能显示完全成功，前端应展示“任务结束但未生成报告”的错误摘要。
