# RAG 与向量检索入门

> 本文面向 RAG（Retrieval-Augmented Generation，检索增强生成）系统的开发者，介绍从文档切片到向量召回的基本链路。

## 1. 什么是 RAG

RAG 把「检索」与「生成」解耦：先从一个外部知识库中检索与问题最相关的片段，再把片段作为上下文交给大语言模型，从而减少幻觉、让回答有据可查。

一个最小 RAG 链路通常包含以下五个环节：

1. 知识库创建
2. 文档导入与解析
3. 文档切片（chunking）
4. 向量化与索引
5. 检索与展示

## 2. 文档切片

切片是 RAG 中影响检索质量最直接的环节。切片过大，召回内容噪声多；切片过小，语义不完整。

### 2.1 定长切分

定长切分是最简单也最可控的方式：按固定字符数或 token 数切分，并保留相邻片段之间的重叠，避免关键句子被切断。

```python
def file_split(text: str, max_len: int = 200):
    chunks = []
    for i in range(0, len(text), max_len):
        chunks.append(text[i:i + max_len])
    return chunks
```

### 2.2 结构化切分

对于 Markdown 或 HTML 等带结构的文档，可以按标题层级切分，使每个片段保持语义边界。

- 一级标题：章节
- 二级标题：小节
- 三级标题：段落主题

### 2.3 切片质量约束

切片结果需要满足若干机械可判定的约束：

- 不允许出现空切片
- 不允许出现远超上限的超长切片
- 相邻片段的重叠必须生效
- 内容不得丢失（允许重叠造成的重复）

## 3. 向量化与召回

切片完成后，需要把文本转换为向量。常用做法是调用 embedding 模型，把每个切片映射为一个固定维度的向量，再写入向量数据库。

### 3.1 相似度度量

向量召回通常使用余弦相似度：

```text
cosine_similarity(a, b) = (a · b) / (||a|| * ||b||)
```

取值范围为负一到一，值越接近一表示两个向量的方向越一致。

### 3.2 召回流程

1. 将用户问题用同一 embedding 模型编码为向量
2. 在向量库中做近似最近邻搜索
3. 返回 Top-K 个最相似的切片
4. 将切片拼接为上下文，交给生成模型

## 4. 索引一致性

除检索正确性外，还应关注跨环节的一致性：

| 场景 | 预期行为 |
|---|---|
| 删除文档后检索 | 该文档片段不再出现 |
| 重复导入同一文档 | 不产生重复向量 |
| 更换切分参数重新索引 | 旧向量被清理，行数与新切片数一致 |

## 5. 小结

RAG 系统的核心是「切片 + 向量化 + 召回」三步。样本数据应当覆盖纯文本、Markdown、PDF 和 Word 等格式，才能充分验证解析与切片在不同输入下的行为一致性。
